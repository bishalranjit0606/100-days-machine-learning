The Trip Planning Problem

Imagine you book a trip from Kathmandu to Pokhara. You do the work in pieces, one website at a time.

A trip by hand

  1. Flight Pick an airline, date, and time, then book.
  2. Hotel Search Make My Trip. Filter by budget and reviews. Book.
  3. Local travel Plan the visit and a cab, such as Pathao or inDrive.

This can take days. It is hectic. That is the problem AI agents are built to solve.

478

How an Agent Chatbot Helps

Now picture a 60 year old traveler. The same site has an AI agent chatbot. You talk. It does the research and the next steps.

User and agent

  1. Prompt Plan Kathmandu to Pokhara from 1 May to 5 May, budget travel.
  2. Intent Origin, destination, dates, and budget.
  3. Research Transport, then hotels, then a cab, then a visit plan.
  4. Reply The user can ask to search, book, or plan the next piece.

As a user, this saves time and effort. The same idea works in other domains too, such as customer support or hospitality.

What Is an AI Agent

An AI agent is an intelligent system you give a high level goal. You say plan Kathmandu to Pokhara. You do not list every click.

The agent has its own brain. It has access to tools, such as APIs, so it can do real work. It keeps the end goal in context. If new information arrives in the middle, it can replan.

480

Why an Agent Beats a Plain LLM

In a nutshell, an AI agent is an LLM plus tools.

Piece Job
LLM Reasoning. It understands natural language and decides the next step.
Tools Action. Search, APIs, weather, booking, and other real work.
Agent Both together. Think, then act, then think again.

Day 37 you ran that loop by hand. Today the agent framework runs it for you.

481

Five Traits of an AI Agent

These five traits show up in a real agent, not in a one shot LLM reply.

Goal driven

Tell it what you want, not how to do every step.

Autonomous planning

It breaks the problem into a sequence of tasks on its own.

Adaptive

It can readjust when facts change.

Context aware

It keeps memory across steps so later choices stay on goal.

Tool using

It calls APIs and other tools to get work done.

Search Tool and Weather Tool

We give the agent two tools. DuckDuckGo search for current facts. A custom weather tool for live weather from WeatherStack.

Install, keys, and tools

!pip install -qU langchain langchain-groq \
  langchain-community ddgs requests

import os
import requests
from langchain_core.tools import tool
from langchain_community.tools import DuckDuckGoSearchRun

search_tool = DuckDuckGoSearchRun()

@tool
def get_weather_data(city: str) -> str:
    """Get current weather for a given city."""
    api_key = os.environ.get("WEATHERSTACK_API_KEY")
    if not api_key:
        return "WeatherStack API key is not configured."

    url = "https://api.weatherstack.com/current"
    params = {
        "access_key": api_key,
        "query": city,
        "units": "m",
    }
    try:
        response = requests.get(url, params=params, timeout=15)
        response.raise_for_status()
        data = response.json()
        if "error" in data:
            return f"Weather API error: {data['error'].get('info', 'Unknown error')}"

        location = data.get("location", {})
        current = data.get("current", {})
        city_name = location.get("name", city)
        country = location.get("country", "")
        temperature = current.get("temperature")
        description = current.get("weather_descriptions", ["Unknown"])[0]
        humidity = current.get("humidity")
        wind_speed = current.get("wind_speed")
        return (
            f"Location: {city_name}, {country}\n"
            f"Temperature: {temperature} C\n"
            f"Condition: {description}\n"
            f"Humidity: {humidity}%\n"
            f"Wind speed: {wind_speed} km/h"
        )
    except requests.exceptions.RequestException as e:
        return f"Weather request failed: {str(e)}"
    except Exception as e:
        return f"Unexpected weather error: {str(e)}"

What you need ready

GROQ_API_KEY in the environment.
WEATHERSTACK_API_KEY in the environment.
search_tool and get_weather_data ready to bind.

Put keys in env vars or a secret store. Never paste them into a notebook cell.

Create the Agent

The agent is the main brain. It plans, picks a tool, and writes the final answer. create_agent wires the model, tools, and a system prompt together.

create_agent

from langchain_groq import ChatGroq
from langchain.agents import create_agent

llm = ChatGroq(
    model="llama-3.3-70b-versatile",
    temperature=0,
)

agent = create_agent(
    model=llm,
    tools=[search_tool, get_weather_data],
    system_prompt=(
        "You are a helpful research assistant. "
        "Use the search tool when you need current "
        "or factual information. "
        "Use the weather tool when asked about weather. "
        "Give concise and accurate answers."
    ),
)

print("Agent created successfully.")

What you get

Agent created successfully.
The agent can now search and fetch weather.

The system prompt tells the agent when to use each tool. Keep it short and clear.

ReAct: Thought, Action, Observation

LangChain Hub stores pre defined prompts. One common design pattern is ReAct. That name means reasoning plus acting.

A plain LLM path is user to LLM to response. ReAct runs a loop of three steps until the agent can finish.

ReAct loop

  1. Thought What do I need next?
  2. Action Pick a tool and an input.
  3. Observation Read the tool result, then think again.

ReAct fits multi step problems and tool work such as web search or a database lookup. You can see each step of the workflow.

486

ReAct Example: Capital Then Population

Query: what is the population of the capital of France? The agent does not guess both facts in one shot. It walks the loop.

Step What happens
Thought I need the capital of France.
Action Search tool. Input: capital of France.
Observation Paris.
Thought I need the population of Paris.
Action Search tool. Input: population of Paris.
Observation About 2.1 million in this teaching walk through.
Thought I know the final answer.
Final Paris, about 2.1 million.

Live search can return a different population figure. The pattern is what matters: think, act, observe, repeat.

Agent and Agent Executor

The agent is the brain. It plans and chooses an action. The agent executor does most of the work. It runs the thought, action, observation loop.

Piece Job
Agent Receives the query plus thought trace. Returns an action or a final answer.
Agent executor Sends the query to the agent, runs the tool, feeds the observation back, repeats.

Older LangChain code used create_react_agent plus AgentExecutor. A common prompt on LangChain Hub is hwchase17/react. verbose=True prints the thinking while it runs.

Older ReAct executor shape

# Sketch of the older API from the notes.
# Prefer create_agent in current LangChain.
from langchain import hub
from langchain.agents import (
    create_react_agent,
    AgentExecutor,
)

prompt = hub.pull("hwchase17/react")

agent = create_react_agent(
    llm=llm,
    tools=[search_tool],
    prompt=prompt,
)

agent_executor = AgentExecutor(
    agent=agent,
    tools=[search_tool],
    verbose=True,
)

What this pattern does

The executor loops until the agent finishes.
verbose=True prints thought, action, and
observation as the run proceeds.
488

The Executor Loop

When the loop starts, the executor sends the user query to the agent. The agent returns an action and an action input, or it finishes.

Until a final answer

  1. Receive query Executor gets the user ask.
  2. Think Query plus thought trace go to the agent.
  3. Action or finish Tool name, tool input, and log, or a final output.
  4. Execute tool Observation comes back.
  5. Update trace Loop until AgentFinish, then return the answer.
