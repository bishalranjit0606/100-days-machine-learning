What and Why Chains

When you build an LLM app, the basic path looks like this.

Basic LLM path

  1. Prompt Build the text you send.
  2. LLM Call the model.
  3. Output Read the reply.

In code without a chain, you often do many manual steps: fill a prompt template, get user input, call model.invoke, then read output.content.

That gets long and hard to manage in a complex app.

Chains turn those steps into a pipeline. Once the pipeline is set, the flow runs for you.

You can build different pipelines: linear, parallel, or conditional.

404

Types of Chains

LangChain chains come in three main shapes. We will build one of each today.

Sequential chain

One step after another. Output of step A feeds step B.

Parallel chain

Several branches run at once, then you can merge results.

Conditional chain

Pick a path based on a condition, such as sentiment.

A Simple Chain with the Pipe

Start with the simplest chain: prompt, then model, then string parser.

The | symbol is the pipe operator. It connects each piece into one runnable chain.

Simple chain flow

  1. PromptTemplate Fill in {topic}.
  2. ChatGroq Generate the reply.
  3. StrOutputParser Return plain text.

Input code

from dotenv import load_dotenv
from langchain_groq import ChatGroq
from langchain_core.prompts import PromptTemplate
from langchain_core.output_parsers import StrOutputParser

load_dotenv()

prompt = PromptTemplate(
    template="generate 5 interesting facts about {topic}",
    input_variables=["topic"],
)

model = ChatGroq(
    model="llama-3.3-70b-versatile"
)

parser = StrOutputParser()

chain = prompt | model | parser

result = chain.invoke({"topic": "Nepal"})
print(result)

# Print a graph of the chain
chain.get_graph().print_ascii()

Chain graph

+-------------+
| PromptInput |
+-------------+
       *
       *
+----------------+
| PromptTemplate |
+----------------+
       *
       *
 +----------+
 | ChatGroq |
 +----------+
       *
       *
+-----------------+
| StrOutputParser |
+-----------------+
       *
       *
+-----------------------+
| StrOutputParserOutput |
+-----------------------+

One invoke call runs the full pipeline. You pass a topic and get five facts as a string.

Sequential Chain

A sequential chain runs steps in order. The output of one step becomes the input of the next.

Here is the flow we build: user topic, then a detailed report, then a short summary.

Sequential pipeline

  1. Topic User input.
  2. Report First LLM call.
  3. Summary Second LLM call.

Input code

from dotenv import load_dotenv
from langchain_groq import ChatGroq
from langchain_core.prompts import PromptTemplate
from langchain_core.output_parsers import StrOutputParser

load_dotenv()

prompt1 = PromptTemplate(
    template="generate a detailed report on {topic}",
    input_variables=["topic"],
)

prompt2 = PromptTemplate(
    template="write a four-line summary of the following text:\n{text}",
    input_variables=["text"],
)

model = ChatGroq(
    model="llama-3.3-70b-versatile"
)

parser = StrOutputParser()

chain = prompt1 | model | parser | prompt2 | model | parser

result = chain.invoke({"topic": "Nepal"})
print(result)

chain.get_graph().print_ascii()

What the pipe does

prompt1 | model | parser  -> long report text
prompt2 | model | parser  -> four line summary

The first parser output becomes the text for prompt2. You only invoke once with the topic.

Parallel Chain

A parallel chain runs more than one path at the same time, then you can merge the results.

Example app: from one document, make notes and a quiz, then merge them for the user.

Parallel then merge

  1. Document Shared input text.
  2. Notes path Model 1 writes notes.
  3. Quiz path Model 2 writes questions.
  4. Merge Model 3 joins both.

RunnableParallel runs the notes chain and the quiz chain together. Keys like notes and question name each branch.

Input code

from dotenv import load_dotenv
from langchain_groq import ChatGroq
from langchain_core.prompts import PromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnableParallel

load_dotenv()

prompt1 = PromptTemplate(
    template="generate short and simple notes from the following text {text}",
    input_variables=["text"],
)

prompt2 = PromptTemplate(
    template="generate 5 short question from the following text {text}",
    input_variables=["text"],
)

prompt3 = PromptTemplate(
    template="merge the provided notes and quiz into a single document \n notes -> {notes} \n question -> {question}",
    input_variables=["notes", "question"],
)

model1 = ChatGroq(model="llama-3.3-70b-versatile")
model2 = ChatGroq(model="llama-3.3-70b-versatile")
model3 = ChatGroq(model="llama-3.3-70b-versatile")

parser = StrOutputParser()

parallel_chain = RunnableParallel(
    {
        "notes": prompt1 | model1 | parser,
        "question": prompt2 | model2 | parser,
    }
)

merge_chain = prompt3 | model3 | parser
chain = parallel_chain | merge_chain

text = """
Linear regression is a foundational statistical and machine learning method
used to predict a continuous target value based on one or more explanatory
variables. At its core, the technique models the relationship between a
dependent variable and an independent variable by fitting a linear equation
to the observed data.
"""

result = chain.invoke({"text": text})
print(result)
chain.get_graph().print_ascii()

How data moves

text
  |-- notes branch    -> notes string
  |-- question branch -> question string
         |
         v
merge prompt uses {notes} and {question}
         |
         v
one merged document for the user

First run the parallel block. Then pipe into the merge chain. One invoke on the full chain is enough.

Conditional Chain

A conditional chain picks a path based on a rule.

Example app: user sends feedback. If the sentiment is positive, write a thank you message. If negative, write a sorry message.

In a real product you might also show a rating form on positive feedback, or email customer support on negative feedback. Today we focus on the LLM branch that writes the reply.

Feedback branch flow

  1. Feedback User message.
  2. Classify Positive or negative.
  3. Branch Thank you or sorry.

We use a Pydantic model for sentiment, then RunnableBranch to pick the reply. RunnablePassthrough.assign keeps the original feedback and adds the sentiment field.

Input code

from dotenv import load_dotenv
from langchain_groq import ChatGroq
from langchain_core.prompts import PromptTemplate
from langchain_core.output_parsers import StrOutputParser, PydanticOutputParser
from pydantic import BaseModel, Field
from typing import Literal
from langchain_core.runnables import RunnableBranch, RunnableLambda, RunnablePassthrough

class Feedback(BaseModel):
    sentiment: Literal["positive", "negative"] = Field(
        description="the sentiment of the feedback"
    )

parser2 = PydanticOutputParser(pydantic_object=Feedback)

load_dotenv()

prompt1 = PromptTemplate(
    template="classify the sentiment of the following feedback into positive or negative\n{feedback}\n{format_instructions}",
    input_variables=["feedback"],
    partial_variables={"format_instructions": parser2.get_format_instructions()},
)

model = ChatGroq(model="llama-3.3-70b-versatile")
parser = StrOutputParser()

classifier_chain = prompt1 | model | parser2 | RunnableLambda(lambda x: x.sentiment)

prompt2 = PromptTemplate(
    template="write a thank you message for the following feedback {feedback}",
    input_variables=["feedback"],
)

prompt3 = PromptTemplate(
    template="write a sorry message for the following feedback {feedback}",
    input_variables=["feedback"],
)

branch_chain = RunnableBranch(
    (lambda x: x["sentiment"] == "positive", prompt2 | model | parser),
    (lambda x: x["sentiment"] == "negative", prompt3 | model | parser),
    RunnableLambda(lambda x: "could not find the sentiment of the feedback"),
)

chain = RunnablePassthrough.assign(sentiment=classifier_chain) | branch_chain

result = chain.invoke({"feedback": "I love the product!"})
print(result)
chain.get_graph().print_ascii()

Example invoke

Input:  {"feedback": "I love the product!"}
Path:   sentiment == "positive"  -> thank you prompt
Output: a thank you message string

The default branch runs only if sentiment is neither positive nor negative.
