Why OOP

OOP means object oriented programming. This idea comes up a lot in interviews. You do not have to use it for every program. Functions are still fine. Use a class when it helps you model the work.

First we wrote procedural code. Then we learned functions, which cut copy paste and made reuse easy. Classes and objects are the next step when you want a blueprint you can stamp many times.

How our code style grew

  1. Procedural Line by line, like add two numbers and print.
  2. Functions Write the work once. Call it many times.
  3. Classes A blueprint. Each object is one copy.

Input

a = 10
b = 20
c = a + b
print(c)

Output

30

Class Is a Blueprint

In the real world, a person, a pencil, and a mobile phone are objects. Before you make an object, you write a class. The class is the blueprint.

A school class has many students. A car model is one class. Cars from that model share features such as four doors and the same kind of engine. Each car you build from it is an object.

For a college system you could store students in a list or a dictionary. You can also make a Student class. OOP is mostly this idea: class first, then objects.

Class

The blueprint. The shared plan for every copy.

Object

One copy made from the class. Also called an instance.

Create an Object

Writing the class is not enough. You make an object by calling the class name with parentheses. That object is also called an instance.

Input

class Student:
    name = "John"

s1 = Student()
print(s1.name)
print(s1)

s2 = Student()
print(s2.name)
print(s2)

Output

John
<__main__.Student object at 0x104bfe7b0>
John
<__main__.Student object at 0x104bec410>

print(s1) shows that this is an object in memory. The hex number changes each run. s1 and s2 are two instances.

The same idea works for a car. Every object reads the same class values until you give each car its own data.

Input

class Car:
    color = "red"
    brand = "BMW"
    model = "2020"
    speed = "100 km/h"

car1 = Car()
print(car1.color)
print(car1.brand)
print(car1.model)
print(car1.speed)

Output

red
BMW
2020
100 km/h

Constructor

A constructor is the __init__ function. It runs by itself when you make a new object. You do not call it by name. Python still runs a constructor even if you never write __init__. If you write one, yours is the one that runs.

Make an object, init runs

  1. Car() You create the object.
  2. __init__ Python runs this automatically.

The first parameter is always the new object. We name it self. That is the standard. Another name such as abc can work, but use self.

Input

class Car:
    brand = "BMW"
    def __init__(self):
        print("this is a constructor")

car1 = Car()

Output

this is a constructor

Attributes

The data you store on a class or an object is called an attribute. Name and marks here are attributes on each student.

Input

class Student:
    def __init__(self, name, marks):
        self.name = name
        self.marks = marks

s1 = Student("John", 90)
print(s1.name)
print(s1.marks)

s2 = Student("Jane", 85)
print(s2.name)
print(s2.marks)

Output

John
90
Jane
85

Constructors come in two kinds. A default constructor is def __init__(self):. Python also makes one for you if you write none. A parameterized constructor takes extra values, such as name and marks. In one class we usually write only one constructor.

Default Parameterized
def __init__(self): def __init__(self, name, marks):

Class and Instance Attributes

There are two kinds of attributes. A class attribute is shared by every object. An instance attribute is unique to one object. You set instance data with self in the constructor.

Ten students can share one college name. That college name is a class attribute. Each student name is an instance attribute. Shared data on the class also saves memory, because Python stores it once.

Class attribute Instance attribute
Same for every object, such as college name. Different per object, such as student name.
Written on the class, like brand = "BMW". Written with self.name = name.

Input

class Car:
    brand = "BMW"
    def __init__(self, name):
        self.name = name

car1 = Car("test")
print(car1.brand)
print(car1.name)

Output

BMW
test

Object Attribute Wins

If the class and the object both have an attribute with the same name, the object value is the one you get. Instance attribute ranks above class attribute.

Input

class Car:
    brand = "BMW"
    name = "class attribute"
    def __init__(self, name):
        self.name = name

car1 = Car("object attribute")
print(car1.brand)
print(car1.name)

Output

BMW
object attribute

Methods

A class has two kinds of things. Attributes are the data, the properties. Methods are the actions, what the object can do. A car has brand and model. It also starts, stops, and runs. Strings, lists, and dictionaries already give you methods.

Attribute

What the object has, such as brand or name.

Method

What the object can do, such as hello or stop.

A method needs self so it knows which object you called. Use it like car1.hello(). You can put many methods in one class.

Input

class Car:
    def __init__(self, fullname):
        self.name = fullname

    def hello(self):
        print("welcome tester")

    def stop(self):
        print("car stopped")

car1 = Car("test")
car1.hello()
car1.stop()

Output

welcome tester
car stopped

Practice Student Average

Create a Student class that takes a name and marks for 3 subjects in the constructor. Add a method that returns the average. Do not put a comma after self.name = name. A trailing comma would store a tuple, not a string.

Input

class Student:
    def __init__(self, name, marks):
        self.name = name
        self.marks = marks

    def average(self):
        sum = self.marks[0] + self.marks[1] + self.marks[2]
        average = sum / 3
        return average

s1 = Student("John", [90, 80, 70])
print(s1.average())

Output

80.0

You can change an attribute later by assigning to it.

Input

s1.name = "Jane"
print(s1.name)
s1.marks = [100, 90, 80]
print(s1.marks)

Output

Jane
[100, 90, 80]

Static Methods

The methods above are normal methods. They need self. If you write a function in the class with no self, calling it on an object fails. Python still passes the object in, so the function gets one extra argument.

Input

class Car:
    def __init__(self, fullname):
        self.name = fullname

    def hello():
        print("welcome tester")

car1 = Car("test")
print(car1.hello())

Output

TypeError: Car.hello() takes 0 positional arguments but 1 was given

A static method does not use self. Put @staticmethod above it. That line is a decorator. It changes how the function behaves. You can call it on an object or on the class, with no object.

Input

class Car:
    @staticmethod
    def hello():
        print("welcome tester")

car1 = Car()
car1.hello()
Car.hello()

Output

welcome tester
welcome tester

Four Concepts and Abstraction

OOP has four main concepts: abstraction, encapsulation, inheritance, and polymorphism. This part 1 focuses on the first two.

Abstraction

Hide extra detail. Show only what the user needs.

Encapsulation

Wrap data and methods in one object.

Inheritance

A later OOP idea. Named here so you know the four.

Polymorphism

A later OOP idea. Named here so you know the four.

Abstraction is like a car. The driver does not need the engine internals. They need start, stop, and the pedals. Inside start we still set acc, brake, and clutch. The caller only sees car1.start().

Input

class Car:
    def __init__(self):
        self.acc = False
        self.brake = False
        self.clutch = False

    def start(self):
        self.acc = True
        self.brake = True
        self.clutch = True
        print("car started")

car1 = Car()
car1.start()

Output

car started

Encapsulation

Think of a capsule. Encapsulation wraps data and functions into one unit, the object. That is what we have been doing all lesson: attributes plus methods live together on the class.

One object holds both

  1. Data Attributes such as balance and name.
  2. Functions Methods such as debit and start.
  3. Object The single unit that holds both.

Practice Account

Create an Account class with two attributes: balance and account number. Add methods to debit, credit, and print the balance. Start at 500. Debit 100. Credit 200. The balance ends at 600.

500, then debit, then credit

  1. Debit 100 500 minus 100 is 400.
  2. Credit 200 400 plus 200 is 600.
  3. get_balance Prints 600.

Input

class Account:
    def __init__(self, balance, account_no):
        self.balance = balance
        self.account_no = account_no

    def debit(self, amount):
        self.balance = self.balance - amount
        print("Debit amount is successful")
        print(self.balance)

    def credit(self, amount):
        self.balance = self.balance + amount
        print("Credit amount is successful")
        print(self.balance)

    def get_balance(self):
        print(self.balance)

account1 = Account(500, 12345)
account1.debit(100)
account1.credit(200)
account1.get_balance()

Output

Debit amount is successful
400
Credit amount is successful
600

Python 8 takeaways

Python 8 takeaways

  • OOP means object oriented programming. It is common in interviews. You can still use functions when a class is not needed.
  • A class is a blueprint. An object is one copy. An object is also called an instance.
  • __init__ is the constructor. It runs when you make an object. The first parameter is self.
  • Attributes are stored data. Class attributes are shared. Instance attributes are unique and use self.
  • If both exist with the same name, the instance attribute wins.
  • Methods are actions. Normal methods need self. Static methods use @staticmethod and skip self.
  • A decorator such as @staticmethod changes how a function behaves.
  • Do not put a trailing comma after self.name = name. That would store a tuple.
  • The four OOP ideas are abstraction, encapsulation, inheritance, and polymorphism.
  • Abstraction hides extra detail. Encapsulation wraps data and methods in one object.
