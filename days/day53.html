Day 53

Iterative Workflow in LangGraph

Generate a social post, evaluate it, then either stop or optimize and evaluate again. A loop, a max iteration cap, and a human in the loop before a real post.

696

What Is Iterative

An iterative workflow repeats until the work is good, or until we hit a limit. START generates. Then we evaluate. If it is good, we approve and end. If it fails, we need improvement. We optimize, then evaluate again. The diagram below is that loop.

697

A Social Media Post

We will make a workflow that posts on social media. It generates, evaluates, then either posts or optimizes and evaluates again. How do we evaluate? We make an iterative workflow. Topic goes to an LLM that generates a post. Another LLM evaluates it with a strict guideline. If approved, we post. Else we optimize through another LLM, then evaluate again. If yes, post. Else optimize again.

We do not usually post directly. We use a human in the loop. In the code, a good evaluation or a max iteration cap sends the graph to END. That stop is the approve moment. A person still decides before a real post goes out.

698

Tweet State

One ChatOpenRouter model serves the whole example. State holds the topic, the current tweet, a good or bad evaluation, feedback, the iteration count, and max iterations. tweet_history and feedback_history are lists. operator.add appends each new version so we keep the past.

LLM and state

from langchain_openrouter import ChatOpenRouter
from langchain_core.messages import SystemMessage, HumanMessage
from langgraph.graph import StateGraph, START, END
from pydantic import BaseModel, Field
from typing import Literal, Annotated
from typing_extensions import TypedDict
import operator
from dotenv import load_dotenv

load_dotenv()

llm = ChatOpenRouter(
    model="openrouter/free",
    temperature=0
)

class TweetState(TypedDict):
    topic: str
    tweet: str
    evaluation: Literal["good", "bad"]
    feedback: str
    iteration: int
    max_iterations: int
    tweet_history: Annotated[list[str], operator.add]
    feedback_history: Annotated[list[str], operator.add]

graph = StateGraph(TweetState)

Start histories as empty lists. Each node returns a one item list so add can join them.

699

Generate Tweet

generate_tweet is a social media manager. It reads the topic, asks the LLM for a high quality tweet, stores that tweet, and appends it to tweet_history. The prints help you watch the loop while it runs.

generate

def generate_tweet(state: TweetState):
    print("\n==============================")
    print("GENERATE NODE")
    print("==============================")
    print("Topic:")
    print(state["topic"])

    messages = [
        SystemMessage(
            content=(
                "You are a social media manager. "
                "Generate a high quality tweet about the given topic."
            )
        ),
        HumanMessage(
            content=f"Topic: {state['topic']}"
        )
    ]

    response = llm.invoke(messages)

    print("\nGenerated Tweet:")
    print(response.content)

    return {
        "tweet": response.content,
        "tweet_history": [response.content]
    }

This node runs once from START. Later loops go through optimize, not generate again.

700

Evaluate Tweet

The evaluator is also an LLM, with a strict guideline. TweetEvaluation forces good or bad, plus feedback. Return good only if the tweet is excellent. Otherwise return bad and explain how it can be improved. The score is not a number here. It is the word good or the word bad.

evaluate

class TweetEvaluation(BaseModel):
    evaluation: Literal["good", "bad"] = Field(
        description="Whether the tweet is good or bad."
    )
    feedback: str = Field(
        description="Feedback explaining how the tweet can be improved."
    )

structured_evaluator_llm = llm.with_structured_output(
    TweetEvaluation
)

def evaluate_tweet(state: TweetState):
    print("\n==============================")
    print("EVALUATE NODE")
    print("==============================")
    print("Current iteration:")
    print(state["iteration"])
    print("\nTweet being evaluated:")
    print(state["tweet"])

    messages = [
        SystemMessage(
            content=(
                "You are a strict social media manager. "
                "Evaluate the tweet carefully. "
                "Return good only if the tweet is excellent. "
                "Otherwise return bad and explain how it can be improved."
            )
        ),
        HumanMessage(
            content=f"""
Tweet:

{state["tweet"]}
"""
        )
    ]

    response = structured_evaluator_llm.invoke(messages)

    print("\nEvaluation:")
    print(response.evaluation)
    print("\nFeedback:")
    print(response.feedback)

    return {
        "evaluation": response.evaluation,
        "feedback": response.feedback,
        "feedback_history": [response.feedback]
    }

Each pass adds one feedback string to feedback_history.

701

Optimize Tweet

If the tweet is bad, optimize_tweet improves it with the evaluator feedback. It bumps iteration by 1. It writes the new tweet and appends that version to tweet_history.

optimize

def optimize_tweet(state: TweetState):
    print("\n==============================")
    print("OPTIMIZE NODE")
    print("==============================")
    print(
        f"Optimization iteration: "
        f"{state['iteration'] + 1} of {state['max_iterations']}"
    )
    print("\nOld Tweet:")
    print(state["tweet"])
    print("\nFeedback:")
    print(state["feedback"])

    messages = [
        SystemMessage(
            content=(
                "You are a social media manager. "
                "Improve the tweet using the evaluator feedback."
            )
        ),
        HumanMessage(
            content=f"""
Original Tweet:

{state["tweet"]}

Evaluator Feedback:

{state["feedback"]}

Improve the tweet significantly.
"""
        )
    ]

    response = llm.invoke(messages)
    new_iteration = state["iteration"] + 1

    print("\nImproved Tweet:")
    print(response.content)

    return {
        "tweet": response.content,
        "iteration": new_iteration,
        "tweet_history": [response.content]
    }

After optimize, the graph goes back to evaluate. That is the loop.

702

The Router

route_evaluation chooses the next step. If evaluation is good, return end. If iteration is already at max iterations, also return end. Otherwise the tweet is bad, so return optimize. The map sends optimize to the optimize node, and end to END.

route_evaluation

def route_evaluation(
    state: TweetState
) -> Literal["optimize", "end"]:
    print("\n==============================")
    print("ROUTER")
    print("==============================")
    print("Evaluation:")
    print(state["evaluation"])
    print("Iteration:")
    print(state["iteration"])
    print("Maximum Iterations:")
    print(state["max_iterations"])

    if state["evaluation"] == "good":
        print("\nTweet is GOOD")
        print("Stopping graph")
        return "end"

    if state["iteration"] >= state["max_iterations"]:
        print("\nMaximum iterations reached")
        print("Stopping graph")
        return "end"

    print("\nTweet is BAD")
    print("Sending tweet to optimizer")
    return "optimize"

max_iterations stops an endless loop if the evaluator never says good.

703

Build and Run

Edges are START to generate, generate to evaluate, then a conditional from evaluate. optimize goes back to evaluate. The topic is The future of AI. iteration starts at 0. max_iterations is 4. evaluation starts as bad. Histories start empty. invoke runs the loop. The prints at the end show the last tweet, evaluation, feedback, iteration count, and both histories.

Edges, compile, invoke

graph.add_node("generate", generate_tweet)
graph.add_node("evaluate", evaluate_tweet)
graph.add_node("optimize", optimize_tweet)

graph.add_edge(START, "generate")
graph.add_edge("generate", "evaluate")

graph.add_conditional_edges(
    "evaluate",
    route_evaluation,
    {
        "optimize": "optimize",
        "end": END
    }
)

graph.add_edge("optimize", "evaluate")

app = graph.compile()

initial_state = {
    "topic": "The future of AI",
    "tweet": "",
    "evaluation": "bad",
    "feedback": "",
    "iteration": 0,
    "max_iterations": 4,
    "tweet_history": [],
    "feedback_history": []
}

result = app.invoke(initial_state)

print("\n\n==============================")
print("FINAL RESULT")
print("==============================")
print("\nFinal Tweet:")
print(result["tweet"])
print("\nFinal Evaluation:")
print(result["evaluation"])
print("\nFinal Feedback:")
print(result["feedback"])
print("\nOptimization Iterations:")
print(result["iteration"])

print("\n==============================")
print("TWEET HISTORY")
print("==============================")
for index, tweet in enumerate(result["tweet_history"], start=1):
    print(f"\nTweet Version {index}:")
    print(tweet)

print("\n==============================")
print("FEEDBACK HISTORY")
print("==============================")
for index, feedback in enumerate(result["feedback_history"], start=1):
    print(f"\nFeedback {index}:")
    print(feedback)

The tweet text, evaluation, and feedback come from the model. We do not paste a fake post here. Run the cell to see yours. iteration will be between 0 and 4 depending on how many optimize passes ran.

Day 53 takeaways

Day 53 takeaways

  • An iterative graph generates, evaluates, then either stops or optimizes and evaluates again.
  • This social post flow uses a generate LLM, a strict evaluator LLM, and an optimize LLM.
  • If evaluation is good, or iteration reaches max iterations, the router returns end. Otherwise it returns optimize.
  • optimize always goes back to evaluate. generate runs only at the start.
  • tweet_history and feedback_history use operator.add so every version is kept.
  • We do not usually post directly. A human in the loop still approves before a real post.
