Day 26

Output Parsers in LangChain

Convert raw LLM text into usable fields with string, JSON, structured, and Pydantic parsers.

393

Why Output Parsers Matter

LLMs are great at natural language. But apps need consistent data for APIs, databases, and tools.

Output parsers convert raw model responses into a format you can reliably use.

In this day, we compare four common parser types and when to use each one.

394

String Output Parser

String output parsing is the simplest case.

You force the chain to return plain text instead of a model object with extra metadata.

from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import PromptTemplate
from langchain_groq import ChatGroq
from dotenv import load_dotenv

load_dotenv()

model = ChatGroq(model="llama-3.3-70b-versatile")

template1 = PromptTemplate(
    template="Write a detailed report on {topic}.",
    input_variables=["topic"],
)

template2 = PromptTemplate(
    template="Write a four-line summary of the following text:\n{text}",
    input_variables=["text"],
)

parser = StrOutputParser()

chain = (
    template1
    | model
    | parser
    | {"text": lambda text: text}
    | template2
    | model
    | parser
)

result = chain.invoke({"topic": "Nepal"})
print(result)

Here the parser makes the chain output a real string.

JSON Output Parser

JSON output parsing makes the model return JSON shaped data.

This is useful for connecting to code that expects key value fields.

The important limit is that JSON output parsing does not fully validate your full schema like Pydantic does.

from langchain_core.prompts import PromptTemplate
from langchain_core.output_parsers import JsonOutputParser
from langchain_groq import ChatGroq
from dotenv import load_dotenv

load_dotenv()

model = ChatGroq(model="llama-3.3-70b-versatile")
parser = JsonOutputParser()

template = PromptTemplate(
    template=(
        "Give me the name, age, and city of a fictional character.\n"
        "{format_instructions}"
    ),
    input_variables=[],
    partial_variables={
        "format_instructions": parser.get_format_instructions()
    },
)

chain = template | model | parser
result = chain.invoke({})

print(result)
print(result["name"])
print(result["age"])
print(result["city"])

Structured Output Parser

A structured output parser helps you shape a response into fields.

It can enforce the structure of the output format, but it does not do full data validation.

from langchain_classic.output_parsers import ResponseSchema, StructuredOutputParser
from langchain_core.prompts import PromptTemplate
from langchain_groq import ChatGroq
from dotenv import load_dotenv

load_dotenv()
model = ChatGroq(model="llama-3.3-70b-versatile")

schemas = [
    ResponseSchema(
        name="name",
        description="The name of the fictional character",
    ),
    ResponseSchema(
        name="age",
        description="The age of the fictional character",
    ),
    ResponseSchema(
        name="city",
        description="The city of the fictional character",
    ),
]

parser = StructuredOutputParser.from_response_schemas(schemas)

template = PromptTemplate(
    template=(
        "Give me the name, age, and city of a fictional character.\n"
        "{format_instructions}"
    ),
    input_variables=[],
    partial_variables={
        "format_instructions": parser.get_format_instructions()
    },
)

chain = template | model | parser
result = chain.invoke({"topic": "Nepal"})
print(result)

Use this when you want structure, but you do not need strict type validation.

Pydantic Output Parser

Pydantic output parsing gives you the strongest guarantees.

You define a Pydantic model, and the parser validates types and shapes.

from langchain_groq import ChatGroq
from dotenv import load_dotenv
from langchain_core.prompts import PromptTemplate
from langchain_core.output_parsers import PydanticOutputParser
from pydantic import BaseModel, Field

load_dotenv()

model = ChatGroq(model="llama-3.3-70b-versatile")

class Person(BaseModel):
    name: str = Field(description="The name of the fictional character")
    age: int = Field(
        gt=18,
        description="The age of the fictional character",
    )
    city: str = Field(description="The city of the fictional character")

parser = PydanticOutputParser(pydantic_object=Person)

template = PromptTemplate(
    template=(
        "Give me the name, age, and city of a fictional character "
        "from {place}.\n{format_instructions}"
    ),
    input_variables=["place"],
    partial_variables={
        "format_instructions": parser.get_format_instructions()
    },
)

prompt = template.invoke({"place": "Nepal"})
result = model.invoke(prompt)
final_result = parser.parse(result.content)

print(final_result)
print(final_result.name)

When types are wrong, Pydantic can raise an error so your app stays safe.

398

Output Parsers Work for Any LLM

Some models can generate structured output directly. Some cannot.

Output parsers still help in both cases by converting the raw response into your desired format.

So you can keep your app logic consistent, even when you swap providers.

399

Limitations to Know

Each parser gives a different level of safety:

  • String output parsing returns text, so it is simple but not typed.
  • JSON output parsing helps, but it does not fully validate your schema like Pydantic.
  • Structured output parsing shapes fields, but does not guarantee strict type validation.
  • Pydantic output parsing validates types and shapes at run time.
400

Quick Decision Guide

Parser Structured format Type validation
String Plain text No
JSON Keys and values Limited
Structured output Fields from schema descriptions No full validation
Pydantic Typed model Yes

If you need safe tool calls, choose Pydantic. If you only need simple text or JSON shaped fields, choose String or JSON.
