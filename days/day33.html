Recap: Core RAG Pieces So Far

In the RAG path we already covered three building blocks.

What you already learned

  1. Document loader Bring source files into LangChain Document objects.
  2. Text splitter Cut long text into chunks the model can use.
  3. Vector store Store embeddings and run similarity search.

Today we learn the retriever. It sits on top of a data source and returns the documents that match a query.

416

What Is a Retriever

A retriever takes a query, looks inside a data source, and returns one or more Document objects.

The data source can be a vector store, an API, Wikipedia, or another backend. The retriever is the bridge between your query and that source.

Query in, documents out

  1. Query The question or search text you send in.
  2. Retriever Goes into the data source and finds matches.
  3. Data source Vector store, Wikipedia API, Arxiv, and more.
  4. Documents Multiple LangChain Document objects come out.
417

Retrievers Are Runnables

Every retriever you meet in LangChain is a Runnable.

That matters for one reason. You can place a retriever inside a chain with the pipe operator, and connect it to prompts, models, and other Runnables you already know.

So a retriever is not only a search helper. It is also a chain building block.

418

Two Ways to Group Retrievers

You can sort retrievers in two useful ways. One is by data source. The other is by search strategy.

Grouping What it means Examples
By data source Where the retriever looks for text. Wikipedia, vector store, Arxiv, and similar APIs.
By search strategy How it picks and ranks documents. MMR, multi query, contextual compression.

Same goal every time: take a query and return useful documents. The source and the strategy change how that search runs.

419

Wikipedia Retriever

The Wikipedia retriever calls the Wikipedia API, finds articles that match your query, and returns them as LangChain Document objects.

Matching here is keyword based. It picks the most relevant articles for that query. It does not download the whole encyclopedia.

Wikipedia as the data source

  1. Query You ask a question.
  2. Wikipedia API Keyword search finds matching articles.
  3. Documents Relevant pages come back as Document objects.

You might think this is a document loader. It is not. A loader reads a known source end to end. A retriever searches and returns only what matches the query. That search step is why Wikipedia access here is a retriever.

Here is a working Wikipedia retriever. Set OPENAI_API_KEY in your environment only for the embedding examples later. Wikipedia search itself does not need that key.

Wikipedia retriever

from langchain_community.retrievers import WikipediaRetriever

# Optional: language and how many articles to return.
retriever = WikipediaRetriever(top_k_results=2, lang="en")

query = (
    "the geopolitical history of india and pakistan "
    "from the perspective of a chinese"
)
docs = retriever.invoke(query)

for i, doc in enumerate(docs):
    print(f"\n--- Result {i+1} ---")
    print(f"Content:\n{doc.page_content}...")

What you get

--- Result 1 ---
Content:
<Wikipedia article text for a matching page>...

--- Result 2 ---
Content:
<Wikipedia article text for another matching page>...

Exact article text changes over time. You get LangChain Document objects, not a full Wikipedia dump.

Vector Store Retriever

This is the most common retriever type in RAG. It fetches documents from a vector store using semantic similarity.

Store once, retrieve by meaning

  1. Documents Your chunks of text.
  2. Embeddings An embedding model turns text into vectors.
  3. Vector store Vectors sit ready for search.
  4. Query path Query becomes a vector, then the store finds close matches.

You can call similarity search on the vector store directly. That works for one fixed strategy.

The retriever layer is still useful. It is a Runnable, so it plugs into chains. It also unlocks advanced search strategies such as MMR, multi query, and contextual compression, without rewriting your whole pipeline.

Build a small Chroma store, turn it into a retriever with as_retriever, then compare that path with a direct similarity_search call.

Vector store retriever with Chroma

from langchain_community.vectorstores import Chroma
from langchain_openai import OpenAIEmbeddings
from langchain_core.documents import Document

documents = [
    Document(page_content="LangChain helps developers build LLM applications easily."),
    Document(page_content="Chroma is a vector database optimized for LLM-based search."),
    Document(page_content="Embeddings convert text into high-dimensional vectors."),
    Document(page_content="OpenAI provides powerful embedding models."),
]

embedding_model = OpenAIEmbeddings()

vectorstore = Chroma.from_documents(
    documents=documents,
    embedding=embedding_model,
    collection_name="my_collection",
)

retriever = vectorstore.as_retriever(search_kwargs={"k": 2})

query = "What is Chroma used for?"
results = retriever.invoke(query)

for i, doc in enumerate(results):
    print(f"\n--- Result {i+1} ---")
    print(doc.page_content)

# Same idea without the retriever wrapper.
results = vectorstore.similarity_search(query, k=2)

for i, doc in enumerate(results):
    print(f"\n--- Result {i+1} ---")
    print(doc.page_content)

What you get

--- Result 1 ---
Chroma is a vector database optimized for LLM-based search.

--- Result 2 ---
<second closest document from the four above>

Needs packages such as langchain, chromadb, openai, tiktoken, langchain_openai, and langchain-community. Ranking of the second hit can shift with the embedding model.

MMR: Maximum Marginal Relevance

MMR is a search strategy. It keeps results relevant to the query, and it also pushes for variety so you do not get near duplicate answers.

Imagine five documents about climate topics. Your query is: what are the effects of climate change.

Doc ID Content
D1 Climate change is causing glaciers to melt rapidly in the Arctic region.
D2 Glaciers in the Arctic are melting at an alarming rate due to rising temperatures.
D3 Deforestation in the Amazon is accelerating global climate change.
D4 Climate change is increasing the frequency of wildfires in California.
D5 Rising sea levels due to climate change threaten coastal cities like Mumbai and New York.

Look at D1 and D2. Both talk about Arctic glaciers melting. Plain semantic search might return D1, D2, and D3. That wastes a slot on the same idea twice.

MMR works in steps. First it picks the most relevant document. Next it picks another relevant document that is different from the ones already chosen. It keeps going until it fills k results.

How MMR picks documents

  1. Most relevant Take the best match for the query first.
  2. Relevant and different Next pick must stay useful and not copy the first.
  3. Repeat to k Build a short list that covers more sides of the topic.

In LangChain you set the search type to MMR and pass search kwargs. k is how many documents to return. lambda_mult is a number from 0 to 1 that balances relevance and diversity.

Here is the same idea with FAISS and a small LangChain document set.

MMR with FAISS

from langchain_core.documents import Document
from langchain_community.vectorstores import FAISS
from langchain_openai import OpenAIEmbeddings

docs = [
    Document(page_content="LangChain makes it easy to work with LLMs."),
    Document(page_content="LangChain is used to build LLM based applications."),
    Document(page_content="Chroma is used to store and search document embeddings."),
    Document(page_content="Embeddings are vector representations of text."),
    Document(page_content="MMR helps you get diverse results when doing similarity search."),
    Document(page_content="LangChain supports Chroma, FAISS, Pinecone, and more."),
]

embedding_model = OpenAIEmbeddings()

vectorstore = FAISS.from_documents(
    documents=docs,
    embedding=embedding_model,
)

retriever = vectorstore.as_retriever(
    search_type="mmr",
    search_kwargs={"k": 3, "lambda_mult": 0.5},
)

query = "What is langchain?"
results = retriever.invoke(query)

for i, doc in enumerate(results):
    print(f"\n--- Result {i+1} ---")
    print(doc.page_content)

What you get

--- Result 1 ---
LangChain makes it easy to work with LLMs.

--- Result 2 ---
<another relevant doc that is not a near copy of Result 1>

--- Result 3 ---
<third diverse relevant doc>

k=3 returns three documents. lambda_mult sits between 0 and 1 to balance relevance and diversity. Exact order depends on embeddings. Install faiss-cpu for this example.

Multi Query Retriever

User queries are often vague or broad. The documents in your store may use different words than the user used.

Example: the user asks how do I manage my sleep, but your docs talk about nutrition habits that also affect sleep. One narrow query can miss those chunks.

The multi query retriever asks an LLM to rewrite the user query into several diverse but related queries. Each rewritten query goes to the retriever. Results are merged, and duplicates are removed.

One vague query becomes many searches

  1. User query Often broad or worded differently than your docs.
  2. LLM rewrites Creates several related queries with different angles.
  3. Retrieve each Run retrieval for every rewritten query.
  4. Merge Combine hits and drop duplicates for the final list.

Compare a plain similarity retriever with MultiQueryRetriever on the same FAISS store. The query is broad: how to improve energy levels and maintain balance.

Multi query versus similarity

from langchain_community.vectorstores import FAISS
from langchain_openai import OpenAIEmbeddings, ChatOpenAI
from langchain_core.documents import Document
from langchain.retrievers.multi_query import MultiQueryRetriever

all_docs = [
    Document(
        page_content="Regular walking boosts heart health and can reduce symptoms of depression.",
        metadata={"source": "H1"},
    ),
    Document(
        page_content="Consuming leafy greens and fruits helps detox the body and improve longevity.",
        metadata={"source": "H2"},
    ),
    Document(
        page_content="Deep sleep is crucial for cellular repair and emotional regulation.",
        metadata={"source": "H3"},
    ),
    Document(
        page_content="Mindfulness and controlled breathing lower cortisol and improve mental clarity.",
        metadata={"source": "H4"},
    ),
    Document(
        page_content="Drinking sufficient water throughout the day helps maintain metabolism and energy.",
        metadata={"source": "H5"},
    ),
    Document(
        page_content="The solar energy system in modern homes helps balance electricity demand.",
        metadata={"source": "I1"},
    ),
    Document(
        page_content="Python balances readability with power, making it a popular system design language.",
        metadata={"source": "I2"},
    ),
    Document(
        page_content="Photosynthesis enables plants to produce energy by converting sunlight.",
        metadata={"source": "I3"},
    ),
    Document(
        page_content="The 2022 FIFA World Cup was held in Qatar and drew global energy and excitement.",
        metadata={"source": "I4"},
    ),
    Document(
        page_content="Black holes bend spacetime and store immense gravitational energy.",
        metadata={"source": "I5"},
    ),
]

embedding_model = OpenAIEmbeddings()
vectorstore = FAISS.from_documents(
    documents=all_docs,
    embedding=embedding_model,
)

similarity_retriever = vectorstore.as_retriever(
    search_type="similarity",
    search_kwargs={"k": 5},
)

multiquery_retriever = MultiQueryRetriever.from_llm(
    retriever=vectorstore.as_retriever(search_kwargs={"k": 5}),
    llm=ChatOpenAI(model="gpt-3.5-turbo"),
)

query = "How to improve energy levels and maintain balance?"

similarity_results = similarity_retriever.invoke(query)
multiquery_results = multiquery_retriever.invoke(query)

for i, doc in enumerate(similarity_results):
    print(f"\n--- Result {i+1} ---")
    print(doc.page_content)

print("*" * 150)

for i, doc in enumerate(multiquery_results):
    print(f"\n--- Result {i+1} ---")
    print(doc.page_content)

What you get

--- Result 1 ---
<similarity hits, often pulled by the word energy>

**************************************************************************************

--- Result 1 ---
<multi query hits after LLM rewrites, often more health focused>

Similarity alone can grab docs that only share the word energy, such as solar or World Cup lines. Multi query rewrites the ask, so health and wellness docs show up more often. Exact lists change with the LLM.

Contextual Compression Retriever

This is an advanced retrieval pattern. First a base retriever returns documents. Then a compressor, often an LLM, trims each document so only the parts that matter for the query remain.

Why do you need that. After text splitting, one chunk can still hold several unrelated facts. The retriever may return that whole chunk even when only one sentence answers the question.

Example chunk: Mt Everest is the highest peak in the world. Nepal heritage is very good. Bishal lives in Kathmandu.

Query: where does Bishal live.

Retrieve, then compress

  1. Query Where does Bishal live.
  2. Base retriever Returns a few chunks, for example D1 and D2.
  3. Compressor LLM Query plus each doc go to the LLM to drop noise.
  4. Trimmed docs You keep lines like Bishal lives in Kathmandu.

The name compression fits. The LLM squeezes each retrieved document down to the relevant bits. LangChain has more retrievers beyond these three strategies, but MMR, multi query, and contextual compression cover the main ideas you will use often.

In code, a base retriever finds candidate chunks, then LLMChainExtractor keeps only the lines that answer the query.

Contextual compression retriever

from langchain_community.vectorstores import FAISS
from langchain_openai import OpenAIEmbeddings, ChatOpenAI
from langchain.retrievers.contextual_compression import ContextualCompressionRetriever
from langchain.retrievers.document_compressors import LLMChainExtractor
from langchain_core.documents import Document

docs = [
    Document(
        page_content=(
            "The Grand Canyon is one of the most visited natural wonders in the world. "
            "Photosynthesis is the process by which green plants convert sunlight into energy. "
            "Millions of tourists travel to see it every year. "
            "The rocks date back millions of years."
        ),
        metadata={"source": "Doc1"},
    ),
    Document(
        page_content=(
            "In medieval Europe, castles were built primarily for defense. "
            "The chlorophyll in plant cells captures sunlight during photosynthesis. "
            "Knights wore armor made of metal. "
            "Siege weapons were often used to breach castle walls."
        ),
        metadata={"source": "Doc2"},
    ),
    Document(
        page_content=(
            "Basketball was invented by Dr. James Naismith in the late 19th century. "
            "It was originally played with a soccer ball and peach baskets. "
            "NBA is now a global league."
        ),
        metadata={"source": "Doc3"},
    ),
    Document(
        page_content=(
            "The history of cinema began in the late 1800s. Silent films were the earliest form. "
            "Thomas Edison was among the pioneers. "
            "Photosynthesis does not occur in animal cells. "
            "Modern filmmaking involves complex CGI and sound design."
        ),
        metadata={"source": "Doc4"},
    ),
]

embedding_model = OpenAIEmbeddings()
vectorstore = FAISS.from_documents(docs, embedding_model)

base_retriever = vectorstore.as_retriever(search_kwargs={"k": 5})

llm = ChatOpenAI(model="gpt-3.5-turbo")
compressor = LLMChainExtractor.from_llm(llm)

compression_retriever = ContextualCompressionRetriever(
    base_retriever=base_retriever,
    base_compressor=compressor,
)

query = "What is photosynthesis?"
compressed_results = compression_retriever.invoke(query)

for i, doc in enumerate(compressed_results):
    print(f"\n--- Result {i+1} ---")
    print(doc.page_content)

What you get

--- Result 1 ---
Photosynthesis is the process by which green plants convert sunlight into energy.

--- Result 2 ---
The chlorophyll in plant cells captures sunlight during photosynthesis.

--- Result 3 ---
Photosynthesis does not occur in animal cells.

Canyon, castle, and cinema lines get dropped. Exact wording from the compressor can vary slightly with the model.
