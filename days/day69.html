Why We Need CRAG

In traditional RAG the user asks a question. The retriever finds the Top K documents. Those documents are sent to the LLM. The LLM generates an answer. That is retrieval, then augment, then generation. The problem is this. Retrieved documents are not always relevant or accurate. Traditional RAG may use them without properly checking their quality. CRAG solves this by introducing a retrieval evaluator to check the documents before generating an answer. The cards below are those RAG names.

Retrieval

Find the Top K docs that look close to the question.

Augmented

Put the retrieved data and the question into the LLM.

Generation

The LLM writes the answer.

It might give documentation of a chatbot, or of random forest. The LLM will reply, because RAG gave it that answer. The cards below are that miss.

917

Leave Policy and Parametric Data

Like in a business scenario. A user asks if there is a leave policy, but there is no answer in the store. The LLM might give a wrong answer, because the vector database is not able to give the answer, and it still gives the wrong doc. If traditional RAG does not have the data from the doc, it uses parametric data for the reply. That is knowledge already inside the model weights. It has a high chance of hallucination. This is where CRAG comes in.

918

CRAG Puts a Check Before the LLM

The big difference in CRAG is this. We do not directly send the retrieved docs to the main LLM. We put a retrieval evaluator before it. It checks if the retrieved data we got is useful or not. CRAG does not assume the docs are right. The picture below is that extra check.

919

Three Cases

After scoring, CRAG picks one of three cases. Correct means at least one document has a high enough score. Then we refine the original documents into internal knowledge. Incorrect means all documents have very low scores. Then we discard those originals and search the web for external knowledge. Ambiguous means neither clearly correct nor incorrect. Then we refine the originals and also search the web, and we combine both knowledge sources. The table below is that branch.

Decision What CRAG does
Correct Refine the original docs. Send internal knowledge to the main LLM.
Incorrect Discard the originals. Rewrite the query. Search the web. Send external knowledge.
Ambiguous Refine the originals and search the web. Combine both knowledge sources.

Knowledge Refinement

When at least one document scores above the upper threshold, CRAG follows the Correct path. We perform knowledge refinement. We apply refinement to the retrieved documents, not just the ones scoring above the upper threshold. Why? Even a low scoring document might contain a useful sentence. During filtering, the evaluator checks the smaller pieces again. In the paper, it keeps up to 5 useful strips, with a filtering threshold of minus 0.5. We send the original question and this refined internal knowledge to the main LLM. The LLM generates the answer. The graph below is retrieve, then refine, then generate.

922

Decompose, Filter, Recompose

Think of refinement as three stages across the retrieved documents. Decompose all. Filter the pieces. Recompose useful pieces. Decomposition means breaking documents into smaller text pieces called strips. Filter means score each strip and remove the ones that are not relevant. Recompose means combine useful strips in order. That merge is internal knowledge. In actual code, processing each document using a loop is also possible. The steps below are those three stages.

Refine the retrieved docs

  1. Decompose Break D1, D2, D3, D4 into smaller strips.
  2. Filter Score each strip. Drop the ones that are not relevant.
  3. Recompose Join useful strips in order. That is internal knowledge.
923

Retrieval Evaluator

We send each document along with the original question to the retrieval evaluator. The evaluator gives each document a score. Higher score means more relevant to the question. The paper uses a specially trained T5 model to evaluate the documents. That is not the main LLM that writes the final answer. The paper evaluator gives scores between minus 1 and plus 1. In our own CRAG we can use Jev for this job, or another latest classification model that gives a score. Jev is built to score and classify, not to write the final answer. If we switch the scorer, we also retune the thresholds, because the numbers will not match the T5 range. Here is a paper style example with K equal to 4. The table below is that scoring.

Document Example score
D1 0.90
D2 minus 0.40
D3 0.50
D4 minus 0.80
924

Correct, Incorrect, or Ambiguous

We use two thresholds. The upper threshold determines whether a document is good enough. The lower threshold determines whether a document is very poor. For illustration, suppose the upper threshold is 0.8 and the lower threshold is minus 0.3. Correct means at least one document scores above the upper threshold. Incorrect means all retrieved documents score below the lower threshold. Ambiguous is the rest. Not every document needs to score in the middle. For ambiguous, some documents can be below the lower threshold. The only requirement is that no document is above the upper threshold, and not all documents are below the lower threshold. The table below is that decision.

Scores of 4 documents Decision
0.9, 0.2, minus 0.5, 0.1 Correct. One score is above 0.8.
minus 0.8, minus 0.5, minus 0.6, minus 0.9 Incorrect. All scores are below minus 0.3.
0.5, 0.3, minus 0.7, 0.1 Ambiguous. None above 0.8, and not all below minus 0.3.

How We Pick Thresholds

The paper does mention the thresholds in its appendix. Those are the values the researchers used. They are not universal. Your own evaluator may give very different scores. For your own CRAG system, collect around 100 real questions, score their retrieved documents, test different threshold values, and see which settings produce the best answers. Incorrect Path and Web Search

When all retrieved documents score below the lower threshold, CRAG decides Incorrect. It discards the original retrieved documents. Then it rewrites the question, searches the web, extracts web page text, and selects relevant information. That useful web information is called external knowledge. Web results are documents too, in a practical sense. The search returns website links. CRAG accesses those web pages and extracts their text. Knowledge refinement is also applied to web results, but with a small difference. For internal documents, CRAG breaks text into smaller strips. For web pages, the paper uses existing paragraphs from the pages and selects the relevant ones. It generally does not need to split them further. Finally the original question plus external knowledge goes to the main LLM. The table below is that difference.

Internal documents Web pages
Break text into smaller strips, then filter and recompose. Use existing paragraphs. Select the relevant ones. No extra split, in general.

Query Rewrite

We do not search the original question directly. The original user question may not be ideal for a search engine. Query rewriting is used for web search, not for the Correct path. In the paper, ChatGPT is used to create search keywords. Then web search uses that better query. The block below is that rewrite. The steps below are the Incorrect path.

Rewrite for search

Original question: Who invented the telephone?
Rewritten search query: telephone inventor Alexander Graham Bell history

The rewrite adds search keywords. It is not used on the Correct path.

Incorrect path

  1. Discard All retrieved docs scored below the lower threshold.
  2. Rewrite Turn the question into web search keywords.
  3. Web search Open pages, pick useful paragraphs, then generate.
928

Handling Ambiguity

When CRAG is unsure about the retrieved documents, it uses both sources. Ambiguous means no document is above the upper threshold, and not all documents are below the lower threshold. Some documents can still be below the lower threshold. We refine the original documents into internal knowledge. We also search the web and select useful text as external knowledge. Then we combine both knowledge sources. The original question plus that combined knowledge goes to the main LLM. This path is useful because CRAG does not have to completely trust or completely discard uncertain retrieved information. The table below is what each path sends.

Path What the generator gets
Correct The original question plus refined internal knowledge.
Ambiguous The original question plus internal knowledge plus external knowledge.
Incorrect The original question plus external knowledge.

The Full CRAG Picture

Here is the complete CRAG flow at a glance. The user asks a question. We retrieve Top K documents. The retrieval evaluator scores each document and decides. Correct refines the original documents into internal knowledge. Incorrect discards the originals, searches the web, and builds external knowledge. Ambiguous does both, then combines both knowledge sources. The main LLM generates the final answer. Day 69 takeaways

The one sentence to remember is this. Traditional RAG retrieves documents and uses them to answer. CRAG first evaluates those documents, decides whether to use them or search for better information, removes content that is not relevant, and then sends the useful information to the LLM. CRAG improves the quality of information given to the LLM, but it cannot guarantee that every retrieved fact or final answer is correct. The table below is the word list.

Term Simple meaning
Top K Number of documents retrieved.
Retrieval evaluator Model that checks document relevance. The paper uses a trained T5. We can also use Jev, or another classification model that gives a score.
Score How useful a document seems for the question. Paper range is minus 1 to plus 1.
Threshold Limit used to make a decision. Pick it on your data. Paper values are not universal.
Correct At least one document has a high enough score.
Incorrect All documents have very low scores.
Ambiguous Neither clearly Correct nor Incorrect.
Knowledge strip Small piece of document text.
Internal knowledge Useful information from original documents, after refine.
Query rewriting Turn a question into web search keywords. Used for web search, not the Correct path.

Day 69 takeaways

  • Traditional RAG sends Top K docs to the LLM with no quality check.
  • CRAG scores each doc, then picks Correct, Incorrect, or Ambiguous.
  • Correct refines all retrieved docs into internal knowledge, not only the high scoring ones.
  • Incorrect discards the originals, rewrites the question, and searches the web.
  • Ambiguous uses both internal knowledge and external knowledge.
  • CRAG cannot guarantee every fact or answer is correct.
