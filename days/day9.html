Day 9

Machine Learning Life Cycle

54

What Is MDLC

This day is different from earlier topics. About 90% of what we cover next comes from here.

MDLC means Machine Learning Development Life Cycle. It is similar to SDLC. When we build software, we follow SDLC. MDLC teaches us how to build machine learning from idea to product.

As students we often only train the model. Companies need an end to end product.

MDLC has 9 steps. Most future lessons in this series will grow from these steps. The steps are not fixed forever. They can change. The main idea: build ML end to end.

The 9 steps of MDLC.

  1. Framing Define the problem.
  2. Gather Collect data.
  3. Process Clean and format.
  4. EDA Explore patterns.
  5. Features Engineer and select.
  6. Train Evaluate models.
  7. Deploy Ship to users.
  8. Test Beta and A/B.
  9. Optimize Scale and retrain.
55

Framing the Problem

Step 1 happens before any code. It is our job to find all the important details.

  • Cost: what budget and resources do we have?
  • Supervised or not: do we have labels for training?
  • Algorithm: which approach might fit this problem?
  • Data: how will we get the data we need?

Good framing saves time later. A vague problem leads to a weak product.

56

Gathering the Data

This is one of the most important steps. We rarely get data exactly as we want.

Without data we cannot go further.

Data can come from many sources:

  • API (often JSON).
  • Web scraping.
  • Surveys.
  • Company databases, sometimes built into a data warehouse.
  • Data stored in a cluster.

Bringing data together is a critical stage in the life cycle.

57

Data Processing

Raw data is not clean. It can be noisy. Columns may not match. We must preprocess the data.

Common tasks:

  • Remove duplicates.
  • Handle missing data.
  • Remove outliers.
  • Scale values (one column may be very big, another very small).

The key idea: clean and format the data. This step is also called data preprocessing.

58

Exploratory Data Analysis

EDA means we read the input and output. We experiment with the data before modeling.

We make graphs and study patterns:

  • Univariate: mean, median, and curve of each column alone.
  • Bivariate: relationship between two columns.
  • Multivariate: more than two columns together.

Imbalance: handle unbalanced data. Example: dog vs cat classification where cat images far outnumber dog images.

59

Feature Engineering and Selection

We create new columns or remove useless ones.

Example: a house pricing model has number of rooms and washrooms but not square feet. We may drop those columns because we need square feet to predict price well.

We decide which features to use and when. Good features often matter more than a fancy algorithm.

60

Model Training, Evaluation, and Selection

We try multiple algorithms. Not every algorithm fits every problem.

In evaluation we compare different models. This helps us pick which algorithm to use.

Ensemble learning: join multiple ML models to make a stronger result.

Hyperparameter tuning: adjust settings to improve the model.

This is one of the most important things we do in the life cycle.

61

Model Deployment

Turn the model into real software: website, desktop app, and more.

Typical flow:

train model → save binary file → expose API → return JSON.

The user gives input. The Python app gets the data. The model returns a JSON answer.

We build an end to end website. Platforms like Heroku, GCP, and AWS help host it.

62

Testing

Beta testing: only a limited group gets the latest feature. We collect feedback before a full launch.

A/B testing: run two versions. If the new model is good, it stays. If it is bad, we go back to the step that needs fixing.

Testing keeps bad models from reaching all users.

63

Optimization

After launch, we keep the system healthy. Common work:

  • Backup and rollback.
  • Automation setup.
  • Load balancing and concurrent processes so many people can use it.
  • Retrain when the model gets old and unreliable (the model has "rotten").
  • Set how often to retrain.
  • Optimize cost, tokens, and more.

Day 9 takeaways

  • MDLC is the roadmap from idea to product, like SDLC for software.
  • Nine steps: frame, gather, process, explore, engineer features, train, deploy, test, optimize.
  • Most of this series builds on these steps. Train the model is only one part.

Companies hire for end to end skills. This life cycle is what separates a notebook from a real product.
