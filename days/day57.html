Day 57

Streaming in LangGraph

Tokens arrive as the model writes them. Use stream instead of invoke, message mode, and Streamlit write_stream so the chat feels like a typewriter.

740

The Wait Problem

We notice that when we say give a 500 word essay, it takes time and gives the result at once. It works. The user experience is not good. The page sits still. Then a long block appears. That is why we use streaming.

741

What Is Streaming

In an LLM, streaming means the model starts sending tokens, which are words, as soon as they are generated. It does not wait for the entire response to be ready before returning it. We get the answer token by token. ChatGPT does this. It is like a typewriter effect. The picture below is wait for all versus token by token.

742

Why Streaming Matters

Streaming is very important. It increases the user experience by 10x. The cards below are five reasons.

Faster feel

The first words show sooner. Drop rates stay lower. The user is less likely to think the website is frozen.

Human like talk

It mimics conversation. That builds trust. It feels alive. It keeps the user engaged.

Voice and more

Important for a multi modal UI. Ask an Alexa type device for a pasta recipe. A 10 second wait, then one dump, does not feel comfortable.

Long output

Strong UX for long output such as code. If we see the whole code at once, it is hard to understand.

Stop and watch

We can cancel midway and save tokens. We can also see the process, like an agent open a site and read a blog.

invoke Versus stream

The change is small. Instead of graph.invoke we use graph.stream. stream is a generator. We use a loop to read each chunk. There are multiple stream modes, such as messages and others. For an LLM response we use message mode. The table below puts invoke next to stream.

invoke stream
Wait. Then return the full answer. A generator. Yield chunks as they arrive.
One result at the end. A loop reads each chunk. Message mode for LLM text.

Back End with streaming True

The back end is the same chat graph as Day 56. ChatState still uses add_messages. The model is ChatOpenRouter with streaming set to True. The node still calls llm.invoke. The compiled chatbot is what the page will stream from.

langgraph_backend.py

from langgraph.graph import StateGraph, START, END
from typing import TypedDict, Annotated
from langchain_core.messages import BaseMessage
from langchain_openrouter import ChatOpenRouter
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.graph.message import add_messages
from dotenv import load_dotenv

load_dotenv()

llm = ChatOpenRouter(
    model="openrouter/free",
    temperature=0,
    streaming=True
)

class ChatState(TypedDict):
    messages: Annotated[list[BaseMessage], add_messages]

def chat_node(state: ChatState):
    messages = state["messages"]
    response = llm.invoke(messages)
    return {
        "messages": [response]
    }

checkpointer = InMemorySaver()

graph = StateGraph(ChatState)
graph.add_node("chat_node", chat_node)
graph.add_edge(START, "chat_node")
graph.add_edge("chat_node", END)

chatbot = graph.compile(
    checkpointer=checkpointer
)

streaming True tells the model it may send tokens as they are made. The front end will call chatbot.stream, not chatbot.invoke.

write_stream on the Page

The Streamlit page still keeps message_history. After the user line, we open an assistant bubble. stream_response is a generator. It loops chatbot.stream with stream_mode set to messages. Each item is a message chunk and metadata. If the chunk has content, we yield that text. st.write_stream draws those pieces as they arrive. Then we save the full ai_message in history.

Streamlit page

import streamlit as st
from langgraph_backend import chatbot
from langchain_core.messages import HumanMessage

CONFIG = {
    "configurable": {
        "thread_id": "thread-1"
    }
}

if "message_history" not in st.session_state:
    st.session_state["message_history"] = []

for message in st.session_state["message_history"]:
    with st.chat_message(message["role"]):
        st.write(message["content"])

user_input = st.chat_input("Type here")

if user_input:
    st.session_state["message_history"].append(
        {
            "role": "user",
            "content": user_input
        }
    )

    with st.chat_message("user"):
        st.write(user_input)

    with st.chat_message("assistant"):

        def stream_response():
            for message_chunk, metadata in chatbot.stream(
                {
                    "messages": [
                        HumanMessage(content=user_input)
                    ]
                },
                config=CONFIG,
                stream_mode="messages"
            ):
                if message_chunk.content:
                    yield message_chunk.content

        ai_message = st.write_stream(
            stream_response()
        )

    st.session_state["message_history"].append(
        {
            "role": "assistant",
            "content": ai_message
        }
    )

The words on screen come from the model one chunk at a time. We do not paste a fake essay here. Run the app and ask for a long reply to see the typewriter effect.

Day 57 takeaways

Day 57 takeaways

  • invoke waits, then returns the whole answer. That feels slow on a 500 word essay.
  • Streaming sends tokens, which are words, as soon as they are generated.
  • It feels faster, more human, better for voice and long code, and you can stop midway.
  • Use graph.stream. It is a generator. For LLM text use stream_mode messages.
  • Set streaming True on the model. On the page, loop the stream and pass it to write_stream.
