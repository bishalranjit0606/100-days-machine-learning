Day 23

LangChain Models

Language models, chat models, open source options, Hugging Face, and embedding models for search.

277

Why Models Matter

Models are a crucial part of the LangChain framework.

They are how your app talks to language models and embedding models.

Without this layer, every provider would need its own custom code. With LangChain models, you get one clear way to call many backends.

278

Model Types at a Glance

LangChain groups models into two big families.

  1. Language models. Text goes in. Text comes out. Inside this family you will see LLMs and chat models.
  2. Embedding models. Text goes in. Vector data comes out. These help with semantic search and RAG based applications.

Today we go deep on both families, starting with language models.

279

LLMs Explained

A language model takes text as input and returns text as output.

An LLM is a general purpose model. You can use it for text generation, code generation, and many other tasks.

Key points about classic LLMs:

  • They are becoming old style in modern apps.
  • In LangChain they are being removed slowly.
  • They were trained on books, articles, and similar text.
  • They do not remember a previous conversation by themselves.
  • You cannot assign a role like "act like a doctor" in the same clean way chat models support.

For new work, prefer chat models. The rest of this day uses chat style APIs.

280

Chat Models Explained

Chat models are specialized for conversation. They are the best fit for chatbots and AI agents.

Why teams pick them:

  • Optimized for multi turn conversation.
  • Trained on books and chat style data, including forums like Reddit.
  • They can remember previous turns in a chat session (when you pass history).
  • You can assign roles, such as system, user, and assistant.

If you are building a chatbot or an agent, start with a chat model.

281

LLM vs Chat Model

Use this side by side view when you choose an API.

Topic LLM Chat model
Best for General text and code generation Chatbots and AI agents
Conversation No built in multi turn style Built for multi turn chat
Roles Hard to assign chat roles cleanly Roles like system and user
In LangChain Being removed slowly The path you should use now
282

Call ChatGroq

Here is a minimal chat model call with Groq and LangChain.

Put your API key in a .env file, load it with dotenv, then invoke the model.

from langchain_groq import ChatGroq
from dotenv import load_dotenv

load_dotenv()

llm = ChatGroq(model="llama-3.3-70b-versatile")

result = llm.invoke("what is the capital of nepal")

print(result.content)

result.content is the text answer. The same pattern works when your .env lives one folder up, for example load_dotenv("../llm/.env").

283

Temperature

Temperature controls how much creativity the model adds to its answers.

The range often goes from 0 to about 1.5 or a bit higher, depending on the provider.

  • For math like tasks, keep it low: about 0.0 to 0.5.
  • For creative writing, raise it: about 0.7 to 1.5+.

Pass it when you build the model object:

model = ChatGroq(
    model="llama-3.3-70b-versatile",
    temperature=1.5,
)
284

Max Tokens and Metadata

Max tokens means the model will not use more tokens than that limit for the reply.

You can also inspect response metadata and usage after each call.

from langchain_groq import ChatGroq
from dotenv import load_dotenv

load_dotenv("../llm/.env")

model = ChatGroq(
    model="llama-3.3-70b-versatile",
    temperature=1.5,
    max_tokens=100,
)

result = model.invoke("write 5 one line quotes on motivation")

print(result.content)
print(result.response_metadata)
print(result.usage_metadata)

Use a small max_tokens value when you want short answers and tighter cost control.

Open Source Models

Open source models are free AI models you can download and modify.

You can deploy them without the restrictions of a single central provider.

In practice that means:

  • You download the model and use it how you want.
  • You can modify it.
  • You can deploy it yourself.
  • You get full access to the weights.
  • Data privacy is stronger when you keep the model on your own machines.
  • You can fine tune it for your domain.

Famous open source families include Llama, Gemma, and DeepSeek.

286

Find Models on Hugging Face

Hugging Face is where many teams find open models.

The hub has many task types: multimodal, text generation, and more.

Two common ways to use Hugging Face models:

  1. Call them through the Hugging Face API.
  2. Run them locally on your machine.

Trade offs to know before you choose local:

  • Local runs often need large hardware.
  • Setup can be complex.
  • Many open models lack strong RLHF, meaning less fine tuning with human feedback than big closed chat products.

Store your token in .env:

HUGGINGFACEHUB_ACCESS_TOKEN="ACCESS TOKEN"
287

Hugging Face API

With the API path, Hugging Face hosts the model. Your code only sends requests.

from langchain_huggingface import ChatHuggingFace, HuggingFaceEndpoint
from dotenv import load_dotenv

load_dotenv()

llm = HuggingFaceEndpoint(
    repo_id="id of the repo we want",
    task="text-generation",
)

model = ChatHuggingFace(llm=llm)
result = model.invoke("what is the capital of nepal")

print(result.content)

Replace repo_id with the model id you pick on the Hugging Face hub.

288

Hugging Face Local Pipeline

Local mode downloads the model and runs it on your machine. No live API call to Hugging Face for each prompt.

from langchain_huggingface import ChatHuggingFace, HuggingFacePipeline

llm = HuggingFacePipeline.from_model_id(
    model_id="id of the repo we want",
    task="text-generation",
    pipeline_kwargs=dict(
        temperature=0.5,
        max_new_tokens=100,
    ),
)

model = ChatHuggingFace(llm=llm)
result = model.invoke("what is the capital of nepal")

print(result.content)

Expect a large download the first time, and enough RAM or GPU for the model size you choose.

289

Embedding Models

Embedding models turn text into vector numbers.

Those vectors make semantic search possible. Similar meaning lands near similar vectors.

That is the base for many RAG based applications: store document vectors, embed the user question, then find the closest chunks.

290

Embed a Query

With OpenAI embeddings in LangChain, you create an embedding client and call embed_query for one string.

Dimensions control vector size. Lower dimensions usually mean lower cost.

from langchain_openai import OpenAIEmbeddings
from dotenv import load_dotenv

load_dotenv()

embedding = OpenAIEmbeddings(
    model="text-embedding-3-large",
    dimensions=32,
)

result = embedding.embed_query("Kathmandu is the capital of Nepal.")

print(str(result))

The printed result is a list of numbers: the embedding vector.

291

Embed Documents

Use embed_documents when you have many strings at once.

from langchain_openai import OpenAIEmbeddings
from dotenv import load_dotenv

load_dotenv()

embedding = OpenAIEmbeddings(
    model="text-embedding-3-large",
    dimensions=32,
)

documents = [
    "my name is bishal",
    "i live in nepal",
    "I am ai learner",
]

result = embedding.embed_documents(documents)

print(str(result))

You get one vector per document. Store those vectors when you build search later.

292

Document Search Project

Put the pieces together: embed your documents, embed a query, then rank with cosine similarity.

from langchain_openai import OpenAIEmbeddings
from dotenv import load_dotenv
from sklearn.metrics.pairwise import cosine_similarity
import numpy as np

load_dotenv()

embedding = OpenAIEmbeddings(
    model="text-embedding-3-large",
    dimensions=32,
)

documents = [
    "my name is bishal",
    "i live in nepal",
    "I am ai learner",
]

query = "where does bishal live"

doc_embeddings = embedding.embed_documents(documents)
query_embedding = embedding.embed_query(query)

scores = cosine_similarity([query_embedding], doc_embeddings)[0]
index = int(np.argmax(scores))

print(documents[index])
print(scores[index])

The highest score points to the closest document. That is the heart of simple semantic search.

Day 23 takeaways

  • Models connect your app to language models and embedding models.
  • Prefer chat models over classic LLMs for chatbots and agents.
  • Temperature and max tokens shape creativity and reply length.
  • Open source models live on Hugging Face via API or local pipelines.
  • Embeddings plus cosine similarity power document search and RAG.
