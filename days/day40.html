Day 40

FastAPI Philosophy

What FastAPI is, why it is fast to run and fast to code, then how to install it and write a first app.

555

What Is FastAPI

FastAPI is a Python framework. It is a modern, high performance web framework for building APIs.

You write Python. FastAPI turns that Python into an API other apps can call.

556

Starlette plus Pydantic

FastAPI is not one giant new engine. It sits on two tools: Starlette and Pydantic. The two cards below split that pair.

Starlette

Handles how the API receives an HTTP request and sends an HTTP response.

Pydantic

Checks that data coming in is the right type and the right format.

So FastAPI is Starlette plus Pydantic.

557

How Starlette Handles a Request

When you make an API, that API must receive an HTTP request, process it, and send an HTTP response. Starlette manages that path.

The steps below are the job Starlette does for FastAPI.

Request in, response out

  1. Receive The API gets an HTTP request from a client.
  2. Process Starlette runs your route and prepares a result.
  3. Respond The API sends an HTTP response back to the client.
558

How Pydantic Checks Data

Pydantic is for data validation. That is very useful when you make an API, because other people and other apps will call it.

You want to know if a value is a string or not, or an int or not. Pydantic helps with that. It checks if the data coming into your API is correct and in the right format.

The two cards below show a pass and a fail.

Right format

The API asked for an int and the caller sent an int. Pydantic lets it through.

Wrong format

The API asked for an int and the caller sent a string. Pydantic stops it.

559

Why FastAPI Was Built

Before FastAPI, people built APIs with Django and other frameworks. Those older tools had performance issues. Response time was slow. That delay is latency.

Those frameworks also needed a lot of extra setup code before you had a working API.

FastAPI was built to be fast to run, so it can handle concurrent users, and fast to code, so you write less extra setup. That is why it is named FastAPI. The table below puts the old pain next to the FastAPI goal.

Before FastAPI FastAPI goal
Slow response time and latency. Fast to run. Handle concurrent users.
A lot of extra setup code. Fast to code. Less extra setup.
560

Fast to Run

Why does fast to run matter for us? Think of an API for a machine learning model.

The model sits behind a /predict endpoint. That endpoint takes two inputs, i1 and i2, runs predict, and lives on AWS.

When you deploy an API on AWS, you send two things: the API code, and a web server. The web server uses ports to listen. It watches for an HTTP request coming in.

The chain below is that deploy path.

From model to AWS

  1. ML model A trained model ready to predict.
  2. predict endpoint The route is /predict. It takes i1 and i2.
  3. Deploy on AWS You send API code and a web server.
  4. Web server It listens on ports for HTTP requests.
561

The Web Server and SGI

On AWS the path is web server, then SGI, then API code. SGI means Server Gateway Interface. It is a protocol. It lets the web server and the API code talk both ways.

Data arrives in HTTP format. API code only understands Python. SGI converts HTTP format to Python, and converts the Python result back to HTTP.

The chain below is that conversion.

HTTP to Python and back

  1. Data The client sends data in HTTP format.
  2. Web server It receives the HTTP request on a port.
  3. SGI It converts HTTP to Python, and Python back to HTTP.
  4. API code Your Python runs predict and returns a result.
562

WSGI vs ASGI

SGI comes in two types. Flask uses WSGI, which means Web Server Gateway Interface. FastAPI uses ASGI, which means Asynchronous Server Gateway Interface. The table below compares them.

WSGI ASGI
Used in Flask FastAPI
How it works Synchronous. One request at a time. Asynchronous. Many requests in parallel.
Library Werkzeug Starlette
Web server Gunicorn Uvicorn

In Flask the path is web server, then WSGI, then API code. The biggest problem is the synchronous nature. It can process one request at a time. If five users send a request, HTTP cannot convert to Python in parallel. While one runs, the others wait. That is why Flask with Gunicorn has performance issues.

In FastAPI the path is web server Uvicorn, then ASGI, then API code on an asynchronous endpoint. It converts HTTP to Python in parallel. That is concurrent processing. Starlette is the library that does ASGI for FastAPI.

A restaurant makes the wait versus keep moving idea easy to see.

Flask FastAPI
Customer orders. The waiter waits at the kitchen until the food is ready, then serves. Other customers wait. Customer orders. The waiter leaves it with the kitchen and goes to the next customer. The kitchen keeps cooking.
563

Fast to Code

The second philosophy is fast to code.

In Python, types are often automatic. If you write a = 5, Python knows that is an int. An API cannot guess like that. Data comes from other people. You need data validation.

FastAPI gives you automatic input validation. It also auto generates interactive documentation. Each endpoint has its own format, such as JSON, and its own expected types. FastAPI builds docs from that, and those docs are interactive.

It is a modern framework. It is easy to connect with the modern stack: ML and DL libraries, OAuth, JWT, SQLAlchemy, Docker, and Kubernetes. The three cards below are the fast to code idea.

Automatic validation

Incoming data is checked. Wrong types do not silently pass.

Interactive docs

Each endpoint documents the format it expects, and you can try it.

Modern stack

Fits ML, DL, OAuth, JWT, SQLAlchemy, Docker, and Kubernetes.

Set Up and Install

Make a virtual environment, turn it on, then install FastAPI and Uvicorn. Pydantic comes in with FastAPI, so you do not install it as a separate step for this start.

The steps below are the order. The commands sit in the block after that.

Create, activate, install

  1. Create venv Create an isolated folder for this project's packages.
  2. Activate Turn that folder on with the activate script.
  3. Install pip install fastapi uvicorn. Pydantic arrives with FastAPI.

Commands

python -m venv venv
source venv/bin/activate
pip install fastapi uvicorn

What you should see

(venv) in front of your prompt after activate.
pip downloads FastAPI, Uvicorn, and Pydantic.
When it finishes, you can write main.py in this environment.

These activate steps are for Mac and Linux.

565

Your First FastAPI App

Create a file named main.py. This is a first app with two GET routes.

Line by line: from fastapi import FastAPI brings in the class. app = FastAPI() makes the app object. @app.get("/") is a GET request on the root route. If your site is bishalranjitkar.com, a hit on the root hits this function. hello returns a dict. FastAPI sends that as JSON. @app.get("/about") is a second GET route.

main.py

from fastapi import FastAPI

app = FastAPI()

@app.get("/")
def hello():
    return {"message": "Hello World"}

@app.get("/about")
def about():
    return {"message": "About Page about bishal website"}

What the routes return

GET /       {"message": "Hello World"}
GET /about  {"message": "About Page about bishal website"}

Slash means the root route. /about is a second path on the same app.

566

Run with Uvicorn

Start the app with Uvicorn. The first word is the file name without .py. The word after the colon is the app object. Our file is main.py and the object is app, so we use main:app.

If you named the file fastapi.py, the command would use fastapi:app instead. --reload restarts the server when you save the file.

Command

python -m uvicorn main:app --reload

What you should see

Uvicorn starts and watches the file.
Open http://127.0.0.1:8000 for the hello route.
Open http://127.0.0.1:8000/about for the about route.

This form works when uvicorn lives inside your venv.
