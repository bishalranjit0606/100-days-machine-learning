Day 60

Observability in the LangGraph Chatbot

We keep the same chatbot. We send the thread id to LangSmith as well as to SQLite, so each chat has its own thread of traces.

778

The Chatbot We Already Built

Until now we made a chatbot in LangGraph. It streams. It can start a new chat. It can resume an old chat. Today we add observability to that same chatbot.

779

We Do Not Rewrite the Graph

We do not need to change the whole code. The graph is still START, chat_node, END. We add a bit of config so LangSmith can group traces by chat. The cards below are what stays and what we add.

Same graph

ChatState, add_messages, one chat_node, compile with a checkpointer.

New bits

Env keys for LangSmith, make_config with thread_id, pass config into the model, list threads from SQLite.

780

Traces Can Feel Mismanaged

We might ask this. We open a new chat, a new thread. That run also saves in the same LangSmith store. We go back to a previous chat, send a line, and a new trace is stored in LangSmith too. It can feel mismanaged. All chats look dumped in one pile. The picture below is that mix versus one thread per chat.

781

One Thread Id for Both Stores

In LangSmith we can use a different thread for each conversation. Each thread stores that chat only. We put the thread id in the code. LangSmith has an option to show the thread conversation. The same id also goes to the LangGraph checkpointer. The steps below are that shared id.

Same thread_id two ways

  1. thread_id One id for this chat window.
  2. SQLite configurable thread_id saves the graph state.
  3. LangSmith metadata thread_id groups the traces for that chat.
  4. Thread view LangSmith can show that thread convo.

Copy Old Env Names

We still load .env next to the backend file. Older LangChain names still work. If LANGCHAIN_TRACING_V2 is true, we also set LANGSMITH_TRACING. We copy LANGCHAIN_API_KEY, LANGCHAIN_PROJECT, and LANGCHAIN_ENDPOINT to the current LangSmith names when those keys exist. If LANGSMITH_PROJECT is still empty, we default it to langsmith-demo. That is the same project name from Day 59.

783

make_config

make_config takes a thread_id. It returns one dict. configurable thread_id is for the LangGraph checkpointer. metadata thread_id is for LangSmith. run_name is chat. The comment in the code says it. Same id for the saved chat and the LangSmith thread.

make_config

def make_config(thread_id: str) -> dict:
    # Same id for the saved chat and the LangSmith thread.
    return {
        "configurable": {"thread_id": thread_id},
        "metadata": {"thread_id": thread_id},
        "run_name": "chat",
    }

The front end calls this for stream, for get_state, and for the live CONFIG.

784

Pass Config into the Model

chat_node now takes config as a RunnableConfig. It still reads state messages. It calls llm.invoke with those messages and that config. The trace can then carry the thread id. The graph compile is the same as before.

chat_node

def chat_node(state: ChatState, config: RunnableConfig):
    messages = state["messages"]
    response = llm.invoke(messages, config)
    return {
        "messages": [response]
    }

Without this second argument, the model call would not get the thread metadata.

785

Threads from SQLite

The checkpointer is SqliteSaver on chatbot.db next to the backend file. check_same_thread is False so Streamlit can use this connection. get_all_threads reads the checkpoints table. It groups by thread_id and orders by the latest checkpoint_id, newest first. Old chats then stay after a restart. They do not live only in session_state.

SqliteSaver

db_path = os.path.join(os.path.dirname(__file__), "chatbot.db")

conn = sqlite3.connect(db_path, check_same_thread=False)

checkpointer = SqliteSaver(conn)

def get_all_threads():
    query = """
        SELECT thread_id
        FROM checkpoints
        GROUP BY thread_id
        ORDER BY MAX(checkpoint_id) DESC
    """

    with checkpointer.cursor(transaction=False) as cur:
        cur.execute(query)
        return [row[0] for row in cur.fetchall()]

graph = StateGraph(ChatState)
graph.add_node("chat_node", chat_node)
graph.add_edge(START, "chat_node")
graph.add_edge("chat_node", END)

chatbot = graph.compile(
    checkpointer=checkpointer
)

The sidebar later lists these ids, except the one that is already open.

The full backend file puts the env copy, the LLM helper, make_config, chat_node, and this checkpointer in one module named langgraph_backend.py.

langgraph_backend.py

from langgraph.graph import StateGraph, START, END
from typing import TypedDict, Annotated

from langchain_core.messages import BaseMessage
from langchain_core.runnables import RunnableConfig
from langchain_openrouter import ChatOpenRouter

from langgraph.checkpoint.sqlite import SqliteSaver
from langgraph.graph.message import add_messages

import sqlite3
import os

from dotenv import load_dotenv

load_dotenv(os.path.join(os.path.dirname(__file__), ".env"))

if os.getenv("LANGCHAIN_TRACING_V2", "").lower() == "true":
    os.environ.setdefault("LANGSMITH_TRACING", "true")
if os.getenv("LANGCHAIN_API_KEY"):
    os.environ.setdefault("LANGSMITH_API_KEY", os.environ["LANGCHAIN_API_KEY"])
if os.getenv("LANGCHAIN_PROJECT"):
    os.environ.setdefault("LANGSMITH_PROJECT", os.environ["LANGCHAIN_PROJECT"])
if os.getenv("LANGCHAIN_ENDPOINT"):
    os.environ.setdefault("LANGSMITH_ENDPOINT", os.environ["LANGCHAIN_ENDPOINT"])

os.environ.setdefault("LANGSMITH_PROJECT", "langsmith-demo")


def _make_llm():
    openrouter_key = os.getenv("OPENROUTER_API_KEY", "").strip()
    if openrouter_key and openrouter_key != "your_openrouter_key_here":
        return ChatOpenRouter(
            model="openrouter/free",
            temperature=0,
            streaming=True,
        )

    groq_key = os.getenv("GROQ_API_KEY", "").strip()
    if groq_key and groq_key != "your_groq_key_here":
        from langchain_groq import ChatGroq

        return ChatGroq(
            model="openai/gpt-oss-20b",
            temperature=0,
        )

    raise RuntimeError(
        "Add OPENROUTER_API_KEY or GROQ_API_KEY to .env before you start the chatbot."
    )


llm = _make_llm()

Pick OpenRouter or Groq

_make_llm looks at .env. If OPENROUTER_API_KEY is set and is not the placeholder string, it uses ChatOpenRouter with openrouter/free, temperature 0, streaming True. Else if GROQ_API_KEY is set and is not the placeholder, it uses ChatGroq with openai/gpt-oss-20b. Else it raises a RuntimeError and tells you to add a key before you start.

_make_llm

def _make_llm():
    openrouter_key = os.getenv("OPENROUTER_API_KEY", "").strip()
    if openrouter_key and openrouter_key != "your_openrouter_key_here":

        from langchain_groq import ChatGroq

787

Front End Uses make_config

The page still has a sidebar, Start New Chat, and previous conversations. generate_thread_id now uses uuid7 from langsmith. load_conversation calls chatbot.get_state with make_config. Start New Chat makes a new id and clears the bubbles. Previous threads come from get_all_threads, skipping the open id. CONFIG is make_config of the session thread_id. Stream still uses stream_mode messages. The same thread id goes to SQLite and to LangSmith. I do not invent chat text here. Open LangSmith after you talk and look at that thread.

streamlit_frontend.py

import streamlit as st

from langgraph_backend import chatbot, get_all_threads, make_config
from langchain_core.messages import HumanMessage
from langsmith import uuid7


def generate_thread_id():
    return str(uuid7())


if "thread_id" not in st.session_state:
    st.session_state["thread_id"] = generate_thread_id()

if "message_history" not in st.session_state:
    st.session_state["message_history"] = []

st.sidebar.title("LangGraph Chatbot")

st.sidebar.subheader("Current Conversation")
st.sidebar.write(
    st.session_state["thread_id"]
)


def load_conversation(thread_id):
    state = chatbot.get_state(make_config(thread_id))
    messages = []
    for msg in state.values.get("messages", []):
        role = "user" if msg.type == "human" else "assistant"
        content = msg.content
        if isinstance(content, list):
            content = "".join(
                part if isinstance(part, str) else part.get("text", "")
                for part in content
            )
        messages.append(
            {
                "role": role,
                "content": content
            }
        )
    return messages


if st.sidebar.button("Start New Chat"):
    st.session_state["thread_id"] = generate_thread_id()
    st.session_state["message_history"] = []
    st.rerun()

previous_threads = [
    thread_id
    for thread_id in get_all_threads()
    if thread_id != st.session_state["thread_id"]
]

st.sidebar.subheader("Previous Conversations")

for thread_id in previous_threads:
    if st.sidebar.button(thread_id, key=thread_id):
        st.session_state["thread_id"] = thread_id
        st.session_state["message_history"] = load_conversation(thread_id)
        st.rerun()

CONFIG = make_config(st.session_state["thread_id"])

for message in st.session_state["message_history"]:
    with st.chat_message(message["role"]):
        st.write(message["content"])

user_input = st.chat_input("Type here")

if user_input:
    st.session_state["message_history"].append(
        {
            "role": "user",
            "content": user_input
        }
    )
    with st.chat_message("user"):
        st.write(user_input)

    with st.chat_message("assistant"):
        def stream_response():
            for message_chunk, metadata in chatbot.stream(
                {
                    "messages": [
                        HumanMessage(content=user_input)
                    ]
                },
                config=CONFIG,
                stream_mode="messages"
            ):
                if message_chunk.content:
                    yield message_chunk.content

        ai_message = st.write_stream(
            stream_response()
        )

    st.session_state["message_history"].append(
        {
            "role": "assistant",
            "content": ai_message
        }
    )

Day 58 kept ids in session. Today the list comes from SQLite, so a restart still shows old chats.

Day 60 takeaways

Day 60 takeaways

  • We add observability to the LangGraph chatbot. We do not rewrite the graph.
  • New chats and resumed chats all write traces. Without a thread id they look dumped in one pile.
  • LangSmith can keep a different thread per conversation and show that thread convo.
  • make_config puts the same thread_id in configurable and in metadata. run_name is chat.
  • chat_node passes that config into llm.invoke so the model run stays on the thread.
  • Copy LANGCHAIN env names to LANGSMITH names. Default project is langsmith-demo.
  • SqliteSaver stores chats in chatbot.db. get_all_threads fills the sidebar after a restart.
  • uuid7 makes the new thread id. Stream still uses that CONFIG.
