The del Keyword

del deletes an object property, or the object itself.

Input

class Car:
    def __init__(self, make, model, year):
        self.make = make
        self.model = model
        self.year = year

car1 = Car("Toyota", "Corolla", 2020)
print(car1.make)
del car1
print(car1.make)

Output

Toyota
NameError: name 'car1' is not defined

To delete one attribute and keep the object, use del car1.make. Then print(car1.make) raises AttributeError.

Public and Private

Other languages have public and private. Public means you can read and change the attribute from outside the class. That is a bad idea for a password. Anyone with the object can print it or overwrite it.

Input

class Account:
    def __init__(self, accno, accpass):
        self.accno = accno
        self.accpass = accpass

acc1 = Account(1234567890, "1234567890")
print(acc1.accno)
print(acc1.accpass)

Output

1234567890
1234567890

Put two underscores in front of the name to mark it private. Then you cannot use acc1.accpass or even acc1.__accpass from outside. Python public and private are similar to other languages, but they are not the same thing.

Input

class Account:
    def __init__(self, accno, accpass):
        self.accno = accno
        self.__accpass = accpass

acc1 = Account(1234567890, "1234567890")
print(acc1.accno)
print(acc1.accpass)

Output

1234567890
AttributeError: 'Account' object has no attribute 'accpass'

Getters and Private Methods

Read a private value with a method inside the class. That method can see self.__accpass.

Input

class Account:
    def __init__(self, accno, accpass):
        self.accno = accno
        self.__accpass = accpass

    def get_accpass(self):
        return self.__accpass

acc1 = Account(1234567890, "1234567890")
print(acc1.get_accpass())

Output

1234567890

A private class attribute or a private method also fails from outside. We still write them because some helpers should only run inside another method.

Input

class Person:
    __name = "John"

p1 = Person()
print(p1.__name)

Output

AttributeError: 'Person' object has no attribute '__name'

Calling a private setter from outside fails too.

Input

class Account:
    def __init__(self, accno, accpass):
        self.__accno = accno
        self.__accpass = accpass

    def get_accno(self):
        return self.__accno

    def get_accpass(self):
        return self.__accpass

    def __set_accpass(self, accpass):
        self.__accpass = accpass

    def set_accno(self, accno):
        self.__accno = accno

acc1 = Account(1234567890, "1234567890")
print(acc1.get_accno())
print(acc1.get_accpass())
print(acc1.__set_accpass("1234567890"))

Output

1234567890
1234567890
AttributeError: 'Account' object has no attribute '__set_accpass'

Inheritance

In real life we inherit values from parents, and they inherit from theirs. In code, one class derives properties and methods from another class.

Every car needs start and stop. A Toyota class should not copy that logic. It inherits attributes and methods from Car. This shape is single inheritance: one base class, one derived class.

Single inheritance

  1. Car The base class. Color, start, stop.
  2. Derives ToyotaCar(Car) takes the parent features.
  3. ToyotaCar The derived class. Adds its own name.

Call start() and stop() directly. Do not wrap them in print, because they already print and they return None.

Input

class Car:
    color = "red"

    @staticmethod
    def start():
        print("Car started")

    @staticmethod
    def stop():
        print("Car stopped")

class ToyotaCar(Car):
    def __init__(self, name):
        self.name = name

car1 = ToyotaCar("Toyota")
print(car1.name)
car1.start()
car1.stop()
print(car1.color)

Output

Toyota
Car started
Car stopped
red

Multilevel Inheritance

A derived class can have its own derived class. That chain is multilevel inheritance: base, then derived, then derived again. Fortuner gets ToyotaCar features and Car features.

Car, then ToyotaCar, then Fortuner

  1. Car start, stop, color.
  2. ToyotaCar Adds safety.
  3. Fortuner Gets all of the above, plus its name.

Input

class Car:
    color = "red"

    @staticmethod
    def start():
        print("Car started")

    @staticmethod
    def stop():
        print("Car stopped")

class ToyotaCar(Car):
    def __init__(self, name):
        self.name = name

    @staticmethod
    def safety():
        print("have safety features")

class Fortuner(ToyotaCar):
    def __init__(self, name):
        self.name = name

fortuner1 = Fortuner("fortuner")
print(fortuner1.name)
fortuner1.start()
fortuner1.stop()
print(fortuner1.color)
fortuner1.safety()

Output

fortuner
Car started
Car stopped
red
have safety features

Multiple Inheritance

One derived class can take more than one parent. That is multiple inheritance. Class C takes A and B, so an object of C has varA, varB, and varC.

A

Parent. Holds varA.

B

Parent. Holds varB.

C(A, B)

Child. Holds varC and inherits both parents.

Input

class A:
    varA = "I am variable A"

class B:
    varB = "I am variable B"

class C(A, B):
    varC = "I am variable C"

c1 = C()
print(c1.varA)
print(c1.varB)
print(c1.varC)

Output

I am variable A
I am variable B
I am variable C

super

super() lets you call a method on the parent class. Use it in the child constructor so the parent can set its own attributes, such as type. You could write self.type = type in the child, but then you skip the rest of the parent constructor. super().__init__(type) runs the parent init.

A static method lives on the class. Python does not make a new copy of it for every object.

Input

class Car:
    def __init__(self, type):
        self.type = type

    @staticmethod
    def start():
        print("Car started")

    @staticmethod
    def stop():
        print("Car stopped")

class ToyotaCar(Car):
    def __init__(self, name, type):
        self.name = name
        super().__init__(type)
        super().start()

car1 = ToyotaCar("fortuner", "suv")
print(car1.type)
car1.start()

Output

Car started
suv
Car started

The first Car started comes from super().start() inside init. The second comes from car1.start().

Changing a Class Attribute

If you assign self.name on the object, you do not change the class value. The object makes its own name. Person.name stays anonymous.

Input

class Person:
    name = "anonymous"

    def changeName(self, name):
        self.name = name

p1 = Person()
print(p1.name)
p1.changeName("John")
print(p1.name)
print(Person.name)

Output

anonymous
John
anonymous

To change the class attribute, assign on the class: Person.name = name. Then both the object and the class show John.

Input

class Person:
    name = "anonymous"

    def changeName(self, name):
        Person.name = name

p1 = Person()
print(p1.name)
p1.changeName("John")
print(p1.name)
print(Person.name)

Output

anonymous
John
John

self.__class__.name also changes the class. This version ignores the argument and always sets rahul.

Input

class Person:
    name = "anonymous"

    def changeName(self, name):
        self.__class__.name = "rahul"

p1 = Person()
print(p1.name)
p1.changeName("John")
print(p1.name)
print(Person.name)

Output

anonymous
rahul
rahul

Class Methods

A class method is bound to the class. It receives the class as cls, not the object as self. Use @classmethod. Then cls.name = name changes the class attribute and uses the name you passed in.

Input

class Person:
    name = "anonymous"

    @classmethod
    def changeName(cls, name):
        cls.name = name

p1 = Person()
print(p1.name)
p1.changeName("John")
print(p1.name)
print(Person.name)

Output

anonymous
John
John

There are three kinds of methods.

Static

@staticmethod. No self and no cls.

Class

@classmethod. Gets cls, the class.

Instance

Normal method. Gets self, the object.

Property Decorator

If you store total in __init__, that number is frozen. Change phy later and st1.total stays 300. calculate_total() does update, because it adds again.

Input

class Student:
    def __init__(self, phy, chem, math):
        self.phy = phy
        self.chem = chem
        self.math = math
        self.total = phy + chem + math

    def calculate_total(self):
        return self.phy + self.chem + self.math

st1 = Student(100, 100, 100)
print(st1.total)
st1.phy = 70
print(st1.total)
print(st1.calculate_total())

Output

300
300
270

A property decorator turns a method into something you read like an attribute. Each time you use st1.total, Python runs the method again.

Input

class Student:
    def __init__(self, phy, chem, math):
        self.phy = phy
        self.chem = chem
        self.math = math

    @property
    def total(self):
        return self.phy + self.chem + self.math

st1 = Student(100, 100, 100)
print(st1.total)
st1.phy = 70
print(st1.total)

Output

300
270

Polymorphism

Poly means many. Morph means form. The same operator can mean different work. That is operator overloading. Python already does this for you. That built in behavior is implicit overloading.

Code What + does
10 + 20 Adds numbers. Result 30.
"hello" + "world" Joins strings. Result helloworld.
[1, 2, 3] + [4, 5, 6] Merges lists. Result [1, 2, 3, 4, 5, 6].

Input

print(10 + 20)
print("hello" + "world")
print([1, 2, 3] + [4, 5, 6])

Output

30
helloworld
[1, 2, 3, 4, 5, 6]

Complex Numbers and Dunder add

A real number is 1, 2, 3, or minus 1. A complex number has a real part and an imaginary part, written with j, such as 3 + 8j. Complex numbers show up in work such as voice recognition.

Python already has a built in complex type. We still write our own class so we can teach what + does. When you write a + b, Python calls a.__add__(b). A name like __add__ is a dunder method, two underscores on each side.

Input

class Complex:
    def __init__(self, real, imaginary):
        self.real = real
        self.imaginary = imaginary

    def showNum(self):
        print(self.real, "+", self.imaginary, "j")

    def __add__(self, other):
        newReal = self.real + other.real
        newImaginary = self.imaginary + other.imaginary
        return Complex(newReal, newImaginary)

num1 = Complex(3, 8)
num2 = Complex(2, 3)
num1.showNum()
num2.showNum()
num3 = num1 + num2
num3.showNum()

Output

3 + 8 j
2 + 3 j
5 + 11 j

Practice Circle

Define a Circle class. The constructor takes radius r. area() is pi times r squared. perimeter() is 2 times pi times r. This class stores pi as 22 / 7. For radius 10, area is about 314.29 and perimeter is about 62.86.

Input

class Circle:
    pi = 22 / 7

    def __init__(self, radius):
        self.radius = radius

    def area(self):
        return Circle.pi * self.radius ** 2

    def perimeter(self):
        return 2 * Circle.pi * self.radius

c1 = Circle(10)
print(c1.area())
print(c1.perimeter())

Output

314.2857142857143
62.857142857142854

Practice Employee and Engineer

Define an Employee class with roles, department, and salary, plus a show_details() method. Engineer inherits from Employee. The engineer constructor stores name and age, then calls super() with Engineer, IT, and 100000. show_details() prints those employee fields. Name and age stay on the object even though this method does not print them.

Input

class Employee:
    def __init__(self, roles, department, salary):
        self.roles = roles
        self.department = department
        self.salary = salary

    def show_details(self):
        print("Roles:", self.roles, "Department:", self.department, "Salary:", self.salary)

class Engineer(Employee):
    def __init__(self, name, age):
        self.name = name
        self.age = age
        super().__init__("Engineer", "IT", 100000)

engg1 = Engineer("bishal", 24)
engg1.show_details()

Output

Roles: Engineer Department: IT Salary: 100000

Python 9 takeaways

Python 9 takeaways

  • del removes an attribute or the whole object.
  • Two underscores in front of a name marks it private. Read it with a method. Python privacy is similar to other languages, not the same.
  • Private methods are for use inside other methods, not from outside.
  • Inheritance lets a child reuse parent attributes and methods. Single, multilevel, and multiple are three shapes.
  • super() runs a parent method, often the parent constructor.
  • self.name on an object does not change Person.name. Assign on the class, or use a class method with cls.
  • Three method kinds: static, class, and instance.
  • @property makes a method look like an attribute and runs it each time you read it.
  • Polymorphism is many forms. + adds numbers, joins strings, and merges lists.
  • a + b calls a.__add__(b). You can write that dunder so your own class works with +.
