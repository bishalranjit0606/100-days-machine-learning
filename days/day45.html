PUT /edit

The update route is /edit. We provide the patient id in the path. We also provide a request body with the fields we want to change. The HTTP method is PUT.

Id in the path. Changes in the body.

  1. Path id /edit/{patient_id} says which patient to change.
  2. Request body JSON with only the fields the client wants to change.
  3. PUT The verb that updates that patient.
611

A New Model: PatientUpdate

First we build a new Pydantic model. The old Patient model requires every field. We do not know if the client will send all fields, or only one field to change. So those update fields must be optional. There is no id on this model. The id comes from the path.

The table below is create versus update.

Patient PatientUpdate
Used on create. Every field is required, including id. Used on edit. Every field is optional and defaults to None.
The client must send the full patient. The client can send only the fields they want to change.

PatientUpdate

from typing import Annotated, Literal, Optional
from pydantic import BaseModel, Field

class PatientUpdate(BaseModel):
    name: Annotated[Optional[str], Field(default=None, description="The name of the patient")] = None
    gender: Annotated[Optional[Literal["male", "female", "other"]], Field(default=None, description="The gender of the patient")] = None
    city: Annotated[Optional[str], Field(default=None, description="The city of the patient")] = None
    age: Annotated[Optional[int], Field(default=None, description="The age of the patient", gt=0, lt=100)] = None
    height: Annotated[Optional[float], Field(default=None, description="The height of the patient in meters", gt=0)] = None
    weight: Annotated[Optional[float], Field(default=None, description="The weight of the patient in kilograms", gt=0)] = None

What a body can look like

Only city, or only age, or any mix.
Fields that are not sent stay None
and must not overwrite the stored patient.

Merge New Data With Old Data

Second, we update the new data with the existing data. Load the file. If the id is missing, raise 404. Take the stored patient. Dump only the fields the client actually sent with exclude_unset=True. Merge those keys into the stored dict. Then we must build a full Patient again. That rechecks the rules and refreshes computed fields such as BMI and verdict. BMI is rounded to 2 decimal places. Save the dump without id, because id is still the key.

Find, merge, recheck, save

  1. Find Load data.json. 404 if the id is not there.
  2. Merge exclude_unset keeps only fields the client sent.
  3. Recheck Patient(**...) rebuilds BMI and verdict.
  4. Save Write the dump back under that id, without repeating id.

The Update Route

load_data now returns an empty dict if the file is missing or the JSON is broken. PUT /edit/{patient_id} takes the path id and a PatientUpdate body. After a good merge we return a success message and the new stored object.

PUT /edit/{patient_id}

@app.put("/edit/{patient_id}")
def update_patient(patient_id: str, patient_update: PatientUpdate):
    data = load_data()

    if patient_id not in data:
        raise HTTPException(
            status_code=status.HTTP_404_NOT_FOUND,
            detail="Patient not found"
        )

    existing_patient = data[patient_id]
    updated_data = patient_update.model_dump(exclude_unset=True)
    existing_patient.update(updated_data)

    existing_patient["id"] = patient_id
    validated_patient = Patient(**existing_patient)

    data[patient_id] = validated_patient.model_dump(exclude={"id"})
    save_data(data)

    return {
        "message": "Patient updated successfully",
        "data": data[patient_id]
    }

What PUT returns

PUT /edit/P001  id exists
{"message": "Patient updated successfully", "data": ...}

PUT /edit/P001  id missing
status 404
{"detail": "Patient not found"}

We put id back on the dict only so Patient can validate. We drop id again before we save.

DELETE /delete

DELETE /delete/{patient_id} removes that patient. If the id is not in the file, we raise 404. If it is there, we delete that key, save the file, and return a success message.

Remove one key

  1. Load Read data.json.
  2. Check 404 if the id is not found.
  3. Delete del data[patient_id], then save.

DELETE /delete/{patient_id}

@app.delete("/delete/{patient_id}")
def delete_patient(patient_id: str):
    data = load_data()

    if patient_id not in data:
        raise HTTPException(
            status_code=status.HTTP_404_NOT_FOUND,
            detail="Patient not found"
        )

    del data[patient_id]
    save_data(data)

    return {"message": "Patient deleted successfully"}

What DELETE returns

DELETE /delete/P001  id exists
{"message": "Patient deleted successfully"}

DELETE /delete/P001  id missing
status 404
{"detail": "Patient not found"}

Day 45 takeaways

Day 45 takeaways

  • We already had view, one patient by path, sort by query, and create. Today we add update and delete.
  • PUT /edit/{patient_id} takes the id in the path and the changes in the request body.
  • Patient requires every field. PatientUpdate makes each field optional so the client can change one field.
  • exclude_unset keeps only fields the client sent. Merge those into the stored patient.
  • Build Patient again so BMI and verdict update. Round BMI to 2 decimals. Save without id as the key.
  • DELETE /delete/{patient_id} removes that key. Missing id returns 404 on both edit and delete.
