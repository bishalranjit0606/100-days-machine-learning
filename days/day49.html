LangGraph Core Concepts

LangGraph is a graph of nodes and edges. We recap five common LLM workflows, then state, reducers, and how a run executes.

651

LangGraph Recap

LangGraph is an orchestration framework for building intelligent, stateful, and multi step LLM workflows. Advanced features include parallel work, loops, branching, memory, and resume. It is a strong fit for production grade AI.

In LangGraph we make a graph. That graph is the workflow. Every node is connected through edges.

What Is an LLM Workflow

A workflow is a step by step process for building an LLM application. Any workflow that uses an LLM in the flow is called an LLM workflow. Five common kinds show up again and again. The cards below are that set. We open each one next.

Prompt chaining

Use the LLM several times in a sequence.

Routing

One LLM decides which path to take.

Parallelization

Several LLMs work at once, then we merge.

Orchestrator

An LLM assigns tasks, then a synthesizer joins the result.

Evaluator optimizer

One LLM writes. Another scores it and sends feedback.

Prompt Chaining

Prompt chaining uses the LLM multiple times in a sequence. Input goes to LLM 1, then LLM 2, then LLM 3. This pattern is common.

Suppose we need a detailed summary from a topic. Topic becomes an outline, then keywords, then a report. We can put a checkpoint on the report, such as no more than 500 words. The chain below is that path.

Topic to report

  1. Topic Start with the subject.
  2. Outline The first LLM pass shapes the outline.
  3. Keywords The next pass pulls key words.
  4. Report The last pass writes the report. A checkpoint can cap it at 500 words.

An orchestrator workflow goes input, then orchestrator, then LLM 1 or LLM 2 or LLM 3, then a synthesizer, then output. The orchestrator is also an LLM. It decides which LLM to use and which LLM gets what task. The tasks depend upon the query. This can also run in parallel. The diagram below is that path.

An Essay Graph

Loksewa in Nepal needs an essay to pass an exam, and that essay carries good marks. We are making a website that helps a user practice the essay. If the score is good we congratulate. If the score is bad we give a chance to rewrite.

In LangGraph the pieces are topic generate, collect from the user, evaluate the essay, aggregate, conditional routing, feedback, collect revision, and success.

Generate a topic, then write the essay. Evaluate on three things at once: clarity of thought, depth of analysis, and language. Aggregate a final evaluation. Then either success, or fail with feedback. Ask retake. If no, end. If yes, go back to write essay. The diagram below is that graph. You can see the nodes and the edges.

Nodes and Edges

Each node is a single task. Behind the node, each node is a Python function. The graph is just a set of Python functions. Nodes tell us what to do. Edges are the direction. Edges can be sequential, parallel, or conditional. They also cover branching and looping.

Nodes Edges
A single task. A Python function. The direction from one task to the next.
Tell the graph what to do. Sequential, parallel, conditional, branching, or looping.
660

State

State is a very important concept. In every LLM workflow each node needs certain data to work. Each node has an output, and that output is required by the next nodes. State is shared memory. Values are added in key value format.

The state changes every time the run gets to the next node. It is mutable. How do we make state? It is a TypedDict dictionary. Nothing special.

The main point is this. State is accessed by all the nodes. And it is mutable.

661

Reducer

Reducer sits very close to state. Multiple nodes can update the state. Update means remove the previous value and put the new one. A reducer helps define how those node updates are applied on the state. With a reducer we can preserve the past state.

662

The Execution Model

An interesting fact: LangGraph is inspired by the Google Pregel system. A run has six steps. The chain below is that model.

From graph to a finished run

  1. Define Define state, nodes, and edges.
  2. Compile Call compile to check the graph structure and prepare it to run.
  3. Invoke Start with the initial state. The first node is active. State updates in parts. The updated state goes to the next node through an edge.
  4. Super step If several nodes run at the same time, that parallel work is a super step. Results merge through a reducer.
  5. Continue Keep going until the last node.
  6. Stop Execution stops.

Compile and invoke are the two calls. The block below is those names.

Compile, then invoke

compile()
invoke(initial_state)

compile checks the graph and prepares it. invoke starts the first node from the initial state. Updates stay partial as they move along the edges.

Day 49 takeaways

Day 49 takeaways

  • LangGraph orchestrates intelligent, stateful, multi step LLM workflows. It supports parallel work, loops, branching, memory, and resume. It fits production grade AI.
  • The graph is the workflow. Nodes connect through edges.
  • An LLM workflow is any workflow that uses an LLM. Common shapes are prompt chaining, routing, parallelization, orchestrator, and evaluator optimizer.
  • Chaining is a line, such as topic, outline, keywords, report, with a 500 word checkpoint. Routing lets LLM 1 pick the next model. Parallelization merges checks such as guidelines, misinformation, and sexual content. An orchestrator LLM assigns tasks from the query. Evaluator optimizer loops until feedback is good.
  • A Loksewa essay site is a graph: topic, write, three scores, aggregate, then success or feedback and a retake loop.
  • Each node is a Python function. Edges set the direction: sequential, parallel, conditional, branching, or looping.
  • State is shared mutable memory in key value form. It is a TypedDict. All nodes can access it.
  • A reducer defines how node updates apply to state, so past state can be preserved.
  • A run defines the graph, compiles, invokes from initial state, may use a super step, continues to the last node, then stops. LangGraph is inspired by Google Pregel.
