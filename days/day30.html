What Is RAG

A common Gen AI use case is a chatbot, such as ChatGPT. You ask a question and get an answer.

But if you ask about your company salary details, ChatGPT will not know. That is obvious. The model never saw that private data.

When an LLM does not have the details, we give it external knowledge. That knowledge can come from a database, a file, or other sources.

RAG means retrieval plus language generation. First find useful information. Then let the model write the answer from that information.

RAG in one line

  1. External knowledge Files, databases, and more.
  2. Retrieve Find the useful parts.
  3. Generate LLM writes the answer.

Here are three strong reasons people use RAG.

Up to date info

You can feed fresh documents the model never trained on.

Better privacy

Keep company data in your own sources instead of hoping the model knows it.

No document size limit

You can work with large collections by retrieving only what you need.

What Are Document Loaders

Document loaders are LangChain components. They load data from many sources into one standard format.

Data can come from a PDF, a text file, a database, S3, and more. LangChain wraps each piece as a Document.

There are hundreds of loaders. We will learn the most used ones for text, PDF, folders, the web, and CSV. The basic idea is the same for all of them.

Every Document has two parts.

page_content

The actual text from the source.

metadata

Extra facts such as source path or page number.

431

TextLoader

TextLoader turns a text file into Document objects. You pass the file path. Sometimes you also set encoding.

Text to Document

  1. .txt file Raw text on disk.
  2. TextLoader Read the file.
  3. Document list page_content plus metadata.

Input code

from langchain_community.document_loaders import TextLoader

loader = TextLoader("day30.txt", encoding="utf-8")
documents = loader.load()

print(documents)
print(type(documents))
print(documents[0].page_content)

What you get

[Document(page_content="...", metadata={"source": "day30.txt"})]
<class 'list'>
...full text from day30.txt...

load returns a list of Document objects. You can read page_content and metadata separately.

PyPDFLoader and Other PDF Loaders

PyPDFLoader loads a PDF into Documents. Often you get one Document per page.

Input code

from langchain_community.document_loaders import PyPDFLoader

loader = PyPDFLoader("day30.pdf")
docs = loader.load()

print(docs)
print(len(docs))
print(docs[0].page_content)

What you get

[Document(...), Document(...), ...]
3
...text from page 1...

len(docs) tells you how many Document objects the PDF produced. Then read page_content on any one of them.

PyPDFLoader is not the only PDF option. Pick the loader that matches the PDF shape.

PDFPlumberLoader

Better when the PDF has tables and columns.

Unstructured loader

Useful for scanned or image based PDFs.

Amazon PDF loader

Another option for scanned or image based PDFs.

DirectoryLoader

What if a folder has many files, such as several PDFs? Use DirectoryLoader. It walks a folder and uses another loader class for each match.

One folder, many PDFs

  1. books/ Folder of files.
  2. glob *.pdf Keep only PDF matches.
  3. PyPDFLoader loader_cls for each file.
  4. Many Documents All pages from all matches.

Input code

from langchain_community.document_loaders import (
    DirectoryLoader,
    PyPDFLoader,
)

loader = DirectoryLoader(
    path="books",
    glob="*.pdf",
    loader_cls=PyPDFLoader,
)

docs = loader.load()

print(len(docs))
print(docs[0].page_content)
print(docs[0].metadata)

What you get

42
...first document text...
{"source": "books/...", "page": 0}

path is the folder. glob picks the file pattern. loader_cls says how each matching file should be loaded.

434

load versus lazy_load

Directory loading can take a few seconds. That is fine for a small set. But what if you load hundreds of PDFs into memory at once?

load() does eager loading. It builds every Document and holds the full list in memory. A 500 page PDF tries to become Document objects all at once.

lazy_load() returns a generator. It loads one Document at a time, on demand. Only one Document needs to sit in memory as you loop.

Method Style Returns Best when
load() Eager loading List of Document objects. All in memory. Small files, and you want everything ready at once.
lazy_load() Lazy loading Generator of Document objects. One at a time. Large folders or big PDFs, and you want lower memory use.

Eager load

docs = loader.load()

for document in docs:
    print(document.page_content)

Memory picture

All Documents exist in the list before the loop starts.

Lazy load

docs = loader.lazy_load()

for document in docs:
    print(document.page_content)

Memory picture

Each Document is created as the loop asks for the next one.

The loop looks the same. The difference is when Documents are created and how much memory you hold.

WebBaseLoader

WebBaseLoader pulls text content from a web page. Under the hood it uses requests and Beautiful Soup to turn HTML into text.

It works well for static sites such as blogs and news pages. It is not a good fit for JavaScript heavy pages that need a browser to render content.

URL to Document

  1. URL Page address.
  2. Fetch HTML requests pulls the page.
  3. Parse Beautiful Soup extracts text.
  4. Document page_content is plain text.

Input code

import os

os.environ["USER_AGENT"] = "python-training-bot/1.0"

from langchain_community.document_loaders import WebBaseLoader

loader = WebBaseLoader(
    web_paths=["https://www.google.com"],
)

docs = loader.load()
print(docs)

What you get

[Document(page_content="...page text...", metadata={...})]

Set USER_AGENT before you load. Many sites expect a clear agent string.

436

CSVLoader

CSVLoader loads CSV files. Each row becomes its own Document object.

Rows become Documents

  1. data.csv Rows and columns.
  2. CSVLoader Read the file.
  3. One Document per row Row fields become page_content.

Input code

from langchain_community.document_loaders import CSVLoader

loader = CSVLoader(file_path="data.csv")
docs = loader.load()
print(docs)

What you get

[
  Document(page_content="col1: a\ncol2: b", metadata={"source": "data.csv", "row": 0}),
  Document(page_content="col1: c\ncol2: d", metadata={"source": "data.csv", "row": 1}),
  ...
]

If the CSV has 100 rows, you get 100 Document objects. One row, one Document.
