Create Needs POST

Today we learn POST. POST is the create endpoint. We can create a patient. Yesterday we learned Pydantic. We need that model here, because the client will send new patient data.

The path is still client, then HTTP request, then server. The only change is the method. This request is POST, not GET.

POST from client to server

  1. Client Sends a POST request with new patient data.
  2. HTTP POST Same path idea as GET, but the verb is POST.
  3. Server FastAPI receives it and can create the patient.

The Request Body

We send the data in JSON format. That JSON is called the request body. It is the portion of an HTTP request that holds the data the client sends to the server.

A request body is used mostly with POST and PUT. For create, the HTTP method is POST and the request body is JSON.

GET POST
Read data. Path and query carry the extra facts. Create data. The extra facts sit in the request body.
Usually no JSON body. JSON body. POST and PUT use this a lot.

Validate the Body

We must validate that JSON. We may expect age as an int. The client might send the string thirty. It looks like a number in words, but it is still a string. That is why we make a Pydantic model. If the data is valid, we add it to our store. Here the store is a JSON file that acts as the database.

The two cards below are a bad body versus a valid body.

Rejected

Age was typed as thirty. Pydantic stops it. Nothing is saved.

Accepted

Age is a real int, and the other fields match the model. Then we add the patient.

605

The Patient Model

The create route takes a Patient object. FastAPI reads the JSON body and builds that object. id is required. The example id is P001. Age must be greater than 0 and less than 100. Gender must be male, female, or other. Height is in meters. Weight is in kilograms. Both must be greater than 0.

Patient fields

from pydantic import BaseModel, Field, computed_field
from typing import Annotated, Literal

class Patient(BaseModel):
    id: Annotated[str, Field(..., description="The ID of the patient", examples=["P001"])]
    name: Annotated[str, Field(..., description="The name of the patient")]
    city: Annotated[str, Field(..., description="The city of the patient")]
    age: Annotated[int, Field(..., description="The age of the patient", gt=0, lt=100)]
    gender: Annotated[Literal["male", "female", "other"], Field(..., description="The gender of the patient")]
    height: Annotated[float, Field(..., description="The height of the patient in meters", gt=0)]
    weight: Annotated[float, Field(..., description="The weight of the patient in kg", gt=0)]

What FastAPI does

The JSON body must match these fields.
A missing id, a word for age, or a gender
outside male, female, other, fails validation.
606

BMI and Verdict

The client does not send BMI or verdict. Those are computed fields. BMI is weight divided by height squared. Height must be in meters. Verdict is a label from that BMI. The table below is the rule in the code.

BMI Verdict
Less than 18.5 Underweight
Less than 24.9 Normal
Less than 30 Overweight
30 or more Obese

Computed fields

    @computed_field
    @property
    def bmi(self) -> float:
        return self.weight / (self.height ** 2)

    @computed_field
    @property
    def verdict(self) -> str:
        if self.bmi < 18.5:
            return "Underweight"
        elif self.bmi < 24.9:
            return "Normal"
        elif self.bmi < 30:
            return "Overweight"
        else:
            return "Obese"

What the client does not send

bmi and verdict are calculated after
height and weight pass validation.
607

POST /create

load_data reads data.json. save_data writes it back with indent 4. POST /create takes a Patient. If that id is already a key, we raise 400, patient already exists. If not, we turn the model into a dict with model_dump(exclude=["id"]). The id is the key in the file, so we do not store it again inside the object. Then we save. We return 201, patient created successfully.

The steps below are that create path.

From body to file

  1. Load Read data.json.
  2. Check id If the id exists, return 400.
  3. Save Store the dump under that id, without repeating id.
  4. 201 Patient created successfully.

Create route

from fastapi import FastAPI, status, HTTPException
from fastapi.responses import JSONResponse
import json

app = FastAPI()

def load_data():
    with open("data.json", "r") as f:
        return json.load(f)

def save_data(data):
    with open("data.json", "w") as f:
        json.dump(data, f, indent=4)

@app.post("/create")
def create_patient(patient: Patient):
    data = load_data()

    if patient.id in data:
        raise HTTPException(
            status_code=status.HTTP_400_BAD_REQUEST,
            detail="Patient already exists"
        )

    data[patient.id] = patient.model_dump(exclude=["id"])
    save_data(data)

    return JSONResponse(
        status_code=status.HTTP_201_CREATED,
        content={"message": "Patient created successfully"}
    )

What POST returns

POST /create  new id
status 201
{"message": "Patient created successfully"}

POST /create  same id again
status 400
{"detail": "Patient already exists"}

Day 44 takeaways

Day 44 takeaways

  • GET so far: home message, all patients, one patient by path id, and sort with query parameters.
  • POST creates a patient. The client still talks to the server. The verb is POST.
  • The JSON the client sends is the request body. POST and PUT use a body a lot.
  • A Pydantic model checks the body. A string like thirty is not an int. Invalid data is not saved.
  • id, name, city, age, gender, height in meters, and weight in kg are required. BMI and verdict are computed.
  • If the id exists, return 400. If create works, dump without id, save data.json, return 201.
