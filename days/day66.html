Day 66

How LLMs Remember

An LLM at inference is a math function with no memory. We build a system around it so a chatbot can keep a thread, and later keep facts that last.

861

A Parameterized Math Function

Let us start with a simple statement. An LLM at inference is just a parameterized math function. We write y equals f of x with theta. In math, parameterized means we need the input and the parameters to find the output.

The next example is linear regression. y equals m x plus b. Here m and b are the parameters. We find them from the data. We can also write y equals f of x with m and b. Theta in the LLM formula stands for the billions of parameters. That is why we say a 100 billion parameter model, or a 100 million parameter model. The picture below is those formulas.

862

x, y, and Theta

We now name x, y, and theta in that function. x is the input tokens. We can call it the prompt. y is the output tokens. y depends on both theta and x. Theta is fixed. It is trained at the beginning. x is not fixed. That is why when we change the prompt we get a different answer. The cards below are those three parts.

x

Input tokens. The prompt. This changes every turn.

y

Output tokens. The answer the model writes.

theta

The trained weights. Fixed at inference. Billions of numbers.

863

Stateless by Nature

The interesting property of the formula is this. It is stateless. That means it only depends on the current input, not on anything that happened before. An LLM is stateless by nature. That means the LLM does not have memory, and it cannot remember the past conversation on its own.

864

We Invent Memory

Every LLM app still needs memory. What happens in a chatbot is this. You send a message and it replies. Next turn, if we do not send the old context, the model will not remember. It will not remember that my name is Bishal. So we build a system that acts as memory. We invent that system around the model. The table below is the gap we fill.

The model alone The system we build
Sees only the current prompt. Sends history, or saved facts, with the prompt.
Forgets the name Bishal on the next call. Puts that name back into x, so y can use it.
865

Context Window

First question. How much x, that is input tokens, can we send? Is there a max? The answer is the context window. Every LLM has a context window. The context window is the limit an LLM can read and remember before giving the answer.

The analogy is a camera. If the lens is small, we capture a small part. If the lens is big, we get a big picture. Today some context windows are 1 million tokens, like Gemini. We can upload up to 200 pages of PDF as well. That is a very important power. We can send a lot of tokens in the input. The cards below are that lens idea.

Small lens

A small context window. The model sees only a thin slice of text.

Big lens

A large window, such as 1 million tokens. More of the file fits in x.

866

In Context Learning

When we train an LLM, we give a huge amount of data. The LLM finds patterns in the data and puts them in the parameters. When we ask a prompt, that prompt goes through those parameters. If the answer lives there, the model can write it.

As models got stronger, we found they do not only use the parameters. They also look at the prompt. They try to find details from the prompt as well. For example, we give a PDF of 100 pages. It is private company data. We ask a question about that PDF. The LLM does not have that PDF in theta. It can still read the PDF in x and answer.

In context learning is an emergent ability. It lets an LLM use information and patterns present in the prompt itself, then generate an answer. The table below is parameters versus the prompt.

From theta From the prompt
Patterns learned in training, stored in weights. Facts sitting in x right now, such as a private PDF.
Fixed until we train again. New each call. This is in context learning.
867

Concat History

When we invoke the LLM, we concat the whole context and send it. At first we did y1 equals f of x1 with theta, then y2 equals f of x2 with theta. Each call was alone. What we do now is concat the old turns into x. For the second answer we send concat of x1, y1, and x2. We are not telling the LLM to learn everything into theta. We are giving history as context. The list we add acts as temporary memory. That is short term memory. The picture below is that concat.

868

Thread Scoped Short Term Memory

How do we implement short term memory in a chatbot? The UI has multiple chats in the sidebar. We only concat the messages of that chat session. If we have 1000 conversations with ChatGPT, we cannot put one short term memory over all of them. One chat is one short term memory. The next conversation has no effect on this one. We can call a conversation a thread. Short term memory is thread scoped. It is just a conversation buffer. It holds all the turns with the chatbot in that thread.

869

Fragile, Then Persist

Short term memory has cons. It is fragile. It can break. If the code is reset, it will remove the whole conversation. We need persistence to save the convo for longer. As we chat, and as we go to a new chat, we store the data in a db. We save every convo in the db. We use a thread for it. Then the bot can reply using the previous context after a restart. The steps below are that save.

Keep the buffer

  1. Chat Turns live in the conversation buffer for this thread.
  2. Persist Write that thread into a db so a reset does not wipe it.
  3. Reload Load the thread, concat it, and reply with that context.
870

Trim and Summarize

The second problem is the context window. An LLM can only take a max, such as 1 million tokens, in the input. If we use a chatbot for a very long time, the model needs to read the whole convo for context. If we tokenize that history, it can exceed the context window. The LLM might hallucinate, or forget. The solution is trimming plus summarization. In trimming we send only n messages, such as the last 10. The problem with trimming is we will not have the context of the whole conversation. So we also summarize the older convo, and we send that summary with the last messages. The table below is that pair.

Trimming Summarization
Send only the last n messages, such as the last 10. Send a short recap of the older turns.
Fits the window. Loses the start of the chat. Keeps the gist so the model is not blind to the past.
871

Thread Scope Is a Limit

The third problem. Short term memory is thread scoped. Each convo has its own thread id. Thread scope is also a disadvantage. No user can keep continuity across chats. For a solution we need a new kind of memory. It should store information that survives beyond a single conversation, beyond a single session, and sometimes beyond days and weeks. That is the kind of information that defines continuity. Who the user is. How the system is expected to behave for them. What usually fails. What decisions were already made in the past.

The second property is this. It has to be selective. Only information that proves stable, useful, and reusable should survive beyond a single thread. Everything else should fade away. This is long term memory.

872

Three Types of Long Term Memory

There are three types of long term memory in LLM systems. Episodic memory lets us know what happened in the past. A solution the user rejected. Credentials that were wrong before. The benefit is we can ask what did we do last time, and did we use this technique last time. Semantic memory is the most common and most important. It is made of facts about the user and the system. The user is a Python developer. They use this tech. We store what is true about the user or the system. Procedural memory stores rules, strategies, and learned behaviour. Preferred workflow. When to do what. How. These compound over time. Because of this, the AI can feel better in the long term. The cards below are those three.

Episodic

What happened. A rejected plan. Wrong credentials last time.

Semantic

Facts. The user is a Python developer. What is true about them.

Procedural

Rules and workflows. When to do what. They grow over time.

873

How Long Term Memory Works

Step 1 is creation or update. The user talks with the chatbot. We ask if anything from what just happened is worth remembering beyond this conversation. We look at the user message, the model output, and also tool outcomes. We extract memory candidates. For example the user says I like Python more than JS. We filter out noise. We decide scope, such as user, agent, or app. We decide whether to create a new memory, update one, or ignore it.

Step 2 is storage. We store it so we do not lose it. We add metadata. The main purpose is that it survives any restart and crash. There are many options, like a relational store, a key value store, a log, or a vector db. For each type of memory the store can be different.

Step 3 is retrieval. The user starts a new chat. This is where retrieval comes in. The system asks if the memory is required or not. Retrieval is selective. The steps below are those three, then injection in the next lesson.

Create, store, retrieve

  1. Create or update Extract candidates. Filter noise. Create, update, or ignore.
  2. Store Save with metadata so a crash does not wipe the facts.
  3. Retrieve On a new chat, pick only the memory this turn needs.

Challenges and Libraries

The key challenges for building such memory are these. Deciding what is worth remembering. The user chats a lot, and deciding what is important is hard. Retrieving the right memory at the right time, while the user is in the conversation. Orchestrating the entire system. That part is very hard. It is tricky.

There are managed solutions that act as a memory layer. The app calls a function. The library handles the rest. LangMem. Mem0, for Gen AI apps. SuperMemory as well. They manage long term memory. LLMs do not have default memory. A few labs are in process, such as a Google research paper on Titans plus MIRAS. Currently that is not in use. The research is not complete. The cards below are the libraries named in the notes.

A memory layer you call. It handles long term store and retrieve.

Mem0

For Gen AI apps. You function call. It manages the memory.

SuperMemory

Another managed layer for long term memory.

Day 66 takeaways

Day 66 takeaways

  • At inference an LLM is y equals f of x with theta. Theta is fixed. x is the prompt.
  • The function is stateless. The model does not remember Bishal unless we send that fact again.
  • The context window is the max x. A big window is a big camera lens, such as 1 million tokens.
  • In context learning uses patterns in the prompt, including a private PDF that is not in theta.
  • Short term memory concats the thread. Persist it in a db. Trim and summarize when the window fills.
  • Long term memory is selective, and it lasts beyond one thread. Episodic, semantic, and procedural.
  • The path is create, store, retrieve, then inject into the prompt. Libraries like LangMem and Mem0 help. Titans plus MIRAS is still research.
