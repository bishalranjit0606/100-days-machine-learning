Day 48

LangChain vs LangGraph

LangGraph is very famous and top important. We recap LangChain, walk a hiring workflow, then see seven reasons LangGraph fits that kind of work.

638

LangChain Recap

LangChain is an open source library designed to simplify the process of building applications. It provides the building blocks that let you create sophisticated LLM based workflows with ease.

639

LangChain Components

LangChain gives you a few core parts. The cards below are that set. Chain is the important one. The output of one step is the input of the next.

Model

Connect an LLM such as OpenAI or Gemini.

Prompt

Give a task to the LLM.

Retrievers

Fetch relevant documents from a vector store.

Chain

Hook steps so one output becomes the next input.

One chain looks like this. Prompt, then model, then output parser.

A simple chain

  1. Prompt Write the task for the model.
  2. Model The LLM runs that task.
  3. Output parser Turn the model text into a clean result.

What LangChain Can Do

You can build several kinds of apps with LangChain. The four cards below are that set.

Simple chat

Conversational work such as a chatbot or text summarize.

Multi step

Prompt, then LLM, then prompt, then LLM, then prompt.

RAG

A RAG application that fetches documents and then answers.

Basic agents

Simple agents that connect tools or APIs. The LLM decides what to call. One example is a weather API. The LLM can call it and find the answer.

641

Automated Hiring Workflow

Agents can make a workflow. The hiring flow below is static. The steps are set in advance. It still has waits, loops, and jumps.

Start with a hiring request. An LLM creates the JD. A human must approve it. If the human says no, go back and create the JD again. If yes, post the JD. Wait 7 days. Monitor applications. If there are less than 10 applications, modify the JD, wait 48 hours, monitor again, and check the count again. That loop repeats while the count stays under 10.

If there are not less than 10, shortlist, schedule the interview, and conduct the interview. Check if anyone is selected. If not, send a sorry mail. If yes, send an offer letter. If the offer is not accepted, modify the offer, negotiate, and loop until it ends.

Challenge 1 Control Complexity

If we build that hiring system in LangChain we face many issues. Challenge 1 is control complexity.

LangChain is used for making chains and linear workflows. Our hiring workflow has too many conditionals, loops, and jumps. Implementing that workflow in LangChain is very hard.

We have to write glue code. Glue code means framework code plus actual code. That is LangChain plus Python. When the glue code is large, the object gets very bad. LangChain has code for the chain, the prompt, and similar parts. It has no code for a condition or a loop. That part is Python.

In LangGraph we make nodes. We do not have to use glue code or custom Python for those jumps. Every task is a node.

LangChain LangGraph
Chains and linear workflows. Each task is a node.
Conditions and loops need Python glue code. No glue code for those jumps.
643

Challenge 2 Handling State

State means the important data points in the workflow. In hiring that might be the created JD, how many people applied, and similar facts. We need to maintain that every time.

Those data points evolve. First there is none. Then the JD is created. Then we monitor. As we go to the next step, the data evolves. Every workflow has data points, so state scales with the workflow.

State evolves as we move

  1. None At the start there is no hiring data yet.
  2. JD created The job description is now in state.
  3. Monitor Application counts and later facts join the same state.

LangChain is stateless. We cannot track state inside it. To track it we must do it manually, by making our own state. LangGraph is stateful. While creating LangGraph we make a state object or dict. It can be added in any node. It is mutable, so it can be edited. That means the state is available in every node. Passing information is very good in LangGraph.

644

Challenge 3 Event Driven Execution

A workflow can be sequential or event driven. Sequential work runs in a line. Prompt, then LLM, then prompt, then LLM, then a response. That execution works in sequence and stays in a flow.

Our hiring workflow has nodes that wait for an event. Once we post on LinkedIn we wait 7 days. Once an offer letter is sent we wait for the candidate to say yes or no.

LangChain is not meant for event driven work. It is sequential. If we still use LangChain we make two workflows and custom code to wait 7 days. That is too much glue code. LangGraph gives us event driven facility. LangGraph also gives us a feature like store state.

Sequential Event driven
Prompt, LLM, prompt, LLM, response. Post, then wait 7 days. Offer, then wait for yes or no.
LangChain is built for this line. LangGraph supports this wait.
645

Challenge 4 Fault Tolerance

Fault tolerance does not mean the system is bad and it still works. It means the work can continue when a fault happens. That is very important for a long running workflow. We might wait 7 days. The workflow might run for months.

A fault can be small or big. A small fault is an API not working. A big fault is the server not working.

LangChain does not have fault tolerance. If a node fails in the middle, we have to restart from the beginning.

LangGraph is different. If a small error occurs, retry it after some time. For a big fault, such as the server down, recovery uses checkpoints. We track state, and the graph is stateful, so we can restart when we want. Fault tolerance is very high in LangGraph.

Small fault Big fault
An API is not working. The server is not working.
LangGraph can retry after some time. LangGraph restarts from a checkpoint.
646

Challenge 5 Human in the Loop

In the hiring workflow, when we make the JD we wait for approval. The flow only continues after the human approves. Agents do not have all the control. A human should have all the control.

LangChain does not have a default mechanism for the human. What we can do is ask for human input. That only works for a very small time. If the input takes 24 hours, the system might crash because it will wait too long. Human in the loop is not present in LangChain.

In LangGraph it is a first class citizen. LangGraph can pause the workflow for a minute, an hour, or a week, until the human response is received, without that crash. Since we track state, there is no issue. We can continue from where we stopped.

647

Challenge 6 Nested Workflow

Nested workflow is a feature of LangGraph. A node can be a graph as well. A nested node can be a subgraph. That is a workflow inside a workflow.

For example, conduct interview can have a sub workflow, because we might conduct the interview multiple times. This is the concept of encapsulation in LangGraph. With this feature we can make a multi agent system. The work is reusable. We can use it multiple times, like a function we write in code. LangChain does not have this feature.

A self driving car is a good example of multi agent work. The three cards below are those agents. Multi agent setups are used for complex problems.

Sensor agent

Takes all the sensor data.

Driving agent

Handles driving capability.

Manager agent

Works as a manager over the others.

648

Challenge 7 Observability

Observability means how easily we can monitor and understand what our work is doing at run time. It is a very important concept.

LangSmith helps monitor the application. It can be used for LangChain and for LangGraph. It records what we send in the prompt, and the output tokens.

The problem is that LangChain only monitors LangChain, not the glue code. That is the main issue. We get only partial observability if we make a complex workflow in LangChain. LangSmith is tightly tied to LangGraph, and everything is recorded. We can backtrack everything.

649

When to Use Which

LangGraph is a framework for stateful, multi step, and event driven workflows. It is for both single agent and multi agent agentic AI applications. It covers state management, branching, loops, pausing, and fault memory.

The table below is when to use each one.

LangChain LangGraph
Simple linear workflow. Complex, non linear workflow.

Should we still use LangChain? Yes. Every component of LangChain is still useful. Prompt templates, retrievers, documentation, tools, and the rest still help us.

650

Day 48 takeaways

Day 48 takeaways

  • LangGraph is very famous and top important. LangChain is still the open source library of building blocks for LLM workflows.
  • LangChain parts are model, prompt, retrievers, and chain. A chain can be prompt, then model, then output parser.
  • LangChain fits chat, multi step prompts, RAG, and basic agents such as a weather API call.
  • A hiring workflow is static but full of approval loops, a 7 day wait, a less than 10 applications loop, interviews, and offer negotiation.
  • LangChain is linear and stateless. Conditions, loops, and waits become glue code. A mid run fault restarts from the beginning. Human waits of 24 hours can crash it. Observability misses the glue code.
  • LangGraph uses nodes, a shared mutable state, event driven waits, retries, checkpoints, pause for a human, nested subgraphs, and full LangSmith traces.
  • Use LangChain for simple linear work. Use LangGraph for complex non linear work. Keep LangChain components such as prompt templates, retrievers, documentation, and tools.
