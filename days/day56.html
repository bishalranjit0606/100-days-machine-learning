Day 56

Chatbot with UI in LangGraph

Split the chatbot into a LangGraph back end and a Streamlit front end. The user talks to the page. The page talks to the graph. Session state keeps the chat on screen.

729

Plan of Action

The chatbot is divided into two parts. The back end is the LangGraph workflow. The front end is Streamlit. The user talks to the front end. The front end talks to LangGraph. The cards below are that split. The diagram after them is the path.

Back end

A LangGraph workflow. State is a message list. One chat node. A checkpointer.

Front end

A Streamlit page. Chat bubbles and a chat box. It calls the compiled graph.

730

Streamlit Basics

Streamlit is a very simple library. You write Python. It draws a web page. Today we need two pieces from it: chat_message for bubbles, and chat_input for the box at the bottom.

731

Back End State

The back end lives in a file named langgraph_backend. ChatState holds messages. add_messages is the reducer, so new messages append. ChatOpenAI is the model. Put this file next to the Streamlit file so the front end can import chatbot.

langgraph_backend.py

from langgraph.graph import StateGraph, START, END
from typing import TypedDict, Annotated
from langchain_core.messages import BaseMessage
from langchain_openai import ChatOpenAI
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.graph.message import add_messages
from dotenv import load_dotenv

load_dotenv()

llm = ChatOpenAI()

class ChatState(TypedDict):
    messages: Annotated[list[BaseMessage], add_messages]

messages is a list. The reducer keeps old turns when a node returns a new list item.

732

Chat Node and Compile

chat_node reads the message list, invokes the model, and returns the new AI message. START goes to chat_node. chat_node goes to END. We compile with InMemorySaver and name the app chatbot. The diagram below is that back end line.

Node, edges, compile

def chat_node(state: ChatState):
    messages = state['messages']
    response = llm.invoke(messages)
    return {"messages": [response]}

checkpointer = InMemorySaver()

graph = StateGraph(ChatState)
graph.add_node("chat_node", chat_node)
graph.add_edge(START, "chat_node")
graph.add_edge("chat_node", END)

chatbot = graph.compile(checkpointer=checkpointer)

The front end will import this chatbot object and call invoke on it.

733

Two Boxes on the Page

This is the front end part of the chatbot. In Streamlit we want two boxes. One is chat_message. The other is chat_input. The steps below are how we build them.

Front end pieces

  1. chat_message A bubble. User or assistant.
  2. chat_input The box where the user types.
734

chat_message

st.chat_message draws one bubble. Pass user or assistant. Then st.write puts text inside that bubble. The sample below is four bubbles in a row.

Fixed bubbles

import streamlit as st

with st.chat_message("user"):
    st.write("Hello, how are you?")

with st.chat_message("assistant"):
    st.write("I'm good, thank you!")

with st.chat_message("user"):
    st.write("my name is bishal")

with st.chat_message("assistant"):
    st.write("Nice to meet you, bishal!")

These lines are fixed text. They always show the same four lines.

735

chat_input

The second component is chat_input. It returns the string the user typed, or nothing if they have not sent a line yet. If there is input, we draw a user bubble with that text.

Read one line

user_input = st.chat_input("Enter your message")

if user_input:
    with st.chat_message("user"):
        st.write(user_input)

Run this with streamlit run and type in the box at the bottom of the page.

736

Echo, Then the Rerun Problem

Now we make the AI repeat the same thing we write. The assistant bubble writes user_input again. That is only a test. It is not the LangGraph model yet.

Echo

import streamlit as st

user_input = st.chat_input("Enter your message")

if user_input:
    with st.chat_message("user"):
        st.write(user_input)

    with st.chat_message("assistant"):
        st.write(user_input)

You send hi. You see hi, then hi again as the assistant line.

The data will change again and again. It will not save. Streamlit reruns the whole script after each send. The old bubbles are gone. We need to store conversation history. That is why we use a dictionary on session_state.

Only local variables session_state
The script reruns. Old lines disappear. The list stays on the page across reruns.
737

message_history

st.session_state is a dictionary. If message_history is not in it yet, we start it as an empty list. Each item is a small dictionary with role and content. On every rerun we loop that list and draw the old bubbles first. Then we wait for a new line.

History shape

if 'message_history' not in st.session_state:
    st.session_state['message_history'] = []

for message in st.session_state['message_history']:
    with st.chat_message(message['role']):
        st.text(message['content'])

# {'role': 'user', 'content': 'Hi'}
# {'role': 'assistant', 'content': 'Hello'}

role is user or assistant. content is the text in that bubble.

738

Front End Calls the Graph

The full front end imports chatbot from langgraph_backend. CONFIG sets thread_id to thread-1 so the checkpointer keeps one conversation. After the user types, we append the user line, invoke the graph with a HumanMessage, take the last message content, append the assistant line, and draw it.

Streamlit page

import streamlit as st
from langgraph_backend import chatbot
from langchain_core.messages import HumanMessage

CONFIG = {'configurable': {'thread_id': 'thread-1'}}

if 'message_history' not in st.session_state:
    st.session_state['message_history'] = []

for message in st.session_state['message_history']:
    with st.chat_message(message['role']):
        st.text(message['content'])

user_input = st.chat_input('Type here')

if user_input:
    st.session_state['message_history'].append(
        {'role': 'user', 'content': user_input}
    )
    with st.chat_message('user'):
        st.text(user_input)

    response = chatbot.invoke(
        {'messages': [HumanMessage(content=user_input)]},
        config=CONFIG
    )

    ai_message = response['messages'][-1].content
    st.session_state['message_history'].append(
        {'role': 'assistant', 'content': ai_message}
    )
    with st.chat_message('assistant'):
        st.text(ai_message)

The assistant text comes from the model. We do not paste a fake reply here. Run the Streamlit app to see yours. message_history keeps the page. The thread keeps the graph memory.

Day 56 takeaways

Day 56 takeaways

  • The chatbot has two parts: a LangGraph back end and a Streamlit front end.
  • The path is user, then front end, then LangGraph.
  • The back end is START, chat_node, END, compiled with InMemorySaver as chatbot.
  • Streamlit uses chat_message for bubbles and chat_input for the box.
  • A rerun wipes local variables. session_state message_history keeps the bubbles on the page.
  • invoke sends a HumanMessage with a thread id. The last message content is the assistant line.
