Why Paper Records Fail

From this day we will make a project API. It is an app for a doctor.

When you visit a doctor, the doctor often gives you a paper file to bring next time, and the time after that. The file is offline. It can get lost.

The steps below are that paper path.

Paper at the clinic

  1. Visit The patient sees the doctor.
  2. Paper file The doctor writes notes to bring next time.
  3. Next visit The same paper is needed again.
  4. Lost Because it is offline, the file can disappear.

Static vs Dynamic Software

HTTP methods matter because software can be static or dynamic. Static software limits the user. You mostly receive data. Dynamic software lets you talk both ways.

A calendar is static. It gives dates and days. You do not engage with it much. A clock is the same idea. Microsoft Excel is dynamic. You interact with it a lot. The table below puts those two kinds side by side.

Static Dynamic
You mostly receive data. Little two way talk. You can send and change data. Two way talk.
Calendar. Clock. Microsoft Excel.
573

CRUD

In dynamic software we only interact in four ways. Those four are CRUD. C is create. R is retrieve. U is update. D is delete. The four cards below are that set.

C Create

Make a new record.

R Retrieve

Read data that is already stored.

U Update

Change a record.

D Delete

Remove a record.

574

A Website Is Software

A website is also software. The only difference is where it lives. Installed software sits on your machine. A website sits on a server. Other machines, called clients, use it. That use happens with HTTP methods.

A website can be static or dynamic too. A dynamic website also has CRUD. The table below is installed software next to a website.

Installed software Website
Installed on your machine. Installed on a server.
You run it on that same machine. Clients on other machines use it.
Talk happens inside the app. Talk happens with HTTP methods.
575

HTTP Methods

HTTP methods are a very important concept. While you do a task on the web, the verb tells the server what kind of work you want.

To retrieve data, use GET. To fill a form, use POST. To update, use PUT. To delete, use DELETE. The four methods are GET, POST, PUT, and DELETE. The table below maps each CRUD job to a verb.

CRUD job HTTP method
Retrieve GET
Create, like filling a form POST
Update PUT
Delete DELETE
576

Load Patients and GET Routes

Today we start with retrieve. load_patients opens patients.json and returns the file as a Python dict. GET / says this is a patient management system. GET /about describes the API. GET /patients reads every patient from the JSON file and returns it.

That last route is our first read. Later we will add create, update, and delete.

main.py

import json
from fastapi import FastAPI

def load_patients():
    with open("patients.json", "r") as f:
        return json.load(f)

app = FastAPI()

@app.get("/")
def read_root():
    return {"message": "patient management system"}

@app.get("/about")
def about():
    return {"message": "this is a full API for a patient management system"}

@app.get("/patients")
def get_patients():
    data = load_patients()
    return data

What GET returns

GET /          {"message": "patient management system"}
GET /about     {"message": "this is a full API for a patient management system"}
GET /patients  the whole patients.json object, including poo1

json.load turns the file text into a Python dict. FastAPI sends that dict back as JSON.
