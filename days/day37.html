Day 37

Tool Calling in LangChain

Connect tools to the LLM, let it choose a tool, then run the tool yourself and send the result back.

463

Recap: Tools and the Gap

Day 36 covered tools. An LLM can think and generate language. It cannot do real work on its own.

It cannot book a flight, change a file on your machine, or hit your API without help. Tools are functions that can interact with the outside world.

Today we connect the LLM to those tools. We learn how the model decides to use one, and how we run it safely.

464

What Is Tool Binding

Tool binding is how you register tools with the LLM. You connect them so the model knows they exist.

After binding, the LLM learns three things.

Tools exist

Which tools are available for this chat.

What each does

Name and description from the tool schema.

Input format

Which arguments each tool expects.

Not every LLM supports tool binding. You need a model that was built for tool or function calling.

465

Create a Tool and Bind It

Start with a simple add tool. Bind it to the LLM with bind_tools.

Tool create and bind

import os
from langchain_openai import ChatOpenAI
from langchain_core.tools import tool

@tool
def add(a: int, b: int) -> int:
    """Add two numbers."""
    return a + b

print(add.invoke({"a": 3, "b": 4}))
print(add.args)

llm = ChatOpenAI(
    model="openrouter/free",
    temperature=0.3,
    base_url="https://openrouter.ai/api/v1",
    api_key=os.environ["OPENROUTER_API_KEY"],
)

llm_with_tools = llm.bind_tools([add])

What you get

7
Schema for a and b as integers.
llm_with_tools is ready to suggest the add tool when needed.

Keep API keys in environment variables, not in notebook cells.

466

What Is Tool Calling

Tool calling is when the LLM decides during a task that it needs a specific tool. It returns structured output instead of a plain answer.

Chat vs math ask

result = llm_with_tools.invoke("hello")
print(result.content)

result = llm_with_tools.invoke("add 4 and 5")
print(result.content)
print(result.tool_calls[0]["args"])

What you get

For hello: normal text reply.

For add 4 and 5: content may be empty.
tool_calls shows something like:
{"name": "add", "args": {"a": 4, "b": 5}, ...}

The model suggests the tool and the args. It does not run add for you.

467

Tool Execution

Tool calling and tool execution are different steps. Calling means the LLM says use add with a=4 and b=5. Execution means your code actually runs add.

We do not let the LLM run tools on its own. That can be risky. Shell tools, APIs, and databases should stay under your control.

Run the tool yourself

result = llm_with_tools.invoke("add 4 and 5")

# Pass args only:
add.invoke(result.tool_calls[0]["args"])

# Or pass the full tool call object:
tool_result = add.invoke(result.tool_calls[0])
print(tool_result)

What you get

9
A ToolMessage with the result content.

Your app decides when and how to execute. The LLM only plans the call.

468

The Message Loop

To get a final answer, keep a messages list. Add the human ask, the AI tool call, the tool result, then ask the LLM again.

One tool round trip

  1. HumanMessage The user question.
  2. AIMessage Model returns tool_calls.
  3. ToolMessage You run the tool and append the result.
  4. Final reply LLM reads all messages and answers.

Full add loop

from langchain_core.messages import HumanMessage

query = HumanMessage(content="can you add 3 and 10")
messages = [query]

ai_message = llm_with_tools.invoke(messages)
messages.append(ai_message)

tool_result = add.invoke(ai_message.tool_calls[0])
messages.append(tool_result)

final = llm_with_tools.invoke(messages)
print(final.content)

What you get

A natural language answer like:
"The sum of 3 and 10 is 13."
Exact wording depends on the model.

Why Currency Needs Tools

Exchange rates change every day. Ask how much 99 USD is in INR. A plain LLM may guess from old training data.

For a real time answer, we need a live API and two tools. One fetches the rate. One does the math.

Currency flow

  1. Fetch rate get_conversion_factor calls the API.
  2. Convert convert multiplies value by rate.
  3. Answer LLM writes the final reply.
470

Build get_conversion_factor

This tool hits an exchange rate API and returns the conversion factor between two currencies.

Fetch live rate

import requests
from langchain_core.tools import tool

API_KEY = os.environ["EXCHANGE_RATE_API_KEY"]

@tool
def get_conversion_factor(
    base_currency: str,
    target_currency: str,
) -> float:
    """Fetch the currency conversion factor."""
    url = (
        f"https://v6.exchangerate-api.com/v6/"
        f"{API_KEY}/latest/{base_currency}"
    )
    response = requests.get(url)
    data = response.json()
    return data["conversion_rates"][target_currency]

print(get_conversion_factor.invoke({
    "base_currency": "USD",
    "target_currency": "NPR",
}))

What you get

A float rate such as 143.5.
Exact number changes with live market data.

Sign up at exchangerate-api.com for a free key. Store it in EXCHANGE_RATE_API_KEY.

471

Build convert

The second tool takes a base value and a rate, then returns the converted amount.

Multiply by rate

@tool
def convert(
    base_currency_value: int,
    conversion_rate: float,
) -> float:
    """Calculate target currency value from a rate."""
    return base_currency_value * conversion_rate

print(convert.invoke({
    "base_currency_value": 100,
    "conversion_rate": 143.5,
}))

What you get

14350.0

Bind Both Currency Tools

Register both tools on the same LLM. Now the model can plan a fetch step and a convert step for one user question.

Bind two tools

llm_with_tools = llm.bind_tools([
    get_conversion_factor,
    convert,
])

messages = [
    HumanMessage(
        content="What is the conversion factor between "
        "INR and USD, and can you convert 10 INR to USD?"
    )
]

ai_message = llm_with_tools.invoke(messages)
print(ai_message.tool_calls)

What you get

A list of planned tool calls.
Often two calls: one for the rate,
one for the conversion.
Exact order depends on the model.
473

InjectedToolArg

Sometimes the LLM should not pick every argument. The rate from step one should feed step two. InjectedToolArg marks an arg that your code injects, not the model.

Hide conversion_rate from the LLM

from typing import Annotated
from langchain_core.tools import InjectedToolArg

@tool
def convert_injected(
    base_currency_value: int,
    conversion_rate: Annotated[float, InjectedToolArg],
) -> float:
    """Convert using a rate your code supplies."""
    return base_currency_value * conversion_rate

What this means

convert_injected.args no longer asks the LLM
for conversion_rate.
You pass that value when you invoke the tool.

This keeps chained tools safe. The model plans the steps. Your code passes hidden values between them.

474

Run Two Tools in Order

Loop over tool_calls from the AI message. Run get_conversion_factor first. Grab the rate. Inject it into convert. Append each ToolMessage. Then ask the LLM again.

Chain two tool results

import json

messages.append(ai_message)
conversion_rate = None

for tool_call in ai_message.tool_calls:
    if tool_call["name"] == "get_conversion_factor":
        tool_message = get_conversion_factor.invoke(tool_call)
        conversion_rate = float(tool_message.content)
        messages.append(tool_message)
    if tool_call["name"] == "convert":
        tool_call["args"]["conversion_rate"] = conversion_rate
        tool_message = convert.invoke(tool_call)
        messages.append(tool_message)

answer = llm_with_tools.invoke(messages)
print(answer.content)

What you get

A plain language answer with the live rate
and the converted amount.
Numbers match the API at call time.

You orchestrate the loop. The LLM plans which tools to use. Your code runs them in a safe order.

475

Is This an Agent

Not yet. What we built is a manual tool calling loop.

Manual loop today Agent later
You write the for loop over tool_calls. The framework decides the next step in a loop.
You inject values like conversion_rate. The agent picks tools until the task is done.
Good for learning and tight control. Good for open ended tasks with many steps.

Tool binding, calling, and execution are the foundation. Agents add automatic planning on top.

Day 37 takeaways

Day 37 takeaways

  • Tool binding registers tools so the LLM knows names, jobs, and input schemas.
  • Tool calling means the model returns tool_calls. Tool execution means your code runs the tool.
  • Keep a messages list: human ask, AI plan, tool result, then a final LLM reply.
  • Live data like currency rates needs API tools, not guesswork from training.
  • InjectedToolArg lets your code pass hidden values between chained tools.
  • A manual loop is not an agent yet. Agents automate the think and act cycle.
