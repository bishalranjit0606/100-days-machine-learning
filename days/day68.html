901

put Writes a Memory

We use the put method. It has three values. Namespace, key, and value. put inserts into that namespace. We learned create using put. The first block writes two keys under user u1. The second block writes two keys under user u2. We use the name namespace after we point it at u2. The notes had namespace2 there. That name was not set, so the working code uses namespace.

InMemoryStore and put

from langgraph.store.memory import InMemoryStore

store = InMemoryStore()

namespace = ("user", "u1")
store.put(namespace, "1", {"data": "hello i am bishal"})
store.put(namespace, "2", {"data": "hello i am kiran"})

namespace = ("user", "u2")
store.put(namespace, "1", {"data": "bishal likes python"})
store.put(namespace, "2", {"data": "bishal likes javascript"})

Same store. Two namespaces. u1 and u2 do not mix.

get and search

Retrieve has two methods. get and search. get is used if we have the exact key. search is used to get all the items. We learned create using put, and retrieve with those two. The first block gets one key at a time. The second block searches the namespace and loops the items. We print each item. We do not invent that print here.

get

store.get(namespace, "1")
store.get(namespace, "2")

namespace = ("user", "u2")
store.get(namespace, "1")
store.get(namespace, "2")

search

items = store.search(namespace)

for item in items:
    print(item)

get needs the key. search returns the items in that namespace.

904

Semantic Search

There is one situation both get and search cannot help. get gets a single item if we have the key. search gets all. Like we are using a chatbot, and we talk about the travel plan. The memory has all the details, like name, travel, programming. If we bring all the data from memory and give it to the LLM, the LLM might get confused. The best situation is to retrieve only the data that is related to travel. What we need is semantic searching. We fetch them based on meaning. We use the same search function. The table below is that gap.

Bring all Search by meaning
Name, travel, and programming all go into the prompt. Only the travel facts come back for a travel question.
The LLM might get confused. The LLM sees the related slice.
905

Search with Embeddings

We send the embedding model to the store so it can store the data for search by meaning. This is a very important concept. We still call search. Now we pass a query and a limit. limit is 3. We loop the items and print them. We do not invent those three hits. The working constructor takes index, with embed set to the embedding model. The notes had embedding as a direct argument. That name is not the store API.

InMemoryStore with embeddings

from langchain_community.embeddings import OpenAIEmbeddings
from dotenv import load_dotenv
from langgraph.store.memory import InMemoryStore

load_dotenv()

embedding = OpenAIEmbeddings()

store = InMemoryStore(index={"embed": embedding})
namespace = ("user", "u1")
store.put(namespace, "1", {"data": "hello i am bishal"})
store.put(namespace, "2", {"data": "hello i am kiran"})
store.put(namespace, "3", {"data": "hello i am bishal"})
store.put(namespace, "4", {"data": "hello i am kiran"})
store.put(namespace, "5", {"data": "hello i am bishal"})
store.put(namespace, "6", {"data": "hello i am kiran"})
store.put(namespace, "7", {"data": "hello i am bishal"})
store.put(namespace, "8", {"data": "hello i am kiran"})
store.put(namespace, "9", {"data": "hello i am bishal"})
store.put(namespace, "10", {"data": "hello i am kiran"})

items = store.search(namespace, query="what is memory learning", limit=3)

for item in items:
    print(item)

Same search method. query ranks by meaning. limit keeps three.

Day 68 takeaways

Day 68 takeaways

  • Short term memory is one thread. Long term memory is a store across threads.
  • As the user asks, extract details and persist them in a db so later answers can use them.
  • BaseStore is the abstract class. InMemoryStore is RAM. PostgresStore and RedisStore are production grade.
  • put takes namespace, key, and value. Namespace is like a folder. get needs the exact key. search can return all items.
  • Semantic search uses the same search method with a query, so the LLM sees related facts, not every fact.
  • Chat can read existing memory into the system prompt with short term memory. Remember writes new memories. Then merge both nodes.
  • Dedup matters. Tell the model what the previous memory already contains. Do not leave the store in RAM for a real product.
