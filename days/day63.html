Outdated Knowledge

Why is RAG important? Outdated knowledge. Every LLM has a knowledge cutoff date. The training is completed on a particular date. By definition, if an LLM is ready on 31 August 2026, and today we ask about something after that, it will not be able to answer from its own weights. You might think ChatGPT replies with the latest answer. Behind it, it calls web search and then answers. That is extra knowledge at ask time, not new training. The table below is that split.

From weights At ask time
Training stopped on a date, like 31 August 2026. ChatGPT can search the web, then answer.
Facts after that date are missing. The extra knowledge is retrieve, not new training.
826

Privacy

The second biggest problem RAG helps with is privacy. GPT can answer many public things. If we ask a personal question, like our salary, it will not be able to answer. That fact is not in public training. If the salary lives in our own PDF, RAG can retrieve that private sheet and answer from it, instead of guessing.

827

Hallucination

The third problem is hallucination. The model gives false information, with confidence. It is still a big problem. RAG helps with this. We ground the answer in retrieved chunks. The biggest use cases of RAG sit in these three: cutoff, privacy, and hallucination.

Cutoff

Training stopped on a date. New facts need retrieve.

Privacy

Personal files are not in GPT. RAG can read yours.

Hallucination

Answer from chunks, not from a confident guess.

In Context Learning

RAG works on a simple principle, like in context learning. We give context to the LLM. The LLM gets the query and the context. We give a prompt. The LLM also has parametric knowledge, which is what it learned in training.

Suppose we have an expense sheet. We ask the LLM about it, but parametric knowledge does not have that sheet. What we do is give the expense sheet, the whole sheet, in the prompt. Then the model can answer from that context. The picture below is query plus context.

829

Context Filtering

The only problem is we cannot give the whole context every time. It has a context size. If the folder has 100 books, that information will cross the context size. A second example is a code base. We do not give the whole repo every time we ask. We only give the context that is required. Context filtering is the most important part. In context learning plus context filtering. That pair is RAG retrieve.

830

PDF to Vector Store

We take the PDF, chunk it, then embed each chunk. Embedding converts the chunk into a vector. That vector captures the semantic meaning of the chunk. We save those embeddings in a vector store, for example FAISS or Chroma. The steps below are that index path.

Build the store

  1. PDF Upload the file you want to talk with.
  2. Chunk Cut the PDF into smaller pieces.
  3. Embed Turn each chunk into a vector of meaning.
  4. Store Save the vector and the real chunk text, in FAISS or Chroma.
831

Query to Answer

The user asks a query. A retriever converts the question into an embedding. It compares that query embedding with the vector store. That is semantic search. It might pick chunk 1, 4, and 5. In the vector store we store the embedding and its real data as well. Then the prompt is the query plus that context, all three chunks we got. Then the LLM answers. RAG as a Tool in LangGraph

To implement RAG there are multiple ways. We will define it as a tool. That is the best way of doing it. Always try to do RAG as a tool. Then the same chat_node can decide. Normal chat, a calculator, MCP weather, or retrieve from the PDF. We do not need a second graph. We keep START, chat_node, tools_condition, and the loop back from tools. RAG sits in the ToolNode with the other tools. The retrieve tool lives in the live app. Open that app and upload a PDF to see it run.

Day 63 takeaways

Day 63 takeaways

  • This chatbot is multi utility. Normal chat, tools, MCP, and RAG on a PDF.
  • RAG matters for cutoff dates, private files like a salary sheet, and hallucination.
  • ChatGPT can look new because it searches the web, not because training restarted.
  • RAG is in context learning plus context filtering. Do not paste 100 books every turn.
  • Index path is PDF, chunk, embed, vector store. FAISS and Chroma are examples.
  • Ask path is query, retriever, semantic search, prompt with those chunks, then LLM.
  • In LangGraph, treat RAG as a tool. Keep the same loop. Always try RAG as a tool.
