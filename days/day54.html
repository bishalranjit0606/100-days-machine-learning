Day 54

Chatbot in LangGraph

A user talks to a chatbot that remembers earlier turns. The graph is simple. The state is a message list. Memory and persistence come from a reducer, a while loop, and a thread.

705

Memory and a Chatbot

Today we learn advanced LangGraph ideas: memory and persistence. The user task is a chatbot that remembers previous memory. You type. The bot answers. Next turn, it still knows what you said before.

The chatbot is a more simple workflow. It is a sequential workflow. The most important thing is the state of this workflow. That state is the message list.

706

A Simple Sequential Chat

At the high level the path is START, then the chat node, then END. One line. The diagram below is that simple shape. Later we add a tool on the same graph. The chat idea stays sequential.

707

The State Is a Message List

We do not write our own TypedDict for this chatbot. LangGraph gives us MessagesState. That state is a list of messages. Each invoke adds new messages. A reducer is already on that list, so old turns stay. New turns append. That is how the bot can see the full chat.

Imports and MessagesState

import requests
from dotenv import load_dotenv
from langchain_openrouter import ChatOpenRouter
from langchain_core.messages import HumanMessage, SystemMessage
from langchain_core.tools import tool
from langgraph.graph import StateGraph, START
from langgraph.graph import MessagesState
from langgraph.prebuilt import ToolNode, tools_condition
from langgraph.checkpoint.memory import InMemorySaver

load_dotenv()

MessagesState is the state of the whole graph. The key is messages. Keep all the data with that reducer. Do not replace the list yourself.

708

Model and Timestamp Tool

One ChatOpenRouter model serves the chat. We also give it a tool. convert_timestamp takes a Unix timestamp and a timezone. It calls epochcalc and returns JSON. bind_tools lets the model choose that tool when a date conversion is needed.

Model and tool

model = ChatOpenRouter(
    model="openai/gpt-4o-mini",
    temperature=0
)

@tool
def convert_timestamp(
    timestamp: int,
    timezone: str
) -> dict:
    """
    Convert a Unix timestamp to a readable date and time
    for the requested timezone.
    """
    url = "https://epochcalc.com/api/v1/convert_timestamp"
    params = {
        "timestamp": timestamp,
        "timezone": timezone
    }
    response = requests.get(
        url,
        params=params,
        timeout=10
    )
    response.raise_for_status()
    return response.json()

tools = [convert_timestamp]
model_with_tools = model.bind_tools(tools)

The JSON from that API is live data. We do not paste a fake result here. Run the tool to see the real response.

709

The Chat Node

chat reads MessagesState. It puts a system message first, then every message already in state. It invokes the model with tools. It returns a one item list with the new AI message. The reducer appends that message to the list.

chat

def chat(state: MessagesState):
    system_message = SystemMessage(
        content="You are a helpful assistant."
    )
    messages = [
        system_message,
        *state["messages"]
    ]
    response = model_with_tools.invoke(messages)
    return {
        "messages": [response]
    }

The star before state messages unpacks the old list into this new list. The system line is added on every call, not stored as extra history by us.

710

Tools Condition and Edges

We add a chat node and a tools node. START always goes to chat. After chat, tools_condition looks at the last message. If the model asked for a tool, we go to tools. ToolNode runs convert_timestamp. Then we go back to chat with the tool result. If the model did not ask for a tool, we go to END. The diagram below is that graph.

Graph

builder = StateGraph(MessagesState)

builder.add_node("chat", chat)
builder.add_node("tools", ToolNode(tools))

builder.add_edge(START, "chat")

builder.add_conditional_edges(
    "chat",
    tools_condition
)

builder.add_edge("tools", "chat")

tools_condition is prebuilt. We do not write our own router for this split. It maps a tool request to the tools node, and a normal answer to END.

711

Memory and a Thread

Persistence uses a thread to remember the last previous data. InMemorySaver is the checkpointer. We compile the graph with that checkpointer. config sets thread_id to user_123. Every invoke that uses the same thread_id loads the saved message list, then writes it back. The picture below is one thread holding the growing chat.

Checkpointer and thread

memory = InMemorySaver()

graph = builder.compile(
    checkpointer=memory
)

config = {
    "configurable": {
        "thread_id": "user_123"
    }
}

Same thread_id means same memory. A different thread_id would be a different chat. InMemorySaver keeps this in process memory while the program runs.

712

The Chat Loop

For continuous chat we use a while loop. Each pass reads input. exit or quit ends the program. Otherwise we invoke with a HumanMessage and the same config. The last item in result messages is the AI reply. We print that content. The next loop still uses thread_id user_123, so previous turns are still there.

while True chatbot

while True:
    user_input = input("You: ")

    if user_input.lower() in [
        "exit",
        "quit"
    ]:
        print("Chat ended.")
        break

    result = graph.invoke(
        {
            "messages": [
                HumanMessage(
                    content=user_input
                )
            ]
        },
        config=config
    )

    response = result["messages"][-1]
    print("AI:", response.content)

The AI text comes from the model. We do not paste a fake chat here. Run the loop locally. Type exit or quit when you want to stop.

713

Reducer, Loop, and Thread

Three pieces make the chatbot remember. The cards below are that set. Miss one, and the bot forgets or the chat stops after one turn.

Reducer

For keeping all the data. MessagesState appends each new message. Old turns stay in the list.

While loop

For continuous chat. Each pass is one user line, then one invoke, then one AI print.

Thread

For persistence. The same thread_id loads the last previous data on the next invoke.

714

Day 54 takeaways

Day 54 takeaways

  • A LangGraph chatbot is a simple sequential workflow: START, chat, END.
  • The most important thing is the state. That state is a message list, MessagesState.
  • bind_tools plus ToolNode and tools_condition let chat call convert_timestamp, then return to chat.
  • For keeping all the data, use a reducer. MessagesState already appends messages.
  • For continuous chat, use a while loop.
  • For persistence, use a thread_id with InMemorySaver so the graph remembers previous turns.
