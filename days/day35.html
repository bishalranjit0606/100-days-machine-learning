Day 35

YouTube Chatbot with RAG

Turn a long video transcript into a question answering bot with LangChain, FAISS, and one LCEL chain.

437

Why a YouTube Chatbot

Some videos are two or three hours long. Watching the whole thing just to find one answer wastes time.

A YouTube chatbot lets you ask the video questions. The bot answers from the transcript, not from guesswork.

Topic check

Does this video talk about AI?

Summary

Summarize the video in bullet points.

Doubt clearing

Ask about a part you did not understand.

The final product can be a Chrome extension that opens on top of YouTube, or a Streamlit site. Today we focus on the RAG functionality, not the UI.

438

Plan of Action

We build this with the same RAG architecture from Day 34. First index the transcript. Then retrieve, augment, and generate.

YouTube RAG path

  1. Transcript Fetch captions for the video.
  2. Split Cut text into overlapping chunks.
  3. Embed and store Vectors go into FAISS.
  4. Retrieve Query becomes a vector. Top chunks return.
  5. Augment Join query plus context in a prompt.
  6. Generate LLM answers from that context.

You can load transcripts with a YouTube document loader, but that path can be buggy. We use the YouTube Transcript API directly instead.

Fetch the Transcript

Indexing starts with the raw transcript. You pass a video id, ask for English captions, then join every chunk into one long string.

YouTube transcript fetch

from youtube_transcript_api import (
    YouTubeTranscriptApi,
    TranscriptsDisabled,
)

video_id = "Fbr_Solax1w"

try:
    ytt_api = YouTubeTranscriptApi()
    transcript_list = ytt_api.fetch(
        video_id,
        languages=["en"],
    )
    transcript = " ".join(
        chunk.text for chunk in transcript_list
    )
    print(transcript[:500], "...")
except TranscriptsDisabled:
    print("Transcript is disabled for this video.")

What you get

One long string of spoken text from the video.
Exact words depend on the captions for that video_id.
If captions are off, you get the disabled message.

The video id is the part after v= in a YouTube URL.

441

Split Into Chunks

A full transcript is too long to embed as one piece. We split it with overlap so meaning near a cut line is less likely to get lost.

RecursiveCharacterTextSplitter

from langchain_text_splitters import (
    RecursiveCharacterTextSplitter,
)

text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=1000,
    chunk_overlap=200,
    length_function=len,
)

chunks = text_splitter.create_documents([transcript])
print(len(chunks))
print(chunks[0].page_content[:200])

What you get

A list of Document objects.
len(chunks) is the number of pieces
(exact count depends on transcript length).
Each Document has page_content text.

chunk_size=1000 and chunk_overlap=200 are a solid starting point. Tune them later if answers miss context.

442

Embed and Store in FAISS

Next we turn each chunk into a vector and store it in FAISS. Here we use a free Hugging Face sentence transformer so embedding does not need a paid API.

HuggingFaceEmbeddings plus FAISS

from langchain_huggingface import HuggingFaceEmbeddings
from langchain_community.vectorstores import FAISS

embedding = HuggingFaceEmbeddings(
    model_name="sentence-transformers/all-MiniLM-L6-v2"
)

vectorstore = FAISS.from_documents(chunks, embedding)

# Optional checks while you explore:
# vectorstore.index_to_docstore_id
# vectorstore.get_by_ids(["some-doc-id"])

What you get

A FAISS vector store holding one embedding
per chunk. Indexing for this video is done.

The MiniLM sentence model is small and fast. First run may download the model weights.

443

Build the Retriever

The retriever wraps the vector store. You send a question. It embeds the question and returns the most similar chunks.

Similarity retriever

retriever = vectorstore.as_retriever(
    search_type="similarity",
    search_kwargs={"k": 4},
)

docs = retriever.invoke(
    "what is the purpose of this video"
)
for i, doc in enumerate(docs, start=1):
    print(i, doc.page_content[:120], "...")

What you get

Up to 4 Document objects.
Each page_content is a transcript chunk
that is close in meaning to the query.
Exact text depends on the video.

k=4 means four neighbors. Raise k for more context. Lower k for a tighter prompt.

444

Prompt, LLM, and Manual RAG

Before one big chain, run the ask path by hand. Build a grounded prompt, fetch context, join page content only, then call the LLM.

We tell the model to answer only from the transcript. If the answer is missing, it should say it does not know.

Manual retrieve, augment, generate

import os
from langchain_openai import ChatOpenAI
from langchain_core.prompts import PromptTemplate

llm = ChatOpenAI(
    model="openrouter/free",
    temperature=0.3,
    base_url="https://openrouter.ai/api/v1",
    api_key=os.environ["OPENAI_API_KEY"],
)

prompt = PromptTemplate(
    template="""You are a helpful assistant.
Answer only from the provided transcript content.
If the answer is not present in the transcript,
say "I don't know."

Context:
{context}

Question:
{question}
""",
    input_variables=["context", "question"],
)

question = "What is this video about?"
retrieved_docs = vectorstore.similarity_search(
    question, k=3
)

# Send page_content only, not full Document objects.
context_text = "\n\n".join(
    doc.page_content for doc in retrieved_docs
)

final_prompt = prompt.invoke({
    "context": context_text,
    "question": question,
})

answer = llm.invoke(final_prompt)
print(answer.content)

What you get

A short answer grounded in the retrieved chunks,
or "I don't know." if the transcript has no match.
Exact wording changes with the model and video.

Joining page_content keeps the prompt small. Full Document metadata is usually not needed for the LLM.

One Chain With Parallel Inputs

The steps work, but they are separate. We want one invoke that runs the full path.

The prompt needs two inputs: context and question. The question can pass straight through. Context must come from the retriever, then a small format function.

Parallel then generate

  1. Question in One string invoke.
  2. Parallel context branch and question branch.
  3. Prompt Fills context and question.
  4. LLM plus parser Returns plain answer text.

RunnableParallel plus main chain

from langchain_core.runnables import (
    RunnableParallel,
    RunnablePassthrough,
    RunnableLambda,
)
from langchain_core.output_parsers import StrOutputParser

def format_docs(retrieved_docs):
    return "\n\n".join(
        doc.page_content for doc in retrieved_docs
    )

parallel_chain = RunnableParallel(
    {
        "context": retriever | RunnableLambda(format_docs),
        "question": RunnablePassthrough(),
    }
)

# Check the dict shape first:
# parallel_chain.invoke("what is the purpose of this video")

parser = StrOutputParser()

main_chain = (
    parallel_chain
    | prompt
    | RunnableLambda(lambda x: x.to_messages()[0])
    | llm
    | parser
)

print(main_chain.invoke("what is a2a"))

What you get

parallel_chain returns a dict like:
{"context": "...joined chunks...", "question": "..."}

main_chain returns one answer string.
If a2a is not in the transcript, expect "I don't know."

The RunnableLambda after prompt turns the prompt value into a chat message for ChatOpenAI. The parser keeps only the text string at the end.

Improvements You Can Make Later

The core RAG path works. These upgrades make it stronger for real users.

Area What to improve
UI Streamlit site or a Chrome plugin on top of YouTube.
Evaluation RAGAS metrics like faithfulness, answer relevance, context precision, and context recall. LangSmith for tracing the pipeline.
Indexing Auto captions can be wrong or in another language. Splitting can struggle when the transcript includes code. A simple vector store may not be enough later.
Retrieval Pre retrieval: query rewrite, multi query, domain routing. During retrieval: MMR, hybrid search, reranking. Post retrieval: contextual compression.
Augmentation Better prompt templates, answer grounding, and context window optimization.
Generation Answers with citations, plus guardrails.
System design Multimodal inputs, agentic flows, and memory based chat.

You already met several retrieval ideas on Day 33. Evaluation and UI are the next practical layer once the chain is stable.
