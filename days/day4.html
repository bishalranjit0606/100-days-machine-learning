Batch Machine Learning

19

Batch vs Online ML in Production

This is another way to group machine learning: how the model is trained in production.

We care about this because most real projects end on a server. The training style affects cost, speed, and how fresh the model stays.

Two main styles: batch learning (also called offline learning) and online learning.

20

What Is Batch Learning

Batch learning is also known as offline ML.

You use all available data to train the model in one go. There is no incremental training during normal operation.

Data is often huge. Training with all data directly on the live server is expensive. That is why teams usually train on a separate offline machine, then move the finished model to the server.

21

Train Offline, Deploy to the Server

The usual batch flow:

Batch workflow.

  1. Data Collect full dataset.
  2. Model Train offline.
  3. Test Check quality.
  4. Server Deploy model.

Training stays off the production server. Only the trained model runs live.

22

Static Models and Retraining

Problem with batch models: knowledge stays static. What the model learned at training time does not change until you retrain.

Example: Netflix keeps adding movies. An old model that never updates will get worse at recommendations.

Fix: retrain on a schedule. Use new data plus the previous model, train again, and deploy the updated model. Teams often retrain daily or weekly.

Batch learning in practice: train on a large offline dataset, deploy to the server, and repeat on a cycle.

23

Disadvantages of Batch Learning

  • Scale limits: very large data may not fit your tools or hardware. Training can fail.
  • Connectivity: without a good link, moving data or a new model to the server is hard.
  • Freshness: on social feeds, batch updates can feel slow. New posts might show up only after the next batch run (for example once every 24 hours).

Day 4 takeaways

  • Batch = train on all data offline, then deploy.
  • Models go stale; retrain on a schedule.
  • Watch data size, hardware, and how fresh users need results.
