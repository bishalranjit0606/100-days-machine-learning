Path and Query Parameters

Fetch one patient with a path parameter, send the right status code, then sort with query parameters.

578

One Patient, Not All

On the last day, a route like /view or /patients returned every patient in the JSON file. What if we only want the second person?

We can call a path like /view/2. That 2 is dynamic. It can change. The route then shows that one record. This is a path parameter. It is very useful on GET, update, and delete.

The chain below is all patients versus one patient.

All records, then one id

  1. All patients /patients returns the whole JSON file.
  2. Dynamic piece The last part of the path can change, like 2 or P001.
  3. One patient The API returns only that person's data.
579

A Path Parameter in Code

In FastAPI the dynamic piece sits in curly braces. /patients/{patient_id} is the route. The function argument patient_id is a string. We load the JSON file. If that id is a key, we return that patient. If not, we return a message.

main.py

import json
from fastapi import FastAPI

def load_patients():
    with open("patients.json", "r") as f:
        return json.load(f)

app = FastAPI()

@app.get("/patients/{patient_id}")
def view_patient(patient_id: str):
    data = load_patients()

    if patient_id in data:
        return data[patient_id]
    else:
        return {"message": "Patient not found"}

What GET returns

GET /patients/P001
returns that patient's object from the JSON file.

GET /patients/P003
{"message": "Patient not found"}

P001 and P003 are sample ids. Use an id that exists in your file to see a record.

Path Makes the Docs Better

We can make the endpoint easier for a client. Import Path from FastAPI and attach it to the argument. Path adds metadata and data validation: title, description, example, ge, gt, le, min length, max length, regex, and more.

Three dots ... mean the path parameter is required. That is a good habit. Always mark a path id as required.

Path is required

import json
from fastapi import FastAPI, Path

def load_patients():
    with open("patients.json", "r") as f:
        return json.load(f)

app = FastAPI()

@app.get("/patients/{patient_id}")
def view_patient(
    patient_id: str = Path(
        ...,
        description="The ID of the patient to view",
        example="P001"
    )
):
    data = load_patients()

    if patient_id in data:
        return data[patient_id]
    else:
        return {"message": "Patient not found"}

What changes for the client

The route still reads one patient.
The docs now show a description and an example id.
Three dots mean patient_id must be in the path.

HTTP Status Codes

An HTTP status code is a three digit number. A web server, like FastAPI, sends it to show the result of a client's request. The client might be a browser or another API.

The client sends a request. The server sends a response. The status code is part of that response. It tells you if the work succeeded or failed.

Request and response

  1. Client Browser or API consumer sends a request.
  2. Server FastAPI handles the route.
  3. Status code A three digit code comes back with the response.

The first digit is the family. The four cards below are those families. Then the table lists the codes we will use.

2xx

Success. The request worked.

3xx

Another step is needed, often a new URL.

4xx

Client side error. We made a mistake in the request.

5xx

Server side error. The server failed.

Code Meaning
200 Success.
201 A resource was created.
204 No data returned, like after a delete.
400 Bad request. The request is invalid.
401 Unauthorized. Auth is invalid.
404 The resource does not exist.

A Missing Patient Still Returns 200

There is a problem in the code we just wrote. Say the file has two patients and the client asks for P003. We send the error message, but the status code is still 200. 200 means success. A missing resource should be 404.

The table below is that mismatch.

What we send What it should be
Message Patient not found, status 200. Same idea, but status 404, because the resource does not exist.
583

Raise HTTPException

HTTPException is a special built in exception in FastAPI. It returns a custom HTTP error response. If the id is missing, we raise 404 with a detail message instead of returning a normal 200 body.

Raise 404

import json
from fastapi import FastAPI, Path, HTTPException

def load_patients():
    with open("patients.json", "r") as f:
        return json.load(f)

app = FastAPI()

@app.get("/patients/{patient_id}")
def view_patient(
    patient_id: str = Path(
        ...,
        description="The ID of the patient to view",
        examples=["P001"]
    )
):
    data = load_patients()

    if patient_id in data:
        return data[patient_id]

    raise HTTPException(
        status_code=404,
        detail="Patient not found"
    )

What GET returns

GET /patients/P001
status 200, the patient object.

GET /patients/P003
status 404
{"detail": "Patient not found"}

Query Parameters

In the last lesson we created an endpoint that lists patients. We also want to give the user a choice: get that list sorted, in ascending or descending order, on a field such as height, BMI, or age.

The client can send extra values at the end of the URL. Those values can be optional. They are for filtering, searching, pagination, and sorting. The endpoint path itself does not change.

A query string starts with ?. Each piece is a key value pair, written key=value. More than one pair is joined with &. One example is city=kathmandu.

The URL below shows those parts.

Path stays. Query is extra.

  1. Path /sort is the route. It does not change.
  2. Question mark ? starts the query string.
  3. Pairs sort_by=age and order=desc, joined by &.

Path parameters sit inside the URL path. Query parameters sit after the question mark. The table below is that split.

Path parameter Query parameter
Inside the path, like /patients/P001. After ?, like /sort?sort_by=age.
Often required. Names one resource. Often optional. Filters, searches, sorts, pages.
585

Sort Patients with Query

We add GET /sort. sort_by is required. It must be height, age, or weight. order is optional and defaults to asc. If order is desc, we reverse the list. If sort_by is not one of those three fields, we raise 400, a bad request.

This uses the patient objects inside the JSON file. Those objects need height, age, and weight keys for this sort to run.

GET /sort

from fastapi import Query

@app.get("/sort")
def sort_patients(
    sort_by: str = Query(
        ...,
        description="Sort patients by height or age or weight",
        examples=["height", "age", "weight"]
    ),
    order: str = Query(
        "asc",
        description="Sort order (asc or desc)",
        examples=["asc", "desc"]
    )
):
    data = load_patients()

    if sort_by == "height":
        return sorted(
            data.values(),
            key=lambda x: x["height"],
            reverse=order == "desc"
        )
    elif sort_by == "age":
        return sorted(
            data.values(),
            key=lambda x: x["age"],
            reverse=order == "desc"
        )
    elif sort_by == "weight":
        return sorted(
            data.values(),
            key=lambda x: x["weight"],
            reverse=order == "desc"
        )
    else:
        raise HTTPException(
            status_code=400,
            detail="Invalid sort by parameter"
        )

What GET returns

GET /sort?sort_by=age&order=asc
patient objects, lowest age first.

GET /sort?sort_by=age&order=desc
patient objects, highest age first.

GET /sort?sort_by=city
status 400
{"detail": "Invalid sort by parameter"}

Import Query next to Path and HTTPException. sort_by is required because of the three dots. order defaults to asc.

Day 42 takeaways

Day 42 takeaways

  • A path parameter is the dynamic piece of the URL. /patients/{patient_id} returns one patient. Use it on GET, update, and delete.
  • Path(...) marks the id as required and can add description, example, and validation such as min length or ge.
  • A status code is a three digit result. 2xx is success. 3xx needs another step. 4xx is a client mistake. 5xx is a server failure.
  • 200 is success. 201 is created. 204 is no body after a delete. 400 is a bad request. 401 is unauthorized. 404 means the resource does not exist.
  • Returning Patient not found with 200 is wrong. Raise HTTPException with status 404.
  • Query parameters start with ?. Pairs look like key=value. Join them with &. They filter, search, sort, and page without changing the path.
  • GET /sort uses Query for sort_by and order. A bad sort_by raises 400.
