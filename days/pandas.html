What Pandas Is

Pandas is a Python library for working with structured data.

Structured data usually looks like a table with rows and columns.

You mainly use Pandas to:

  • Read datasets.
  • View and understand datasets.
  • Select rows and columns.
  • Filter data.
  • Sort data.
  • Add, edit, or remove data.
  • Clean incorrect or missing values.
  • Group and summarize data.
  • Combine multiple datasets.
  • Perform basic exploratory data analysis.
  • Export processed data.

You do not need to memorize every Pandas function.

You need to understand:

  • What your dataset contains.
  • What result you want.
  • Which rows or columns should be used.
  • What conditions should be applied.
  • How the result should be summarized or transformed.

Then you can explain the task clearly to an AI.

Missing Values

A missing value means data is unavailable. Pandas often shows these as NaN or None.

Missing values can break calculations, skew averages, hurt models, remove rows from analysis, or reveal collection problems.

df.isna().sum()

Removing missing values

Remove rows when the missing field is essential, only a few rows are affected, or filling would mislead.

clean_df = df.dropna(subset=["salary"])

Filling missing values

Common choices: median for many numeric columns, mode for categories, Unknown for text.

df["salary"] = df["salary"].fillna(df["salary"].median())
df["city"] = df["city"].fillna("Unknown")

Mean, median, or mode

  • Mean is the average. Use it when numeric data is balanced.
  • Median is the middle value after sorting. Use it when there are unusually high or low values.
  • Mode is the most common value. Use it for categories or repeated values.
salary_mean = df["salary"].mean()
salary_median = df["salary"].median()
city_mode = df["city"].mode()[0]

Concat and Merge

Concatenating DataFrames

Concatenation places DataFrames above or beside each other. Most often you stack rows from similar files.

combined = pd.concat(
    [january_df, february_df],
    ignore_index=True
)

Merging DataFrames

Merging combines datasets using a shared column. It is like looking up related information from another table.

merged = pd.merge(
    employees_df,
    salaries_df,
    on="employee_id",
    how="left"
)

Merge types

  • Inner merge keeps only matching records.
  • Left merge keeps every record from the first DataFrame.
  • Right merge keeps every record from the second DataFrame.
  • Outer merge keeps every record from both DataFrames.

Use inner when only complete matches matter. Use left when your first table is the main dataset. Use outer when you want to detect missing matches from either side.

Common Mistakes

Incorrect column name

Column names are case sensitive. df["Salary"] fails if the real name is salary.

print(df.columns.tolist())

Numbers stored as text

Values like "50000", "NPR 50,000", or "60k" can break math.

df["salary"] = (
    df["salary"]
    .astype(str)
    .str.replace(",", "", regex=False)
    .str.replace("NPR", "", regex=False)
    .str.strip()
)
df["salary"] = pd.to_numeric(df["salary"], errors="coerce")

Dates stored as text

Text dates may sort alphabetically instead of by time.

df["date"] = pd.to_datetime(df["date"], errors="coerce")

Missing parentheses in filters

Wrong:

df[df["department"] == "IT" & df["salary"] > 50000]

Correct:

df[
    (df["department"] == "IT") &
    (df["salary"] > 50000)
]

Using and instead of &

In Pandas filters use & and |, not Python and / or.

Changing the original by accident

Prefer a new variable when cleaning.

clean_df = df.dropna(subset=["salary"])

Merge creating extra rows

A merge can multiply rows when the merge key is duplicated.

print(employees_df["employee_id"].duplicated().sum())
print(salaries_df["employee_id"].duplicated().sum())

Practical Workflow

For most datasets, follow this order.

# 1 Load
df = pd.read_csv("data.csv")

# 2 Preview
df.head()

# 3 Inspect
print(df.shape)
df.info()

# 4 Check quality
print(df.isna().sum())
print(df.duplicated().sum())

# 5 Fix column names
df.columns = (
    df.columns
    .str.strip()
    .str.lower()
    .str.replace(" ", "_")
)

# 6 Fix data types
df["salary"] = pd.to_numeric(df["salary"], errors="coerce")

# 7 Clean missing values and duplicates
df = df.drop_duplicates()
df["salary"] = df["salary"].fillna(df["salary"].median())

# 8 Filter and transform
result = df[df["experience"] >= 3].copy()
result["annual_salary"] = result["salary"] * 12

# 9 Group or summarize
summary = (
    result.groupby("department")
    .agg(
        employee_count=("name", "count"),
        average_salary=("salary", "mean")
    )
    .reset_index()
)

# 10 Export
summary.to_csv("department_summary.csv", index=False)

How to Frame a Machine Learning Problem

Turn a business goal into a clear ML problem before you write any code.

139

The Netflix Business Problem

Today we learn how to convert a business problem into a machine learning problem.

Suppose you are a data scientist at Netflix. Leadership asks: how do we increase revenue?

Three business levers come to mind:

  • Marketing: bring more new subscribers.
  • Pricing: get existing customers to pay more.
  • Retention: stop existing customers from leaving.

All three can grow revenue. As data scientists we often focus on the third: keep people subscribed.

That is step one in framing. Start with the business goal. Then ask which part of it ML can help with.

140

From Revenue to Churn Rate

Instead of saying "increase revenue" in the meeting room, we narrow the goal to: decrease churn rate.

Churn rate is the share of subscribers who cancel in a period.

Example: Netflix has 100 subscribers and 2 leave. Churn rate is 2%.

In real life Netflix churn is around 4%. The team might set a target: bring it down to 3.75%.

That is a mathematical problem we can track. We leave the meeting with a clear number, not a vague wish.

Business problem: increase revenue. ML framing: reduce churn from 4% to 3.75%.

141

See the End Product First

Look at the big picture. What is the end product?

We do not need a model that predicts the churn rate number itself. Churn rate is a company level metric.

What we need: find if a customer is about to leave.

Once we know that, the product can act:

  • Send a 50% discount offer.
  • Fix a bad UI or help with no internet issues.
  • Reach out immediately when someone shows signs of leaving.

Good framing means you know what the model will do in production, not just what it will predict on paper.

142

Classification and Regression

Now we pick the type of ML problem.

Step 1: Is this person leaving or staying? That is a yes or no question.

Use supervised learning classification. Output: leave or stay.

Step 2: How strong is the feeling to leave? Example: 90% likely to cancel.

That is a number, not yes or no. Use regression to estimate willingness to leave.

Why both? A higher score can trigger a bigger discount. Someone at 90% might get more than someone at 40%.

A real churn solution often uses both models: classification to flag at risk users, regression to rank how urgent the case is.

143

Getting the Right Data

Getting data is one of the most important parts of framing.

Ask: what signals show that someone might leave? Examples:

  • Watch time dropping.
  • Search but did not find what they wanted.
  • Content left in the middle of a show.
  • Clicks on recommendations and the order they clicked.

You rarely pull this data alone. Talk to the data engineer.

They take live app data from OLTP systems and build a data warehouse where you can train models.

If the data you need does not exist yet, framing is not finished. No data means no model.

144

Define Your Metrics

Before you build, decide how you will measure success.

Metrics tell you if what you are doing is good or bad.

For churn you might track whether churn rate actually dropped after the model went live.

Pick metrics that tie back to the business goal. If leadership cares about revenue, show how the model affects revenue, not only model accuracy.

145

Online or Batch Learning

Another framing choice: will the model run in batch or online mode?

A common pipeline looks like this:

OLTP → data warehouse → model → trained model.

Batch learning: retrain on a schedule (daily or weekly). Good when patterns change slowly.

Online learning: update the model as new events arrive. Good when behavior shifts fast.

For churn, many teams start with batch: pull warehouse data, train overnight, score users the next day. Online can come later if you need faster reactions.

146

Check Your Assumptions

The last step in framing: check your assumptions before you invest months of work.

  • Is the data available? Can you actually get watch time, searches, and cancel labels?
  • Does one model fit all regions? Users in different countries may behave differently. You might need separate models by geography.
  • Can the product act on predictions? A discount offer only helps if the system can send it in time.

Catching a wrong assumption early saves the whole project.

read_csv Basics

Start with the two imports you already know:

import numpy as np
import pandas as pd

Load a CSV from a local file:

df = pd.read_csv("file_name.csv")
df

You can also pass a URL instead of a file path. Pandas will download and read it.

url = "https://example.com/data.csv"
df = pd.read_csv(url)
df.head()

df is a DataFrame: a table with rows and columns. We will now look at many read_csv parameters to control how the file is loaded.

150

index_col and header

index_col: use a column as the row index instead of the auto generated 0, 1, 2… index:

df = pd.read_csv("file_name.csv", index_col="col_name")

This removes the extra index column pandas would create by default.

header: pick which row becomes the column names:

df = pd.read_csv("test.csv", header=1)

header=0 is the default (first row). header=1 means the second row becomes your header row.

151

usecols and squeeze

usecols: load only the columns you need:

df = pd.read_csv("test.csv", usecols=["enrolled_id", "gender"])

This saves memory when the file has many columns but you only need a few.

squeeze: when you load one column, turn the DataFrame into a Series:

s = pd.read_csv("test.csv", usecols=["enrolled_id"], squeeze=True)

A Series is a single column of data with an index. In newer pandas versions you can also call .squeeze() on a one column DataFrame.

152

skiprows and nrows

skiprows: skip specific rows when reading:

df = pd.read_csv("test.csv", skiprows=[0, 5])

This skips row 0 and row 5. Useful when the file has junk rows at the top or broken rows in the middle.

nrows: read only the first N rows:

df = pd.read_csv("test.csv", nrows=100)

Good for quick previews on very large files without loading everything.

153

encoding and Bad Lines

encoding: some files use a different text encoding. Special characters may break unless you set it:

df = pd.read_csv("test.csv", encoding="latin-1")

Try latin-1 or cp1252 when you see strange symbols or read errors.

Skip bad lines: sometimes a row is corrupt. Example: rows 5, 6, or 7 have wrong data.

df = pd.read_csv("test.csv", on_bad_lines="skip")

If a row expects 8 columns but has 9 values, pandas skips that row instead of crashing. Older pandas used error_bad_lines=False. Newer versions use on_bad_lines="skip".

154

dtype and parse_dates

dtype: set column types while loading. This helps save memory:

df = pd.read_csv("test.csv", dtype={"target": int})

Without this, pandas may load numbers as floats or objects. Telling it the type upfront keeps the DataFrame smaller.

parse_dates: dates often arrive as plain strings. Convert them on load:

df = pd.read_csv("test.csv", parse_dates=["date"])

After this, the date column is a real datetime type. You can filter, sort, and plot dates properly.

155

converters and na_values

converters: very powerful in pandas. Run your own function on each value in a column.

Example: instead of the full name Bishal Ranjitkar, store a short code br:

def rename(name):
    if name == "bishal ranjitkar":
        return "br"
    else:
        return "norbr"

df = pd.read_csv("test.csv", converters={"team1": rename})

na_values: tell pandas which values should count as missing (NaN):

df = pd.read_csv("test.csv", na_values=["male"])

You can pass strings like "-", "nan", or any custom token your file uses for empty data.

156

Loading Data in Chunks

Sometimes the dataset is so large that loading it all at once fails or slows your machine.

Use chunksize to read the file in pieces:

chunks = pd.read_csv("test.csv", chunksize=100)

for chunk in chunks:
    print(chunk.shape)
    # process each chunk here

Each chunk is a DataFrame with 100 rows. You can clean, filter, or aggregate chunk by chunk without holding the full file in memory.

Day 15 takeaways

  • Data gathering has four paths: CSV, JSON/SQL, API, and web scraping. CSV is the starting point.
  • pd.read_csv works on local files and URLs.
  • Parameters like index_col, header, usecols, and dtype control how data loads.
  • Use encoding, on_bad_lines, converters, and na_values to handle messy real world files.
  • For huge files, use chunksize to process data in batches.

df.describe()

describe() gives count, mean, standard deviation, min, max, and quartiles like 25%, 50%, and 75%.

Use this to spot odd ranges, very large values, or columns that look flat and unhelpful.

177

Duplicate Values

Question 6: Are there duplicate rows?

df.duplicated().sum()

This counts how many rows repeat exactly.

Duplicates can inflate scores and mislead your model. Remove or fix them before training.

178

Correlation Between Columns

Question 7: How are columns related to each other?

Correlation means when one value goes up or down, another column may move in a linked way.

See the full correlation matrix:

df.corr()

Pick one column and read its links to others:

df.corr()["column_name"]

Values range from negative 1 to positive 1. Values close to 0 mean weak link. Values near 1 or negative 1 mean stronger link.

Use this to drop columns that repeat the same signal, or to spot features that may matter for your target.

  • shape, head(), and sample() show size and samples.
  • info() shows types and memory use.
  • isnull().sum() finds missing values you must handle.
  • describe(), duplicated(), and corr() complete your first data check.

Embeddings and Vectors

Embedding means turning text into a vector: a list of numbers that capture meaning.

You embed the whole document (in chunks) and you also embed the user query.

Embeddings are the bridge between plain language and a database that can search by meaning, not only exact keywords.

  • Pages.
  • Paragraphs.
  • Chapters.
  • Custom rules for your data.

RAG Flow Step by Step

RAG means retrieval augmented generation. Here is the flow in plain steps.

Offline (prepare data):

  • PDF or docs go in.
  • Text is chunked.
  • Chunks become embeddings.
  • Vectors are stored in a database.

Online (answer a question):

  • User query becomes an embedding.
  • Semantic search finds the best matching chunks.
  • System prompt combines retrieved pages plus the user question.
  • The LLM returns the final answer.

206

LangChain Recap

Quick recap from Day 21. LangChain is an open source framework for building LLM powered applications.

Its advantages:

  • You can build pipelines.
  • The chain concept: one output becomes the next input.
  • It is very flexible.

Common examples: chatbots and AI knowledge assistants.

207

The Six Components

LangChain has six main components. Learn these and the whole framework makes sense.

  1. Models. Talk to AI models.
  2. Prompts. The input you give the LLM.
  3. Chains. Pipelines of steps.
  4. Memory. Remember past conversation.
  5. Indexes. Connect your own knowledge.
  6. Agents. Let the LLM take actions.

The rest of this day walks through each one.

208

Component 1: Models

The models component is how your app interacts with AI models.

Some history helps. Before LLMs, chatbot context awareness and text generation were weak. LLMs solved that.

But an LLM is trained on huge data, so it is very hard to manage yourself:

  • It cannot easily run on a local machine.
  • Running it on your own server gives a very high bill.

So companies host the models and give us APIs. We just call them.

That created the next problem: implementation. OpenAI needs one code style. Claude needs different code. Even the output structure differs between providers. Standardization was hard.

LangChain fixed this. One common interface, many providers behind it.

209

Language vs Embedding Models

LangChain works with two types of models.

  • Language models: give text, get text. LLMs are language models.
  • Embedding models: give text, get a vector of numbers back.

Embedding models are mainly used for semantic search, which powers RAG and knowledge assistants.

You met embeddings on Day 21. Here they become a first class LangChain component.

210

Component 2: Prompts

A prompt is the input you provide to the LLM.

Prompts are very important. A small change to a prompt can change the whole output.

Prompts even created jobs: prompt engineering.

LangChain supports different prompt styles:

  • Dynamic and reusable prompts. For example: summarize a topic in a chosen tone. Fill the topic and tone at run time.
  • Role based prompting. Tell the model who it is before the task.
  • Few shot prompting. Show a few examples so the model copies the pattern.

Templates keep prompts consistent, so the app does not break from small wording drift.

211

Component 3: Chains

Chains matter so much that LangChain is named after them.

A chain is a pipeline of steps. If you know visual automation tools like n8n, the idea feels familiar.

Example pipeline:

Input, then LLM, then translate, then LLM again, then a summary in 100 words, then output.

The advantage: the output of the first step is the input of the second. No manual glue between steps.

Chains can also get complex:

  • Parallel chains. Input goes to LLM 1, LLM 2, and LLM 3 at once. Then you combine all three outputs into one result.
  • Conditional chains. Like an if else or switch. The pipeline picks a branch based on a condition.
212

Component 4: Indexes

Indexes connect your application to external knowledge, such as a PDF, a website, or a database.

Why you need them: ChatGPT does not know your private details. Ask it for your company leave policy and it cannot answer. Connect it to your company PDF, and now it can.

Indexes have four main parts:

  1. Document loader. Brings the data into the system.
  2. Text splitter. Splits 100 pages into pages, chapters, or paragraphs.
  3. Vector store. Converts those chunks to vectors with embeddings and stores them.
  4. Retriever. Converts the user query to a vector, runs semantic search against the stored vectors, and hands the best pages to the LLM to generate the answer.

This is the machinery behind the RAG flow from Day 21.

213

Component 5: Memory

LLM API calls are stateless.

First query: I am Bishal. Second query: who am I? Without memory, the LLM cannot remember.

LangChain offers several memory types:

  • Conversation buffer memory. Stores the transcript of the recent conversation. Problem: a very long conversation gets hard to carry.
  • Conversation buffer window memory. Keeps only the last N interactions, for example the last 100.
  • Summarizer based memory. Keeps a running summary instead of the full transcript.
  • Custom memory. Keeps advanced data about the user that your app chooses.

Pick the memory type by how long your conversations run and what must survive between turns.

214

Component 6: Agents

An LLM can generate text, but it cannot do work by itself.

Agents can do work, for example with the help of MCP and other tool connections.

Example: an LLM can suggest a trip to Pokhara for your holiday. An agent can also book the ticket to Pokhara.

AI agents have two powers:

  1. Reasoning capabilities. Plan the steps to reach a goal.
  2. Tool access. Call tools and services to act on that plan.

  • LangChain has six components: models, prompts, chains, memory, indexes, and agents.
  • Models give one interface over many LLM providers.
  • Prompts and chains shape input and pipeline flow.
  • Indexes plus retrievers connect your own documents.
  • Memory fixes stateless calls. Agents add reasoning plus tools.

LLMs Explained

A language model takes text as input and returns text as output.

  • Optimized for multi turn conversation.
  • Trained on books and chat style data, including forums like Reddit.

Temperature

Temperature controls how much creativity the model adds to its answers.

The range often goes from 0 to about 1.5 or a bit higher, depending on the provider.

model = ChatGroq(

Document Search Project

Put the pieces together: embed your documents, embed a query, then rank with cosine similarity.

from langchain_openai import OpenAIEmbeddings
from dotenv import load_dotenv
from sklearn.metrics.pairwise import cosine_similarity
import numpy as np

load_dotenv()

embedding = OpenAIEmbeddings(
    model="text-embedding-3-large",
    dimensions=32,
)

documents = [
    "my name is bishal",
    "i live in nepal",
    "I am ai learner",
]

query = "where does bishal live"

doc_embeddings = embedding.embed_documents(documents)
query_embedding = embedding.embed_query(query)

scores = cosine_similarity([query_embedding], doc_embeddings)[0]
index = int(np.argmax(scores))

print(documents[index])
print(scores[index])

The highest score points to the closest document. That is the heart of simple semantic search.

What Are Prompts

Prompts are the input instructions or query you give to a model to guide its output.

They tell the model what to do, how to answer, and what style or limits to follow.

Prompts matter so much that prompt engineering has become its own job profile.

Text Based and Multimodal Prompts

By content type, prompts fall into two groups:

  1. Text based prompts. Only text.
  2. Multimodal prompts. Text plus image, and sometimes sound or video as well.

Our main focus is text based prompts. About 99% of the time, that is what you will use.

234

Static and Dynamic Prompts

So far we often wrote a fixed string ourselves:

model.invoke("whats the capital of nepal")

That is a static style: the developer hard codes the prompt.

In the real world, a user types a prompt and clicks send. The LLM receives that text and returns a result. We as developers do not write every prompt by hand for each user.

That need for user driven text leads to dynamic prompts: a reusable template with slots filled at run time.

235

Why PromptTemplate Over f Strings

You can build dynamic text with Python f strings. That works for small demos.

Using PromptTemplate is a better habit:

  • You can turn on checks such as validate_template=True.
  • You can reuse the same template many times.
  • You can save a template to a file, for example template.json, and load it later.

f strings fill values right away. PromptTemplate keeps placeholders until you call invoke with a dict of values.

236

PromptTemplate Basics

Create a template with named slots, then fill them when you run.

from langchain_core.prompts import PromptTemplate

template = PromptTemplate(
    template="""Please summarize the research paper titled "{paper_input}"
with style {style_input} and length {length_input}.""",
    input_variables=["paper_input", "style_input", "length_input"],
)

# optional: keep the template on disk
template.save("template.json")

Later you pass a dict such as {"paper_input": "...", "style_input": "...", "length_input": "..."} into invoke.

Research Tool with PromptTemplate

Here is a Streamlit research summarizer. The user picks paper, style, and length. The template fills those slots, then the chain runs.

from langchain_groq import ChatGroq
from langchain_core.prompts import PromptTemplate
from dotenv import load_dotenv
import streamlit as st

load_dotenv()

model = ChatGroq(model="llama-3.3-70b-versatile")

st.header("Research Tool")

paper_input = st.selectbox(
    "Select Research Paper Name",
    [
        "Attention Is All You Need",
        "BERT: Pre-training of Deep Bidirectional Transformers",
        "GPT-3: Language Models are Few-Shot Learners",
        "Diffusion Models Beat GANs on Image Synthesis",
    ],
)

style_input = st.selectbox(
    "Select Explanation Style",
    ["Beginner-Friendly", "Technical", "Code-Oriented", "Mathematical"],
)

length_input = st.selectbox(
    "Select Explanation Length",
    ["Short (1-2 paragraphs)", "Medium (3-5 paragraphs)", "Long (detailed explanation)"],
)

template = PromptTemplate(
    template="""Please summarize the research paper titled "{paper_input}" with the following specifications:
Explanation Style: {style_input}
Explanation Length: {length_input}

1. Mathematical Details:
   - Include relevant mathematical equations if present in the paper.
   - Explain the mathematical concepts using simple, intuitive code snippets where applicable.

2. Analogies:
   - Use relatable analogies to simplify complex ideas.

If certain information is not available in the paper, respond with: "Insufficient information available" instead of guessing.
Ensure the summary is clear, accurate, and matches the requested style and length.
""",
    input_variables=["paper_input", "style_input", "length_input"],
)

if st.button("Summarize"):
    chain = template | model
    result = chain.invoke(
        {
            "paper_input": paper_input,
            "style_input": style_input,
            "length_input": length_input,
        }
    )
    st.write(result.content)

Notice chain = template | model. The pipe connects the filled prompt to the chat model in one step.

Chat Message Types

Chat models work with typed messages, not only plain strings.

  • SystemMessage: instructions for the assistant (role and rules).
  • HumanMessage: text from the user.
  • AIMessage: text from the model.
from langchain_core.messages import SystemMessage, HumanMessage, AIMessage

messages = [

Build a Chatbot Loop

Keep a list of messages. Each turn, append the human message, call the model with the full history, then append the AI reply.

from langchain_groq import ChatGroq
from dotenv import load_dotenv
from langchain_core.messages import SystemMessage, HumanMessage, AIMessage

load_dotenv()

model = ChatGroq(
    model="llama-3.3-70b-versatile",
    temperature=1.5,
)

chat_history = [
    SystemMessage(content="You are a helpful assistant that can answer questions and help with tasks.")
]

while True:
    user_input = input("You: ")
    if user_input.lower() == "exit":
        break

    chat_history.append(HumanMessage(content=user_input))
    result = model.invoke(chat_history)
    chat_history.append(AIMessage(content=result.content))
    print("Chatbot:", result.content)

print("Chat history:", chat_history)

Type exit to stop. The printed history shows every system, human, and AI turn.

ChatPromptTemplate builds a list of chat messages from a template, with slots like {domain} and {input}.

from langchain_core.prompts import ChatPromptTemplate

chat_template = ChatPromptTemplate.from_messages([
    ("system", "You are a helpful assistant in a domain {domain} that can answer questions and help with tasks."),
    ("human", "{input}"),

prompt = chat_template.invoke({
    "domain": "healthcare",
    "input": "What is the capital of France?",
})
print(prompt)

The result is a structured chat prompt ready to send to a chat model.

MessagesPlaceholder

A MessagesPlaceholder sits inside a chat template. At run time it injects a list of past messages as dynamic chat history.

from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
from langchain_core.messages import HumanMessage, AIMessage

chat_template = ChatPromptTemplate.from_messages([
    ("system", "You are a helpful assistant that can answer questions and help with tasks."),
    MessagesPlaceholder(variable_name="chat_history"),
    ("human", "{input}"),
])

chat_history = [
    HumanMessage(content="Hi"),
    AIMessage(content="Hello! How can I help?"),
]

prompt = chat_template.invoke({
    "chat_history": chat_history,
    "input": "What is the capital of France?",
})
print(prompt)

You can also load history from a file such as chat_history.json, then pass that list into chat_history when you invoke.

Day 25

Structured Output in LangChain

Turn free text LLM replies into JSON shaped data with TypedDict, Pydantic, and JSON Schema.

242

Why Structured Output Matters

The biggest advantage of an LLM is that it can communicate in natural language.

Real apps also need to connect that LLM to an API, a database, or other tools.

Today we learn how to shape the LLM output so other systems can use it safely.

243

Unstructured vs Structured

Unstructured output: you give a prompt, the LLM answers in free text. That text is hard to plug into code without parsing by hand.

Structured output: the LLM returns formatted data, often like JSON, with known fields.

Structure is a powerful technique. Without it, you mostly get text. With it, you can hand fields to tools and databases.

244

Use Cases

Common places structured output helps:

  1. Data extraction. On a job portal, people upload resumes. You send the resume text to the LLM and get JSON fields back, ready to store.
  2. API building. Think of product reviews on a shop like Amazon. The LLM returns key details in JSON: product focus, good or bad tone, and more.
  3. Agents with tools. A chatbot only answers. An agent acts. When an agent calls tools, it needs structured arguments, not only chat text.
245

Two Paths to Structure

There are two kinds of LLMs for this topic:

  1. Models that can generate structured output on their own.
  2. Models that cannot do that cleanly.

For models that support it, use with_structured_output.

For models that cannot, use an output parser after the free text reply.

This day focuses on with_structured_output.

246

Three Data Formats

When you call with_structured_output, you usually pick one of three shapes:

  1. TypedDict for type hints and a simple dict result.
  2. Pydantic for real validation and safer objects.
  3. JSON Schema when many languages must share one schema.

You wrap the model once, then invoke as usual:

structured_model = model.with_structured_output(Review)
result = structured_model.invoke("This is a very good mobile. I give it 5 stars.")
247

TypedDict Basics

A plain dict can hide type mistakes. One developer might store age as a number. Another might store it as a string.

TypedDict tells tools and teammates the expected keys and types:

from typing import TypedDict

class Person(TypedDict):
    name: str
    age: int

new_person: Person = {
    "name": "bishal",
    "age": 35,
}

Your editor can warn when name is not a string or age is not an int.

Important limit: TypedDict is mainly for data representation and type hints. It does not validate at run time. Bad values can still get through.

248

Review Extraction with TypedDict

Send a phone review to the LLM and ask for a dict with summary and sentiment.

from langchain_groq import ChatGroq
from dotenv import load_dotenv
from typing import TypedDict

load_dotenv()

model = ChatGroq(model="llama-3.3-70b-versatile")

class Review(TypedDict):
    summary: str
    sentiment: str

structured_model = model.with_structured_output(Review)

result = structured_model.invoke(
    "This is a very good mobile. I give it 5 stars."
)

print(result)
print(type(result))
print(result["summary"])

You get a dictionary back.

You did not spell out “write a summary and sentiment” in the user prompt. LangChain still guides the model with a system style schema behind the scenes based on your TypedDict fields.

249

Annotated Guidance

Sometimes the LLM still gets confused. Use Annotated to add a short hint for each field.

from typing import TypedDict, Annotated

class Review(TypedDict):
    summary: Annotated[str, "A brief summary of the review"]
    sentiment: Annotated[
        str,
        "Sentiment: negative, positive, or neutral",
    ]

Those hints travel with the schema so the model knows what each field means.

250

Optional and Literal

Richer reviews need more fields. Three helpers matter:

  • TypedDict: tell humans and tools which keys exist and their types.
  • Annotated: give the model extra meaning for each field.
  • Optional: the field may be missing. Include it only when it fits.
  • Literal: allow only specific words, such as pos or neg.
from typing import TypedDict, Annotated, Optional, Literal, List

class Review(TypedDict):
    key_themes: Annotated[List[str], "Write all the key themes"]
    summary: Annotated[str, "A brief summary of the review"]
    sentiment: Annotated[
        Literal["pos", "neg", "neutral"],
        "Use pos, neg, or neutral",
    ]
    pros: Annotated[
        Optional[List[str]],
        "List of pros if the review has them",
    ]
251

Pydantic Basics

Pydantic is a library for data validation. It checks that data is correct, structured, and type safe at run time.

Teams use it a lot with FastAPI when building APIs. It is very useful for structured LLM output too.

from pydantic import BaseModel

class Student(BaseModel):
    name: str

new_student = {"name": "bishal"}
student = Student(**new_student)
print(student)

If name is missing or the wrong type, Pydantic raises an error instead of silently accepting bad data.

252

Defaults, Email, and Field

Pydantic can set defaults, mark optional fields, validate emails, and add constraints.

from pydantic import BaseModel, EmailStr, Field
from typing import Optional

class Student(BaseModel):
    name: str = "bishal"
    age: Optional[int] = None
    email: EmailStr
    cgpa: float = Field(
        gt=0,
        lt=10,
        description="CGPA between 0 and 10",
    )

new_student = {
    "age": 32,
    "email": "bishal@example.com",
    "cgpa": 8.5,
}
student = Student(**new_student)
print(student)

student_dict = dict(student)
print(student_dict["age"])

Field can set default values, constraints like gt and lt, descriptions, and regex style rules.

Pydantic is also smart about casting. If you pass the string "32" for an int field, it often converts it for you.

253

Structured Output with Pydantic

Pass a Pydantic model into with_structured_output. You get a validated object back, not only a dict.

from langchain_groq import ChatGroq
from dotenv import load_dotenv
from typing import Optional, Literal, List
from pydantic import BaseModel, Field

load_dotenv()

model = ChatGroq(model="llama-3.3-70b-versatile")

class Review(BaseModel):
    key_themes: List[str] = Field(description="Write all the key themes")
    summary: str = Field(description="A brief summary of the review")
    sentiment: Literal["pos", "neg"] = Field(
        description="Sentiment as pos or neg",
    )
    name: Optional[str] = Field(
        default=None,
        description="Reviewer name if present",
    )
    pros: Optional[List[str]] = Field(
        default=None,
        description="Pros as a list if present",
    )

structured_model = model.with_structured_output(Review)
result = structured_model.invoke(
    "This is a very good mobile. I give it 5 stars."
)
print(result.name)
print(result.summary)

Defaults help when the LLM misses a field. Validation catches bad shapes early.

254

JSON Schema Path

Use a JSON Schema when many languages must agree on one shape. Example: a React front end and a Python back end sharing the same contract. JSON is the common format.

from langchain_groq import ChatGroq
from dotenv import load_dotenv

load_dotenv()

model = ChatGroq(model="llama-3.3-70b-versatile")

review_schema = {
    "title": "Review",
    "description": "Schema for a product review",
    "type": "object",
    "properties": {
        "summary": {"type": "string"},
        "sentiment": {"type": "string"},
        "name": {"type": "string"},
    },
}

structured_model = model.with_structured_output(review_schema)
result = structured_model.invoke(
    "This is a very good mobile. I give it 5 stars."
)
print(result)

JSON Schema does not give you Pydantic style automatic conversion and rich Python validation by itself.

255

Which Format and Which Method

Format Use when Watch out
TypedDict You only need type hints and you trust the LLM No real validation. Used less often in production
Pydantic You need validation, defaults, and type conversion This is what you use most of the time
JSON Schema Many languages share one schema No automatic conversion like Pydantic

Inside with_structured_output, providers may use methods such as:

  1. JSON mode: ask the model to return JSON shaped data.
  2. Function calling: treat the schema like a tool call the model must fill.

Day 25 takeaways

  • Natural language is great, but APIs and databases need structured fields.
  • Use with_structured_output when the model supports it. Use parsers when it does not.
  • TypedDict hints shape. Pydantic validates. JSON Schema shares contracts across languages.
  • Annotated, Optional, and Literal guide richer review style schemas.
  • Prefer Pydantic for most LangChain structured output work.

Output Parsers in LangChain

Convert raw LLM text into usable fields with string, JSON, structured, and Pydantic parsers.

256

Why Output Parsers Matter

LLMs are great at natural language. But apps need consistent data for APIs, databases, and tools.

Output parsers convert raw model responses into a format you can reliably use.

In this day, we compare four common parser types and when to use each one.

257

String Output Parser

String output parsing is the simplest case.

You force the chain to return plain text instead of a model object with extra metadata.

from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import PromptTemplate
from langchain_groq import ChatGroq
from dotenv import load_dotenv

load_dotenv()

model = ChatGroq(model="llama-3.3-70b-versatile")

template1 = PromptTemplate(
    template="Write a detailed report on {topic}.",
    input_variables=["topic"],
)

template2 = PromptTemplate(
    template="Write a four-line summary of the following text:\n{text}",
    input_variables=["text"],
)

parser = StrOutputParser()

chain = (
    template1
    | model
    | parser
    | {"text": lambda text: text}
    | template2
    | model
    | parser
)

result = chain.invoke({"topic": "Nepal"})
print(result)

Here the parser makes the chain output a real string.

258

JSON Output Parser

JSON output parsing makes the model return JSON shaped data.

This is useful for connecting to code that expects key value fields.

The important limit is that JSON output parsing does not fully validate your full schema like Pydantic does.

from langchain_core.prompts import PromptTemplate
from langchain_core.output_parsers import JsonOutputParser
from langchain_groq import ChatGroq
from dotenv import load_dotenv

load_dotenv()

model = ChatGroq(model="llama-3.3-70b-versatile")
parser = JsonOutputParser()

template = PromptTemplate(
    template=(
        "Give me the name, age, and city of a fictional character.\n"
        "{format_instructions}"
    ),
    input_variables=[],
    partial_variables={
        "format_instructions": parser.get_format_instructions()
    },
)

chain = template | model | parser
result = chain.invoke({})

print(result)
print(result["name"])
print(result["age"])
print(result["city"])
259

Structured Output Parser

A structured output parser helps you shape a response into fields.

It can enforce the structure of the output format, but it does not do full data validation.

from langchain_classic.output_parsers import ResponseSchema, StructuredOutputParser
from langchain_core.prompts import PromptTemplate
from langchain_groq import ChatGroq
from dotenv import load_dotenv

load_dotenv()
model = ChatGroq(model="llama-3.3-70b-versatile")

schemas = [
    ResponseSchema(
        name="name",
        description="The name of the fictional character",
    ),
    ResponseSchema(
        name="age",
        description="The age of the fictional character",
    ),
    ResponseSchema(
        name="city",
        description="The city of the fictional character",
    ),
]

parser = StructuredOutputParser.from_response_schemas(schemas)

template = PromptTemplate(
    template=(
        "Give me the name, age, and city of a fictional character.\n"
        "{format_instructions}"
    ),
    input_variables=[],
    partial_variables={
        "format_instructions": parser.get_format_instructions()
    },
)

chain = template | model | parser
result = chain.invoke({"topic": "Nepal"})
print(result)

Use this when you want structure, but you do not need strict type validation.

260

Pydantic Output Parser

Pydantic output parsing gives you the strongest guarantees.

You define a Pydantic model, and the parser validates types and shapes.

from langchain_groq import ChatGroq
from dotenv import load_dotenv
from langchain_core.prompts import PromptTemplate
from langchain_core.output_parsers import PydanticOutputParser
from pydantic import BaseModel, Field

load_dotenv()

model = ChatGroq(model="llama-3.3-70b-versatile")

class Person(BaseModel):
    name: str = Field(description="The name of the fictional character")
    age: int = Field(
        gt=18,
        description="The age of the fictional character",
    )
    city: str = Field(description="The city of the fictional character")

parser = PydanticOutputParser(pydantic_object=Person)

template = PromptTemplate(
    template=(
        "Give me the name, age, and city of a fictional character "
        "from {place}.\n{format_instructions}"
    ),
    input_variables=["place"],
    partial_variables={
        "format_instructions": parser.get_format_instructions()
    },
)

prompt = template.invoke({"place": "Nepal"})
result = model.invoke(prompt)
final_result = parser.parse(result.content)

print(final_result)
print(final_result.name)

When types are wrong, Pydantic can raise an error so your app stays safe.

261

Output Parsers Work for Any LLM

Some models can generate structured output directly. Some cannot.

Output parsers still help in both cases by converting the raw response into your desired format.

So you can keep your app logic consistent, even when you swap providers.

262

Limitations to Know

Each parser gives a different level of safety:

  • String output parsing returns text, so it is simple but not typed.
  • JSON output parsing helps, but it does not fully validate your schema like Pydantic.
  • Structured output parsing shapes fields, but does not guarantee strict type validation.
  • Pydantic output parsing validates types and shapes at run time.
263

Quick Decision Guide

Parser Structured format Type validation
String Plain text No
JSON Keys and values Limited
Structured output Fields from schema descriptions No full validation
Pydantic Typed model Yes

If you need safe tool calls, choose Pydantic. If you only need simple text or JSON shaped fields, choose String or JSON.
