Past Chat History in LangGraph

Start a new chat or resume an old one. The back end stays the same. The Streamlit sidebar holds thread ids and loads the saved conversation.

Two New Features

Today we add two features to our chatbot. Start a new chat. Resume a past chat. We do not need to change the back end. The checkpointer already stores each thread. The front end only needs to pick which thread_id to use. The cards below are those two features.

Start new chat

Make a new thread id. Clear the bubbles. Talk in a fresh window.

Resume chat

Click a saved thread id. Load that conversation from the checkpointer.

Four Tasks

We divide this into four tasks. The steps below are that plan. We will build them one by one.

Front end work only

  1. Sidebar Title, a start chat button, and a My Conversations heading. Make a dynamic thread id and show it.
  2. New chat click Open a new window. Make a new thread_id. Save it in session. Reset message history.
  3. Thread list Store all thread ids. Load them in the sidebar. Turn each one into a button.
  4. Load one chat On click of a thread id, load that conversation.

Back End Stays the Same

The graph is still START, chat_node, END. ChatState still uses add_messages. The model still streams. InMemorySaver still saves state per thread_id. We compile chatbot the same way. The front end will call get_state and stream with a chosen thread id.

langgraph_backend.py

from langgraph.graph import StateGraph, START, END
from typing import TypedDict, Annotated
from langchain_core.messages import BaseMessage
from langchain_openrouter import ChatOpenRouter
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.graph.message import add_messages
from dotenv import load_dotenv

load_dotenv()

llm = ChatOpenRouter(
    model="openrouter/free",
    temperature=0,
    streaming=True
)

class ChatState(TypedDict):
    messages: Annotated[list[BaseMessage], add_messages]

def chat_node(state: ChatState):
    messages = state["messages"]
    response = llm.invoke(messages)
    return {
        "messages": [response]
    }

checkpointer = InMemorySaver()

graph = StateGraph(ChatState)
graph.add_node("chat_node", chat_node)
graph.add_edge(START, "chat_node")
graph.add_edge("chat_node", END)

chatbot = graph.compile(
    checkpointer=checkpointer
)

No new nodes. Resume works because this checkpointer already stores each thread.

Sidebar and a Dynamic Thread

generate_thread_id uses uuid4 so each chat gets a unique id. We store thread_id, message_history, and threads on session_state. The sidebar title is LangGraph Chatbot. Current Conversation shows the live thread id. The picture below is that sidebar.

Session and sidebar head

import streamlit as st
from langgraph_backend import chatbot
from langchain_core.messages import HumanMessage
import uuid

def generate_thread_id():
    return str(uuid.uuid4())

if "thread_id" not in st.session_state:
    st.session_state["thread_id"] = generate_thread_id()

if "message_history" not in st.session_state:
    st.session_state["message_history"] = []

if "threads" not in st.session_state:
    st.session_state["threads"] = []

st.sidebar.title("LangGraph Chatbot")

st.sidebar.subheader("Current Conversation")
st.sidebar.write(
    st.session_state["thread_id"]
)

threads is the list of past ids. The live id is thread_id. The code later names the list Previous Conversations.

Start New Chat

On click of new chat we open a new chat window. We generate a new thread_id. We save it in session. We reset message history. First we call save_current_thread so the old id goes into the threads list if that chat already has messages. Then st.rerun() redraws the empty window.

Save, then start fresh

def save_current_thread():
    current = st.session_state["thread_id"]
    if (
        st.session_state["message_history"]
        and current not in st.session_state["threads"]
    ):
        st.session_state["threads"].append(current)

if st.sidebar.button("Start New Chat"):
    save_current_thread()
    st.session_state["thread_id"] = generate_thread_id()
    st.session_state["message_history"] = []
    st.rerun()

An empty chat is not added to the list. Only a thread that already has messages is stored.

Thread Ids as Buttons

We create a list to store all thread ids. That list is session_state threads. We load those ids in the sidebar. We convert the sidebar text to clickable buttons. reversed puts the newest id first. Each button key is the thread id so Streamlit can tell them apart.

Previous Conversations

st.sidebar.subheader("Previous Conversations")

for thread_id in reversed(st.session_state["threads"]):
    if st.sidebar.button(thread_id, key=thread_id):
        save_current_thread()
        st.session_state["thread_id"] = thread_id
        st.session_state["message_history"] = load_conversation(thread_id)
        st.rerun()

Click a button and we switch thread_id, then load that chat into the bubbles.

Load One Conversation

On click of a particular thread id we load that conversation. load_conversation calls chatbot.get_state with that thread id. It reads state.values messages. A human message becomes role user. Anything else becomes assistant. If content is a list, we join the text parts. The picture below is that load path.

load_conversation

def load_conversation(thread_id):
    state = chatbot.get_state(
        config={"configurable": {"thread_id": thread_id}}
    )
    messages = []
    for msg in state.values.get("messages", []):
        role = "user" if msg.type == "human" else "assistant"
        content = msg.content
        if isinstance(content, list):
            content = "".join(
                part if isinstance(part, str) else part.get("text", "")
                for part in content
            )
        messages.append(
            {
                "role": role,
                "content": content
            }
        )
    return messages

The words come from the saved state. We do not paste a fake chat here. Start a chat, click Start New Chat, then click the old id to see it return.

Chat Still Streams

CONFIG now uses the thread_id that is in session. Send a line and we still stream with write_stream. New turns write into that thread. The checkpointer keeps them. After a new chat or a resume, this same block talks to the active id.

CONFIG and stream

CONFIG = {
    "configurable": {
        "thread_id": st.session_state["thread_id"]
    }
}

for message in st.session_state["message_history"]:
    with st.chat_message(message["role"]):
        st.write(message["content"])

user_input = st.chat_input("Type here")

if user_input:
    st.session_state["message_history"].append(
        {
            "role": "user",
            "content": user_input
        }
    )
    with st.chat_message("user"):
        st.write(user_input)

    with st.chat_message("assistant"):
        def stream_response():
            for message_chunk, metadata in chatbot.stream(
                {
                    "messages": [
                        HumanMessage(content=user_input)
                    ]
                },
                config=CONFIG,
                stream_mode="messages"
            ):
                if message_chunk.content:
                    yield message_chunk.content

        ai_message = st.write_stream(
            stream_response()
        )

    st.session_state["message_history"].append(
        {
            "role": "assistant",
            "content": ai_message
        }
    )

Same stream loop as Day 57. Only the thread id in CONFIG has changed. It now comes from session, not a fixed thread 1 string.

Day 58 takeaways

Day 58 takeaways

  • Start new chat and resume chat are front end features. The back end graph does not change.
  • uuid4 makes a dynamic thread id. We store it on session_state with message_history and a threads list.
  • Start New Chat saves the old id if it has messages, then makes a new id and clears the bubbles.
  • The sidebar lists thread ids as buttons under Previous Conversations.
  • Click an id, call get_state, map messages to role and content, then fill message_history.
  • CONFIG uses the active session thread_id so stream writes into that same saved chat.
