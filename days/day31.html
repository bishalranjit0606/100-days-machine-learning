Text Splitters in LangChain

Break large documents into chunks that LLMs, embeddings, and RAG can handle well.

What Is Text Splitting

Imagine a PDF with 1000 pages. You cannot feed the whole file to an LLM in one go.

Text splitting is the process of breaking large text from a PDF or any source into smaller, manageable chunks that an LLM can handle well.

You can split by pages, by paragraphs, by size, or by meaning. Good chunks raise the quality of what the model does next.

From one big file to small pieces

  1. Large source A long PDF or document.
  2. Split Cut into smaller chunks.
  3. Chunks Pieces an LLM can use.
364

Why We Split Text

LLMs have a context length limit. That is how much input the model can take at once.

Picture a model that accepts about 50,000 tokens. For a rough story, treat one token like one word. Now imagine a PDF with more than 100,000 words. You cannot send the whole PDF. Splitting lets you work with that file with ease.

Splitting also unlocks three common tasks: embedding, semantic search, and summarization.

Embedding

Text becomes a vector of numbers so ML models can work with it. Never embed a whole PDF at once. Do text, then chunk, then embedding.

Semantic search

Embed files on food, animals, and sports. Ask for the national dish of Nepal. Convert the query to a vector and find the closest chunks.

Summarization

Smaller pieces help reduce hallucination and topic drift when you ask the model to summarize.

There is one more reason: compute. Smaller chunks use memory more carefully and can run in parallel.

Safe path for embeddings

  1. Text Load the document.
  2. Chunk Split into pieces.
  3. Embedding Vector per chunk.

Four Types of Text Splitters

LangChain gives you several ways to split. Remember these four names. They map cleanly to the classes you will say in an interview.

Character based

CharacterTextSplitter. Cut by size with one separator. Simple and fast.

Recursive character based

RecursiveCharacterTextSplitter. Tries paragraph, line, word, then character.

Recursive with language

Same recursive splitter, but separators match Python, JS, HTML, Markdown, and more.

Semantic meaning based

SemanticChunker. Split where meaning shifts, using embeddings and similarity.

Types two and three are the same tool. Type three only changes the separators for code or Markdown style files.

366

Character Based Text Splitter

The first type is character based splitting. The class is CharacterTextSplitter. It is simple and fast. You decide the chunk size yourself. Size is often characters. Tokens are possible too in other length tools.

A helpful tool to see chunks on screen is chunkviz.app.

The big downside: it does not look at grammar or meaning. It can cut in the middle of a word or sentence. That hurts embeddings, because half of an idea lands in one chunk and the rest in another.

Here is character based splitting on plain text. With an empty separator it cuts by character size only.

Input code

from langchain_text_splitters import CharacterTextSplitter

text = """One of the most important things I didn't understand about the world when I was a child is the degree to which the returns for performance are superlinear.

Teachers and coaches implicitly told us the returns were linear. "You get out," I heard a thousand times, "what you put in." They meant well, but this is rarely true. If your product is only half as good as your competitor's, you don't get half as many customers. You get no customers, and you go out of business.

It's obviously true that the returns for performance are superlinear in business. Some think this is a flaw of capitalism, and that if we changed the rules it would stop being true. But superlinear returns for performance are a feature of the world, not an artifact of rules we've invented. We see the same pattern in fame, power, military victories, knowledge, and even benefit to humanity. In all of these, the rich get richer. [1]

You can't understand the world without understanding the concept of superlinear returns. And if you're ambitious you definitely should, because this will be the wave you surf on."""

splitter = CharacterTextSplitter(
    chunk_size=100,
    chunk_overlap=0,
    separator="",
)

result = splitter.split_text(text)
print(result)

What you get

['One of the most important things I didn\'t understand about the world when I was a child is the degree t',
 'o which the returns for performance are superlinear.\n\nTeachers and coaches implicitly told us the retu',
 ...]

Chunks are about 100 characters. Notice how a cut can land mid word. That is the risk of character based splitting.

The same splitter works on Documents from a PDF loader. Use split_documents instead of split_text.

Input code

from langchain_text_splitters import CharacterTextSplitter
from langchain_community.document_loaders import PyPDFLoader
import warnings

warnings.filterwarnings("ignore", category=DeprecationWarning)

loader = PyPDFLoader("day30.pdf")
docs = loader.load()

splitter = CharacterTextSplitter(
    chunk_size=100,
    chunk_overlap=0,
    separator="",
)

result = splitter.split_documents(docs)
print(result)
print(result[0])
print(result[0].page_content)

What you get

[Document(page_content='...', metadata={...}), ...]
Document(page_content='first 100 chars...', metadata={...})
first 100 chars...

Each item is still a Document. page_content holds the chunk text. metadata from the loader is kept.

What Is Chunk Overlap

Chunk overlap is shared text between two neighboring chunks.

With character based cuts you can lose a full idea at the boundary. Overlap copies a little text from the previous chunk into the next one, so that risk goes down.

If overlap is very large, chunks look safer, but you also repeat more context and waste space. A common tip is about 10 to 20 percent overlap.

Overlap at the boundary

  1. Chunk A Ends with shared words.
  2. Overlap Those words appear twice.
  3. Chunk B Starts with the same words.

Recursive Character Based Splitter

The second type is recursive character based splitting. The class is RecursiveCharacterTextSplitter. It follows natural text structure: text, then paragraph, then sentence, then words. This is the most used style for normal writing.

It tries a list of separators in order. First keep paragraphs. Then lines. Then words. Then single characters if needed.

Separator What it means
\n\n Paragraph break.
\n Line break.
(space) Word break.
"" (empty) Character break as a last step.

Think of the work in two phases: split, then merge. The recursive tree below shows the split phase with chunk_size = 10.

Here is how to read that tree.

At the top you have the full text. There is a blank line in the middle, so the first separator \n\n cuts the text into two paragraphs. One group is 34 characters. The other is 30. Both are bigger than 10, so both get an X.

Because of the X, the splitter calls itself again on each group. Now it uses the next separator, \n. Each paragraph becomes separate lines. You now have four pieces: 17, 17, 19, and 11. Three of them are still bigger than 10. So the work is not done.

Next it uses a space. Each long line becomes words. Words are small enough. Then comes the merge phase.

Merge means packing small pieces back together from left to right, as long as the next word still fits under chunk_size. If the next word would push the total over 10, start a new chunk.

Two phases

  1. Split Go smaller with separators until pieces fit or you run out of separators.
  2. Merge Join neighboring small pieces while the total stays at or under chunk_size.

Walk through the first line, "My name is Bishal" (17). After the space split you get the words My, name, is, Bishal. Spaces count as characters.

Merge walk for the first line

"My"            = 2   start a chunk
"My name"       = 7   still under 10, keep going
"My name is"    = 10  exact fit, keep this chunk
next "Bishal"   = 6   10 + 1 + 6 would be over 10, so new chunk
chunks: "My name is" | "Bishal"

Same idea on the other lines

"I am 35 years old"
  -> "I am 35" | "years old"

"I live in Kathmandu"
  -> "I live in" | "Kathmandu"

"How are you" (11)
  -> "How are" | "you"

Merge packs words inside pieces you already have. It does not glue two paragraphs back together after a paragraph split.

Here is the same example in LangChain code. The separators list is what drives the recursive tree.

Input code

from langchain_text_splitters import RecursiveCharacterTextSplitter

text = """My name is Bishal
I am 35 years old

I live in Kathmandu
How are you"""

splitter = RecursiveCharacterTextSplitter(
    chunk_size=10,
    chunk_overlap=0,
    separators=["\n\n", "\n", " ", ""],
)

result = splitter.split_text(text)
print(result)

What you get

['My name is', 'Bishal', 'I am 35', 'years old', 'I live in', 'Kathmandu', 'How are', 'you']

Each string is at most 10 characters. That is split plus merge working together.

So the recursive part is the X loop: if a piece is too big, split again with a finer separator. The merge part is the packing step that builds final chunks near your size limit without cutting mid word when a space split is enough.

Simple rule: keep as much structure as you can. Go smaller only when you must. Then pack words back up to the limit.

Character versus Recursive

Type one and type two look similar in code. The difference is how many separators they try.

Name you remember Class How it works Best for
Character based CharacterTextSplitter Uses one separator only, such as a newline or a space. If a piece is still too big, it cuts by character size. Fast demos. Can break mid sentence.
Recursive character based RecursiveCharacterTextSplitter Tries many separators in order: paragraphs, lines, words, then characters. Goes smaller only when needed. Real documents, RAG, and embeddings.

Simple rule: use recursive character based for real documents. Character based is mainly for basic demos.

Recursive with Language

The third type is recursive character based splitting with a language. What if the file is not normal English prose? Source code is not organized by paragraphs and sentences. It has functions, loops, and keywords.

This is still the recursive character based splitter. Only the separators change. For Python they look like class and def markers. JavaScript, HTML, and Markdown each have their own list too.

RecursiveCharacterTextSplitter.from_language sets those separators for you. Pass a language such as python, js, html, java, php, or markdown.

Input code

from langchain_text_splitters import RecursiveCharacterTextSplitter

text = """
def hello_world():
    print("Hello, World!")
"""

splitter = RecursiveCharacterTextSplitter.from_language(
    language="python",
    chunk_size=100,
    chunk_overlap=0,
)

result = splitter.split_text(text)
print(result)

What you get

['def hello_world():\n    print("Hello, World!")']

With a small function and chunk_size 100, the whole function stays in one chunk. Larger files split near class and def boundaries first.

Semantic Meaning Based Splitter

The fourth type is semantic meaning based splitting. Sometimes every earlier splitter fails. Look at this text. It looks like two paragraphs, but the first paragraph mixes two topics: farming and the IPL. A third topic, terrorism, follows. Meaning says you need three chunks, not two.

Farmers were working hard in the fields, preparing the soil and planting seeds for the next season. The sun was bright, and the air smelled of earth and fresh grass. The Indian Premier League (IPL) is the biggest cricket league in the world. People all over the world watch the matches and cheer for their favourite teams.

Terrorism is a big danger to peace and safety. It causes harm to people and creates fear in cities and villages. When such attacks happen, they leave behind pain and sadness. To fight terrorism, we need strong laws, alert security forces, and support from people who care about peace and safety.

Semantic splitting does not decide by character count alone. It decides by meaning.

How semantic splitting works

  1. Sentences Split sentence by sentence.
  2. Embed Vector for each sentence.
  3. Compare Check similarity in a row.
  4. Cut Split where similarity drops.

When similarity between neighbors is very low, the topic changed. That is where you split. This approach is still fairly new. Accuracy is not always high yet, so treat it as experimental.

Input code

from langchain_experimental.text_splitter import SemanticChunker
from langchain_openai import OpenAIEmbeddings

text = """Farmers were working hard in the fields, preparing the soil and planting seeds for the next season. The sun was bright, and the air smelled of earth and fresh grass. The Indian Premier League (IPL) is the biggest cricket league in the world. People all over the world watch the matches and cheer for their favourite teams.
Terrorism is a big danger to peace and safety. It causes harm to people and creates fear in cities and villages."""

splitter = SemanticChunker(
    OpenAIEmbeddings(),
    breakpoint_threshold_type="percentile",
    breakpoint_threshold_amount=90,
)

result = splitter.create_documents([text])
for doc in result:
    print(doc.page_content)
    print("---")

What you hope to see

Farmers were working hard... fresh grass.
---
The Indian Premier League (IPL)... favourite teams.
---
Terrorism is a big danger... fear in cities and villages.
---

Exact cuts depend on the embedding model and threshold. You need an API key or another embedding backend for this to run.

Day 31 takeaways

Day 31 takeaways

  • Text splitting turns large documents into chunks an LLM can handle.
  • Remember four names: character based, recursive character based, recursive with language, and semantic meaning based.
  • Character based is fast but can cut mid word. Use overlap of about 10 to 20 percent to reduce boundary loss.
  • Recursive character based is the default for real text. Recursive with language is the same tool with separators for Python, JS, HTML, and more.
  • Semantic meaning based splits where topics change. It is useful, but still experimental.
