Sequential Workflow in LangGraph

Install LangGraph, open a notebook, then build a BMI calculator, a one node LLM graph, and a prompt chain from topic to outline to blog.

Sequential Workflow

A sequential workflow is a straight line. One node finishes, then the next node runs. Today we build that shape in LangGraph. First a BMI calculator with two inputs, height and weight, and an output. Then a simple LLM graph. Then prompt chaining.

665

Install LangGraph

Install LangGraph on your system inside a virtual environment. The steps below are that path. Later LLM cells use ChatOpenRouter, so we also install langchain openrouter. The pip name for dotenv is python dotenv.

Make a venv, then install

  1. venv Create a virtual environment.
  2. Activate Turn that environment on.
  3. Pip Install langgraph, langchain openai, langchain openrouter, and python dotenv.

The commands below are what you run in the terminal.

Terminal

python3 -m venv venv
source venv/bin/activate
pip install langgraph
pip install langchain_openai

Activate the venv first. Then each pip line adds one package. The ChatOpenRouter import needs the openrouter package from that list.

A BMI Calculator in Jupyter

We will use Jupyter notebook. Make a file named test.ipynb. The first workflow is simple. We make a BMI calculator. We give two inputs, height and weight, and we get an output. LangGraph needs state for those values. We start with three fields: weight, height, and bmi. The label step also writes a category.

667

Define the State

Import StateGraph, START, and END from langgraph.graph. Import TypedDict from typing. Then define State. Each key is a value the nodes share. weight and height are floats. bmi is a float. category is a string for the label.

State

from langgraph.graph import StateGraph, START, END
from typing import TypedDict

class State(TypedDict):
    weight: float
    height: float
    bmi: float
    category: str

TypedDict is a dictionary with named keys. Every node can read and update this state.

668

Calculate BMI

The first node is a Python function. It reads weight and height from state. BMI is weight divided by height squared. It returns only the new bmi, rounded to 2 places. LangGraph merges that dict into state.

calculate_bmi

def calculate_bmi(state: State):
    weight = state["weight"]
    height = state["height"]

    bmi = weight / (height ** 2)

    return {"bmi": round(bmi, 2)}

height ** 2 is height times height. round(bmi, 2) keeps two digits after the point.

669

Label BMI

The second node reads bmi from state and returns a category. Under 18.5 is Underweight. Under 24.9 is Normal weight. Under 29.9 is Overweight. Anything else is Obesity.

label_bmi

def label_bmi(state: State):
    bmi = state["bmi"]

    if bmi < 18.5:
        return {"category": "Underweight"}
    elif bmi < 24.9:
        return {"category": "Normal weight"}
    elif bmi < 29.9:
        return {"category": "Overweight"}
    else:
        return {"category": "Obesity"}

This function does not compute BMI again. It only labels the bmi that the first node already stored.

670

Build the Graph

Create a StateGraph with State. Add two nodes. The node name classify_bmi points at the function label_bmi. Then add edges. START goes to calculate_bmi. That node goes to classify_bmi. That node goes to END. The chain below is that line.

START to END

  1. START The run begins.
  2. calculate_bmi Write bmi into state.
  3. classify_bmi Write category into state.
  4. END The run stops.

Nodes, edges, compile

graph = StateGraph(State)

graph.add_node("calculate_bmi", calculate_bmi)
graph.add_node("classify_bmi", label_bmi)

graph.add_edge(START, "calculate_bmi")
graph.add_edge("calculate_bmi", "classify_bmi")
graph.add_edge("classify_bmi", END)

workflow = graph.compile()

compile checks the graph and prepares it to run. After this, the graph is ready for invoke.

671

Run the Graph

Input data is weight 70 and height 1.75. invoke sends that dict in as the initial state. print shows the full state after both nodes. The output below is from this same code.

Input and invoke

data = {
    "weight": 70,
    "height": 1.75
}

result = workflow.invoke(data)

print(result)

Output

{'weight': 70, 'height': 1.75, 'bmi': 22.86, 'category': 'Normal weight'}

70 divided by 1.75 squared is 22.86. That sits under 24.9, so the label is Normal weight. weight and height stay in state because invoke keeps the keys you started with.

A Simple LLM Workflow

Now a simple LLM based workflow. One node. load_dotenv loads secrets. ChatOpenRouter uses the model openrouter/free with temperature 0. State has prompt, and response is NotRequired because it does not exist until the node runs. The node calls llm.invoke on the prompt and returns response.content. START goes to generate_response, then END. The prompt is What is LangGraph?

One node LLM graph

from langgraph.graph import StateGraph, START, END
from langchain_openrouter import ChatOpenRouter
from typing import TypedDict, NotRequired
from dotenv import load_dotenv

load_dotenv()

llm = ChatOpenRouter(
    model="openrouter/free",
    temperature=0
)

class State(TypedDict):
    prompt: str
    response: NotRequired[str]

def generate_response(state: State):
    prompt = state["prompt"]
    response = llm.invoke(prompt)
    return {
        "response": response.content
    }

graph = StateGraph(State)
graph.add_node("generate_response", generate_response)
graph.add_edge(START, "generate_response")
graph.add_edge("generate_response", END)
workflow = graph.compile()

data = {
    "prompt": "What is LangGraph?"
}

result = workflow.invoke(data)
print(result)

print(result) shows prompt plus the model text in response. That text depends on the model, so we do not paste a fake answer here. Run the cell in test.ipynb to see yours.

Prompt Chaining

Prompt chaining uses the LLM more than once in a line. Topic becomes a detailed outline, then a blog. The graph is START, then generate_outline, then generate_blog, then END. The chain below is that path.

Topic to blog

  1. Topic The input is the topic, here LangGraph.
  2. generate_outline The first LLM pass writes a detailed outline.
  3. generate_blog The second pass writes the blog from that outline.

State holds topic, plus outline and blog as NotRequired. generate_outline asks for a detailed outline about the topic. generate_blog asks for a blog about the topic based on that outline. invoke starts with topic LangGraph. The block below is that notebook cell.

Outline, then blog

from langgraph.graph import StateGraph, START, END
from langchain_openrouter import ChatOpenRouter
from typing import TypedDict, NotRequired
from dotenv import load_dotenv

load_dotenv()

llm = ChatOpenRouter(
    model="openrouter/free",
    temperature=0
)

class State(TypedDict):
    topic: str
    outline: NotRequired[str]
    blog: NotRequired[str]

def generate_outline(state: State):
    prompt = f"""
    Generate a detailed outline for a blog post about {state['topic']}.
    """
    response = llm.invoke(prompt)
    return {
        "outline": response.content
    }

def generate_blog(state: State):
    prompt = f"""
    Generate a blog post about {state['topic']}
    based on the following outline:

    {state['outline']}
    """
    response = llm.invoke(prompt)
    return {
        "blog": response.content
    }

graph = StateGraph(State)
graph.add_node("generate_outline", generate_outline)
graph.add_node("generate_blog", generate_blog)
graph.add_edge(START, "generate_outline")
graph.add_edge("generate_outline", "generate_blog")
graph.add_edge("generate_blog", END)
workflow = graph.compile()

data = {
    "topic": "LangGraph"
}

result = workflow.invoke(data)
print(result)

The second node reads state outline from the first node. print(result) will include topic, outline, and blog. Those strings come from the model, so run the cell to see them.
