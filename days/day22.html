LangChain Components

LangChain Recap

Quick recap from Day 21. LangChain is an open source framework for building LLM powered applications.

Its advantages:

  • You can build pipelines.
  • The chain concept: one output becomes the next input.
  • It is very flexible.

Common examples: chatbots and AI knowledge assistants.

344

The Six Components

LangChain has six main components. Learn these and the whole framework makes sense.

  1. Models. Talk to AI models.
  2. Prompts. The input you give the LLM.
  3. Chains. Pipelines of steps.
  4. Memory. Remember past conversation.
  5. Indexes. Connect your own knowledge.
  6. Agents. Let the LLM take actions.

The rest of this day walks through each one.

345

Component 1: Models

The models component is how your app interacts with AI models.

Some history helps. Before LLMs, chatbot context awareness and text generation were weak. LLMs solved that.

But an LLM is trained on huge data, so it is very hard to manage yourself:

  • It cannot easily run on a local machine.
  • Running it on your own server gives a very high bill.

So companies host the models and give us APIs. We just call them.

That created the next problem: implementation. OpenAI needs one code style. Claude needs different code. Even the output structure differs between providers. Standardization was hard.

LangChain fixed this. One common interface, many providers behind it.

346

Language vs Embedding Models

LangChain works with two types of models.

  • Language models: give text, get text. LLMs are language models.
  • Embedding models: give text, get a vector of numbers back.

Embedding models are mainly used for semantic search, which powers RAG and knowledge assistants.

You met embeddings on Day 21. Here they become a first class LangChain component.

Component 2: Prompts

A prompt is the input you provide to the LLM.

Prompts are very important. A small change to a prompt can change the whole output.

Prompts even created jobs: prompt engineering.

LangChain supports different prompt styles:

  • Dynamic and reusable prompts. For example: summarize a topic in a chosen tone. Fill the topic and tone at run time.
  • Role based prompting. Tell the model who it is before the task.
  • Few shot prompting. Show a few examples so the model copies the pattern.

Templates keep prompts consistent, so the app does not break from small wording drift.

348

Component 3: Chains

Chains matter so much that LangChain is named after them.

A chain is a pipeline of steps. If you know visual automation tools like n8n, the idea feels familiar.

Example pipeline:

Input, then LLM, then translate, then LLM again, then a summary in 100 words, then output.

The advantage: the output of the first step is the input of the second. No manual glue between steps.

Chains can also get complex:

  • Parallel chains. Input goes to LLM 1, LLM 2, and LLM 3 at once. Then you combine all three outputs into one result.
  • Conditional chains. Like an if else or switch. The pipeline picks a branch based on a condition.

Component 4: Indexes

Indexes connect your application to external knowledge, such as a PDF, a website, or a database.

Why you need them: ChatGPT does not know your private details. Ask it for your company leave policy and it cannot answer. Connect it to your company PDF, and now it can.

Indexes have four main parts:

  1. Document loader. Brings the data into the system.
  2. Text splitter. Splits 100 pages into pages, chapters, or paragraphs.
  3. Vector store. Converts those chunks to vectors with embeddings and stores them.
  4. Retriever. Converts the user query to a vector, runs semantic search against the stored vectors, and hands the best pages to the LLM to generate the answer.

This is the machinery behind the RAG flow from Day 21.

350

Component 5: Memory

LLM API calls are stateless.

First query: I am Bishal. Second query: who am I? Without memory, the LLM cannot remember.

LangChain offers several memory types:

  • Conversation buffer memory. Stores the transcript of the recent conversation. Problem: a very long conversation gets hard to carry.
  • Conversation buffer window memory. Keeps only the last N interactions, for example the last 100.
  • Summarizer based memory. Keeps a running summary instead of the full transcript.
  • Custom memory. Keeps advanced data about the user that your app chooses.

Pick the memory type by how long your conversations run and what must survive between turns.

351

Component 6: Agents

An LLM can generate text, but it cannot do work by itself.

Agents can do work, for example with the help of MCP and other tool connections.

Example: an LLM can suggest a trip to Pokhara for your holiday. An agent can also book the ticket to Pokhara.

AI agents have two powers:

  1. Reasoning capabilities. Plan the steps to reach a goal.
  2. Tool access. Call tools and services to act on that plan.

Day 22 takeaways

  • LangChain has six components: models, prompts, chains, memory, indexes, and agents.
  • Models give one interface over many LLM providers.
  • Prompts and chains shape input and pipeline flow.
  • Indexes plus retrievers connect your own documents.
  • Memory fixes stateless calls. Agents add reasoning plus tools.
