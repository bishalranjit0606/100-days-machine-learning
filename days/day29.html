Recap: Why Invoke Exists

We already have many components: prompt templates, LLMs, parsers, and retrieval.

You can plug them together to build an app. That is the idea of plugin and play.

The hard part was that each piece had its own methods. A prompt used format. An LLM used predict. A parser used parse. Connecting them felt messy.

LangChain standardized the call. Every component can use invoke. That shared call is what Runnable gives you, so pieces connect with ease.

Every component is a class. With the same interface, you can build flexible workflows.

Two Kinds of Runnables

LangChain Runnables fall into two big groups. Here is the split at a glance.

Kind Job Examples
Task specific Core LangChain pieces turned into Runnables you can drop in a pipeline. ChatOpenAI, PromptTemplate, retrievers.
Runnable primitives Building blocks that connect task specific pieces in sequence, parallel, branch, and more. RunnableSequence, RunnableParallel, RunnableBranch, RunnableLambda, RunnablePassthrough, RunnableMap.

Today we focus on Runnable primitives. These are the tools that join pieces into real workflows.

RunnableSequence

RunnableSequence connects two or more Runnables in order. It is a built in class. Output of one step feeds the next.

Simple sequence

  1. Prompt Fill in the topic.
  2. Model Write the joke.
  3. Parser Return plain text.

Input code

from dotenv import load_dotenv
from langchain_groq import ChatGroq
from langchain_core.prompts import PromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnableSequence

load_dotenv()

prompt = PromptTemplate.from_template(
    "tell me a joke about {topic}"
)
model = ChatGroq(model="llama-3.3-70b-versatile")
parser = StrOutputParser()

chain = RunnableSequence(prompt, model, parser)

result = chain.invoke({"topic": "python"})
print(result)

What you get

A joke string about Python
(one invoke runs prompt, then model, then parser)

Pass a dict with topic. The sequence runs left to right and returns the final string.

You can make the line longer. First create a joke. Then explain that joke. Same class, more steps.

Joke then explain

  1. prompt1 Ask for a joke.
  2. model Write the joke.
  3. parser Joke as text.
  4. prompt2 Ask for an explanation.
  5. model Explain the joke.
  6. parser Explanation as text.

Input code

prompt1 = PromptTemplate(
    template="tell me a joke about {topic}",
    input_variables=["topic"],
)
prompt2 = PromptTemplate(
    template="explain the following joke {input}",
    input_variables=["input"],
)

chain = RunnableSequence(
    prompt1, model, parser, prompt2, model, parser
)

result = chain.invoke({"topic": "python"})
print(result)

What you get

Only the explanation string prints
(the joke text was used as input for prompt2,
but the final parser output is the explanation)

That last point matters. A plain sequence keeps only the final output. Next we fix that with pass through.

RunnableParallel

RunnableParallel runs several Runnables at the same time. Use it when one topic should feed more than one output.

Example: one topic about AI. Branch A writes a tweet. Branch B writes a LinkedIn post.

One topic, two posts

  1. Topic Shared input, such as ai.
  2. Tweet branch prompt1 to model to parser.
  3. LinkedIn branch prompt2 to model to parser.
  4. Dict result Keys tweet and linkedin.

Input code

from langchain_core.runnables import RunnableParallel

prompt1 = PromptTemplate(
    template="generate a tweet about {topic}",
    input_variables=["topic"],
)
prompt2 = PromptTemplate(
    template="generate a linkedin post about {topic}",
    input_variables=["topic"],
)

chain = RunnableParallel(
    {
        "tweet": prompt1 | model | parser,
        "linkedin": prompt2 | model | parser,
    }
)

result = chain.invoke({"topic": "ai"})
print(result)

Result shape

{
  "tweet": "...short tweet text...",
  "linkedin": "...longer post text..."
}

Both branches share the same topic. Keys name each branch in the output dict.

RunnablePassthrough

RunnablePassthrough does not change the input. What goes in comes out the same. A number stays a number. A dict stays a dict.

Remember the joke then explain sequence. You only printed the explanation. What if you need both the joke and the explanation?

Build a joke chain first. Then fan out in parallel: one branch explains, one branch passes the joke through unchanged.

Keep the joke and add an explanation

  1. chain1 prompt to model to parser makes the joke.
  2. chain2 parallel Split into two keys.
  3. explanation prompt2 to model to parser.
  4. joke RunnablePassthrough keeps the joke.

Input code

from langchain_core.runnables import (
    RunnablePassthrough,
    RunnableSequence,
    RunnableParallel,
)

chain1 = RunnableSequence(prompt1, model, parser)

chain2 = RunnableParallel(
    {
        "explanation": RunnableSequence(
            prompt2, model, parser
        ),
        "joke": RunnablePassthrough(),
    }
)

final_chain = RunnableSequence(chain1, chain2)

result = final_chain.invoke({"topic": "python"})
print(result)

Result shape

{
  "explanation": "...why the joke is funny...",
  "joke": "...the original joke text..."
}

Pass through is the quiet branch. It carries the joke forward while the other branch does more work.

RunnableLambda

RunnableLambda turns a normal Python function into a Runnable. Then that function can sit in any pipeline.

A common use case: clean messy customer reviews before sentiment. Reviews may have HTML tags or extra noise. You send the text through your function first, then into the LLM.

Clean, then classify

  1. Review Raw text in.
  2. RunnableLambda Your clean up function.
  3. LLM Read the clean text.
  4. Sentiment Positive or negative.

Here is a small practice flow: make a joke, then in parallel keep the joke and count its words with a lambda.

Joke plus word count

  1. Joke chain prompt to model to parser.
  2. Parallel Two keys from one joke string.
  3. joke Pass through unchanged.
  4. word_count Lambda counts the words.

Input code

from langchain_core.runnables import RunnableLambda

prompt = PromptTemplate(
    template="tell me a joke about {topic}",
    input_variables=["topic"],
)

runnable_word_counter = RunnableLambda(
    lambda text: len(text.split())
)

chain = RunnableSequence(prompt, model, parser)

chain2 = RunnableParallel(
    {
        "joke": RunnablePassthrough(),
        "word_count": runnable_word_counter,
    }
)

chain3 = RunnableSequence(chain, chain2)

result = chain3.invoke({"topic": "python"})
print(result)

Result shape

{
  "joke": "...joke text...",
  "word_count": 12
}

The lambda is plain Python. Wrap it once, and it snaps into the same Runnable world as prompts and models.

RunnableBranch

RunnableBranch is LangChain if else. It picks one path. It does not run every branch.

Think about an email router. A complaint goes to support. An inquiry gets no auto reply. A thank you gets a welcome note. One email, one chosen path.

Email style routing

  1. Email Classify the type.
  2. Branch Pick one path only.
  3. Complaint Trigger support.
  4. Inquiry No auto reply.
  5. Thank you Send a welcome reply.

Here is a code practice version. Write a long report. If it has more than 500 words, summarize it. Else keep the report as is.

Report length branch

  1. report_chain Write the full report.
  2. branch_chain Check word count.
  3. Over 500 Run summary_chain.
  4. 500 or fewer Pass the report through.

Input code

from langchain_core.runnables import (
    RunnablePassthrough,
    RunnableSequence,
    RunnableBranch,
    RunnableLambda,
)

prompt = PromptTemplate(
    template="Generate a detailed report of the following topic: {topic}",
    input_variables=["topic"],
)
prompt2 = PromptTemplate(
    template="Generate a short summary of the following text:\n{text}",
    input_variables=["text"],
)

report_chain = RunnableSequence(prompt, model, parser)

summary_chain = RunnableSequence(
    RunnableLambda(lambda text: {"text": text}),
    prompt2,
    model,
    parser,
)

branch_chain = RunnableBranch(
    (lambda text: len(text.split()) > 500, summary_chain),
    RunnablePassthrough(),
)

final_chain = RunnableSequence(report_chain, branch_chain)

result = final_chain.invoke(
    {"topic": "artificial intelligence"}
)
print(result)

What happens

If report words > 500 -> summary string
Else -> original report string unchanged

The first matching condition wins. The last item is the default path when no condition matches.

LCEL: The Pipe Shortcut

LCEL means LangChain Expression Language.

You saw that RunnableSequence is used a lot. The LangChain team wanted a shorter way to write the same idea.

Instead of wrapping every line in RunnableSequence(...), you can write r1 | r2 | r3. The pipe operator builds a sequence in a declarative style.

Same pipeline, shorter syntax

  1. Prompt Build the message.
  2. LLM Generate the reply.
  3. Parser Return plain text.

Input code

chain = prompt | model | parser

result = chain.invoke({"topic": "python"})
print(result)

Same idea as

RunnableSequence(prompt, model, parser)

You already used pipes inside parallel branches. LCEL is that same pipe style for sequences. Parallel work still uses RunnableParallel around those pipes.

Day 29 takeaways

Day 29 takeaways

  • Task specific Runnables are core pieces like prompts, models, and retrievers.
  • Runnable primitives connect those pieces: sequence, parallel, pass through, lambda, and branch.
  • RunnableSequence runs steps in order. RunnableParallel runs branches together.
  • RunnablePassthrough keeps input unchanged. RunnableLambda wraps a Python function.
  • RunnableBranch is if else: one matching path, plus a default.
  • LCEL uses the pipe operator so sequences read as prompt | model | parser.
