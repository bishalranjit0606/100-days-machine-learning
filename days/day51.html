Day 51

Parallel Workflow in LangGraph

Fan out from START, wait for every branch, then merge. First a cricket calculator. Then a Loksewa essay graph with structured output and a reducer.

675

What We Will Do

Today the graph is parallel. START sends work to strike rate, ball percentage, and boundary share at the same time. Then a summary node waits for all three. Then END. The diagram below is that shape.

676

Cricket State

Inputs are runs, balls, fours, and sixes. Computed values are sr, bpb, boundary_percentage, and summary. Those computed keys are NotRequired because they do not exist until a node writes them.

State

from typing import TypedDict, NotRequired
from langgraph.graph import StateGraph, START, END

class State(TypedDict):
    runs: int
    balls: int
    fours: int
    sixes: int

    sr: NotRequired[float]
    bpb: NotRequired[float]
    boundary_percentage: NotRequired[float]
    summary: NotRequired[str]

sr is strike rate. bpb is the ball percentage from fours plus sixes. boundary_percentage is the share of runs that came from boundaries.

677

Three Calculations

Each function reads the inputs and returns one new key. Strike rate is runs divided by balls, times 100. Ball percentage is fours plus sixes, divided by balls, times 100. Boundary percentage is fours times 4 plus sixes times 6, divided by runs, times 100.

Three nodes

def calculate_sr(state: State) -> dict:
    sr = state["runs"] / state["balls"] * 100
    return {"sr": sr}

def calculate_bpb(state: State) -> dict:
    bpb = (state["fours"] + state["sixes"]) / state["balls"] * 100
    return {"bpb": bpb}

def calculate_boundary_percentage(state: State) -> dict:
    boundary_runs = state["fours"] * 4 + state["sixes"] * 6
    boundary_percentage = boundary_runs / state["runs"] * 100
    return {"boundary_percentage": boundary_percentage}

These three do not wait on each other. Each one only needs the input numbers.

678

Fan Out Then Wait

summarise reads all three computed values and builds one sentence. Then we add nodes and edges. Three edges leave START. That is the fan out. One edge from a list of three node names into summarise waits for all three. That is the fan in. Then summarise goes to END.

Summary, nodes, edges

def summarise(state: State) -> dict:
    summary = (
        f"The strike rate is {state['sr']:.2f}, "
        f"the boundary-ball percentage is {state['bpb']:.2f}%, "
        f"and {state['boundary_percentage']:.2f}% of runs came from boundaries."
    )
    return {"summary": summary}

builder = StateGraph(State)

builder.add_node("calculate_sr", calculate_sr)
builder.add_node("calculate_bpb", calculate_bpb)
builder.add_node(
    "calculate_boundary_percentage",
    calculate_boundary_percentage
)
builder.add_node("summarise", summarise)

builder.add_edge(START, "calculate_sr")
builder.add_edge(START, "calculate_bpb")
builder.add_edge(START, "calculate_boundary_percentage")

builder.add_edge(
    [
        "calculate_sr",
        "calculate_bpb",
        "calculate_boundary_percentage"
    ],
    "summarise"
)

builder.add_edge("summarise", END)

graph = builder.compile()

A list on add_edge means wait for every name in that list before summarise runs.

A Parallel LLM Essay Graph

Now the same shape with an LLM. A Loksewa exam essay goes out in parallel to three checks: clarity of thought, depth of analysis, and language. Each LLM returns two things: text feedback and a score. A final evaluation node sees all the text feedback, summarises it, and averages the scores. Then END. This uses structured output and a reducer. The diagram below is that graph.

681

Structured Output

Each evaluator must return text feedback and a score, not free prose only. EvaluationSchema is a Pydantic model. feedback is a string. score is an int from 0 to 10. with_structured_output wraps the LLM so invoke returns that schema.

Schema and LLM

from langchain_openrouter import ChatOpenRouter
from pydantic import BaseModel, Field
from dotenv import load_dotenv

load_dotenv()

llm = ChatOpenRouter(
    model="openrouter/free",
    temperature=0
)

class EvaluationSchema(BaseModel):
    feedback: str = Field(
        description="Constructive feedback for the essay"
    )
    score: int = Field(
        ge=0,
        le=10,
        description="Score from 0 to 10"
    )

structured_output = llm.with_structured_output(EvaluationSchema)

ge is greater or equal. le is less or equal. The score cannot sit outside 0 to 10.

682

State and a List Reducer

State holds the essay, three feedback strings, overall feedback, and individual_score. We merge three LLM scores, so we need a reducer on that list. Annotated with operator.add tells LangGraph to combine lists from parallel nodes. Each node returns a one item list. add joins them into one list.

State

from typing import TypedDict, Annotated
import operator

class State(TypedDict):
    essay: str

    language_feedback: str
    analysis_feedback: str
    clarity_feedback: str

    overall_feedback: str

    individual_score: Annotated[list[int], operator.add]

Start invoke with individual_score set to an empty list. That empty list is the first value the reducer adds onto.

683

Three Evaluators

Each node asks the model to judge only one thing, then stores its own feedback key and appends its score. Language looks at grammar, vocabulary, sentence structure, and writing style. Analysis looks at depth of ideas, reasoning, supporting arguments, and examples. Clarity looks at organization, readability, logical flow, and how clearly ideas are communicated. The block below is all three.

Language, analysis, clarity

def language_evaluation(state: State) -> dict:
    prompt = f"""
    Evaluate ONLY the language quality of this essay.

    Consider:
    - grammar
    - vocabulary
    - sentence structure
    - writing style

    Give constructive feedback and a score out of 10.

    Essay:
    {state["essay"]}
    """
    result = structured_output.invoke(prompt)
    return {
        "language_feedback": result.feedback,
        "individual_score": [result.score]
    }

def analysis_evaluation(state: State) -> dict:
    prompt = f"""
    Evaluate ONLY the depth and analysis of this essay.

    Consider:
    - depth of ideas
    - reasoning
    - supporting arguments
    - examples or evidence

    Give constructive feedback and a score out of 10.

    Essay:
    {state["essay"]}
    """
    result = structured_output.invoke(prompt)
    return {
        "analysis_feedback": result.feedback,
        "individual_score": [result.score]
    }

def clarity_evaluation(state: State) -> dict:
    prompt = f"""
    Evaluate ONLY the clarity of this essay.

    Consider:
    - organization
    - readability
    - logical flow
    - how clearly ideas are communicated

    Give constructive feedback and a score out of 10.

    Essay:
    {state["essay"]}
    """
    result = structured_output.invoke(prompt)
    return {
        "clarity_feedback": result.feedback,
        "individual_score": [result.score]
    }

Each return uses a list around the score. operator.add then merges those lists after the three nodes finish.

684

Final Evaluation Node

The reducer node is the aggregator. It reads the three feedback strings and the joined score list. It averages the scores. It writes overall_feedback with language, depth, clarity, and the average out of 10. Then we fan out from START, wait for all three evaluators, and go to END.

Reducer and graph

def reducer(state: State) -> dict:
    scores = state["individual_score"]
    average_score = sum(scores) / len(scores)

    overall_feedback = f"""
LANGUAGE:
{state["language_feedback"]}

DEPTH / ANALYSIS:
{state["analysis_feedback"]}

CLARITY:
{state["clarity_feedback"]}

AVERAGE SCORE:
{average_score:.2f}/10
"""
    return {
        "overall_feedback": overall_feedback
    }

builder = StateGraph(State)
builder.add_node("language_evaluation", language_evaluation)
builder.add_node("analysis_evaluation", analysis_evaluation)
builder.add_node("clarity_evaluation", clarity_evaluation)
builder.add_node("reducer", reducer)

builder.add_edge(START, "language_evaluation")
builder.add_edge(START, "analysis_evaluation")
builder.add_edge(START, "clarity_evaluation")

builder.add_edge(
    [
        "language_evaluation",
        "analysis_evaluation",
        "clarity_evaluation",
    ],
    "reducer"
)
builder.add_edge("reducer", END)

graph = builder.compile()

data = {
    "essay": """
    Artificial intelligence is changing the way humans work.
    It can automate repetitive tasks and help people analyze
    large amounts of information. However, AI also introduces
    ethical concerns such as bias, privacy, and job displacement.
    Society must therefore develop responsible ways of using AI.
    """,
    "individual_score": []
}

result = graph.invoke(data)

print("\n--- LANGUAGE ---")
print(result["language_feedback"])
print("\n--- ANALYSIS ---")
print(result["analysis_feedback"])
print("\n--- CLARITY ---")
print(result["clarity_feedback"])
print("\n--- SCORES ---")
print(result["individual_score"])
print("\n--- OVERALL ---")
print(result["overall_feedback"])

The printed feedback and scores come from the model. We do not paste a fake essay grade here. Run the cell to see yours. individual_score should be a list of three ints after the merge.

Day 51 takeaways

Day 51 takeaways

  • A parallel workflow fans out from START, then waits for every branch before the next node.
  • The cricket graph computes strike rate, ball percentage, and boundary percentage together, then summarises.
  • For 100 runs, 100 balls, 10 fours, and 10 sixes, sr is 100.0, bpb is 20.0, and boundary percentage is 100.0.
  • A list on add_edge means wait for all those nodes.
  • The Loksewa essay graph sends language, analysis, and clarity to three LLMs. Each returns feedback and a score from 0 to 10 via structured output.
  • operator.add on individual_score merges the three score lists. Start that field as an empty list. The reducer node then averages and writes overall_feedback.
