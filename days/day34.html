Why LLMs Sometimes Fail

LLMs changed AI. They have huge numbers of parameters. We pre train them on huge amounts of data, often across much of the public internet. That world knowledge lives inside the parameters. More parameters often means a stronger model.

The basic path is simple. You send a prompt. That prompt is your query. The model replies.

Basic LLM path

  1. Query Your prompt.
  2. LLM Uses stored parameters.
  3. Response The answer comes back.

But there are three common cases where the model fails or goes wrong.

Private data

Ask about your company salary file or a private PDF. The model never saw that data in training.

Knowledge cutoff

Ask for the latest news from Kathmandu. Many open source LLMs stop at a fixed date. Chatbots with web tools can fetch live info. Plain LLMs often cannot.

Hallucination

The model sometimes answers with high confidence even when it is guessing. It invents details that sound right but are wrong.

395

One Fix: Fine Tuning

Can we solve those three problems. Yes. One path is fine tuning.

Fine tuning means you take a pre trained LLM and train it a bit more on task related domain data. You build a smaller labeled set, train, and then the model can answer domain questions better.

Here is a simple story. A student in engineering already learned English, CS, microprocessors, and math. That is like pre training. When the student joins a company and learns how that company works, that is like fine tuning.

Story piece ML meaning
Student The LLM.
School courses Pre training on broad knowledge.
Company training Fine tuning on domain knowledge.
396

Fine Tuning Methods in Brief

There are several fine tuning styles. This is only a short map, not a deep course.

Supervised fine tuning

You give labeled pairs. Prompt goes in. Desired output is the label.

Continued pre training

Unsupervised. You feed raw domain text with no labels so the model absorbs the style and facts.

RLHF

Reinforcement learning with human feedback. Humans rank answers to steer the model.

LoRA and QLoRA

Lighter ways to fine tune. You update small adapter weights instead of every parameter.

For many domain chatbots, people start with supervised fine tuning.

Supervised fine tuning steps

  1. Collect data Labeled prompt and desired output pairs.
  2. Choose a method Full parameters, LoRA, or QLoRA.
  3. Train Run for a few epochs.
  4. Evaluate Test quality and safety.

How can fine tuning help the three failure cases.

  • Private data. Train on that private set so the model learns it.
  • Fresh facts. Retrain with newer data so knowledge moves forward.
  • Hallucination. Teach the model to say I do not know when the facts are weak, instead of inventing an answer.
397

Problems With Fine Tuning

Fine tuning helps, but it has heavy costs.

Expensive compute

Even with a smaller data set, large models need big GPUs and money.

Needs expertise

Training, eval, and safety checks take skill and time.

Hard to keep fresh

When facts change every day, you must fine tune again and again. Removing old facts also needs more training.

Fine tuning is a poor fit when new information changes very fast.

In Context Learning

Is there another technique. Yes. In context learning.

You put examples inside the prompt itself. For example you can write this is good equals positive, and hate it equals negative. That style is called few shot prompting.

In context learning is an emergent ability. As LLMs grew larger, this behavior showed up. The model can learn a pattern from examples in the prompt without changing its weights.

The learning ladder

  1. Pre training Broad knowledge in weights.
  2. Fine tuning Domain knowledge in weights.
  3. Examples in prompt Few shot in context learning.

Now push the idea one step further. Instead of sending small examples, send the whole useful context needed to answer.

Imagine you are reading a paper and get stuck. You ask a question and also paste the paper text. You are not teaching with tiny examples. You are giving the facts the model needs right now. That idea leads to RAG.

399

What Is RAG

RAG means Retrieval Augmented Generation. You make the model smarter by giving it extra knowledge at the moment you ask the question.

RAG joins information retrieval with text generation.

RAG in one line

  1. Query Your question.
  2. Context Retrieved external knowledge.
  3. Prompt Query and context joined.
  4. LLM Writes from that prompt.
  5. Response The final answer.

A common system prompt sounds like this. You are an assistant. Answer only from the given context. If the answer is not there, say I do not know.

RAG is usually much cheaper than fine tuning, because you add knowledge at ask time instead of retraining weights every time facts change.

Four Steps of RAG

RAG has four big steps. Indexing builds the knowledge base. Retrieval finds the useful pieces. Augmentation joins context with the query. Generation lets the LLM write the answer.

The diagram below shows both paths. First prepare the store. Then answer a live query.

At ask time, the query also goes through the same embedding model. Semantic search needs a query vector, not raw text.

Indexing

Prepare the external knowledge base so search is fast at query time.

Retrieval

Find only the chunks that matter for this query.

Augmentation

Combine context and query into one prompt.

Generation

The LLM writes the response from that prompt.

401

Indexing in Detail

Indexing is the process of preparing the knowledge base. The context in the prompt comes from that external base. Good indexing makes search effective when a user asks a question.

Indexing has four sub steps. You already studied each one on earlier days.

Indexing sub steps

  1. Document ingestion Load sources into memory with a document loader.
  2. Text chunking Split large docs. LLMs cannot take huge prompts, and search works better on smaller pieces.
  3. Embedding Turn each chunk into a dense vector that captures meaning.
  4. Vector store Save the vector with the original chunk and metadata. Chroma and Pinecone are options.

After indexing, that vector store is your external knowledge base.

402

Retrieval in Detail

Retrieval is a real time step. Among all stored chunks, which ones are the best context for this query.

You send the query to a retriever. The retriever finds the most relevant pieces from the pre built index.

Retriever steps

  1. Embed the query Same embedding model as the chunks. Query text becomes a query vector.
  2. Semantic search Compare the query vector to stored chunk vectors. Methods like MMR can help.
  3. Rank Order the hits by relevance.
  4. Fetch top results Those chunks become the context.
403

Augmentation and Generation

Augmentation is the join step. You take the retrieved context and the user query and build one prompt.

Generation is the last step. You send that prompt to an LLM. The model writes the response from the context you gave it.

Step What happens
Augmentation Query plus context becomes the prompt.
Generation LLM reads the prompt and writes the answer.

Compared with fine tuning, RAG usually costs less. You update knowledge by changing the store, not by retraining the whole model every time.

Day 34 takeaways

Day 34 takeaways

  • LLMs fail on private data, knowledge cutoff, and hallucination.
  • Fine tuning can help, but it is costly and hard to keep up to date.
  • In context learning puts examples in the prompt. RAG puts full useful context in the prompt.
  • RAG means retrieval plus generation. Query plus context becomes the prompt for the LLM.
  • The four steps are indexing, retrieval, augmentation, and generation.
