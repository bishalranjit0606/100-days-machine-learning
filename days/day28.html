Why LangChain Needed One Easy Path

Around 2022, chatbots and public LLM APIs became widely available.

The LangChain team saw that many LLMs would power real apps: chatbots, PDF readers, agents, and more. That demand is strong now in 2026.

They wanted one easy way for developers to use many models, such as OpenAI, Anthropic, and Gemini, without rewriting everything for each provider.

382

Apps Need More Than One LLM Call

Calling an LLM alone is not enough. A PDF reader shows how many steps sit around the model.

PDF reader path

  1. Load PDF Bring the file in.
  2. Split Break text into parts.
  3. Embed Turn parts into vectors.
  4. Store Keep vectors ready.
  5. Retrieve Find useful chunks.
  6. LLM Write the answer.
  7. Parse Shape the response.

Each step needs a component. Prompts show up almost everywhere: chatbots, PDF apps, and agents all send a prompt to an LLM.

383

Too Many Special Chains

To help, LangChain shipped many ready made chains. Experts could move faster. Examples included LLMChain, retrieval QA, router chains, and SQL database chains.

That created a new problem.

Huge codebase

Each use case got its own special chain.

Steep learning curve

New learners struggled to pick the right chain.

No shared connect rule

Components did not snap together the same way.

The team wanted Lego style pieces. Instead, every new use case needed another special chain. That is the mistake Runnable was built to fix.

384

What Is a Runnable

A Runnable is one unit of work.

One Runnable

  1. Input in You give it data.
  2. Process It does its job.
  3. Output out You get a result.

Every Runnable shares the same interface. One common call you will see often is invoke.

385

Connect Runnables Like Lego

Because every piece uses the same interface, you can connect them. The output of one becomes the input of the next.

Three Runnables in a line

  1. r1 Takes input, gives output.
  2. r2 Uses r1 output as input.
  3. r3 Uses r2 output as input.

Think of Lego. Each block has a job. Every block has the same dots, so any block can snap to another.

386

A Chain Is Still a Runnable

Here is the key idea. Once you connect Runnables into a workflow, that whole workflow is itself a Runnable.

Small builds join into bigger builds

  1. Workflow A r1 to r2 to r3 as one unit.
  2. Workflow B r4 to r5 as one unit.
  3. Bigger build Snap A and B together.

Like Lego again: build a wheel set, build a car body, then join both into one car. Small builds become bigger builds.

Day 28 takeaways

Day 28 takeaways

  • Runnable exists so every piece shares one connect standard.
  • A Runnable is one unit of work: input in, process, output out.
  • Same interface means you can line pieces up: r1 to r2 to r3.
  • A connected workflow is itself a Runnable, so workflows can connect again.
  • Lego is the metaphor: same dots, snap together, small builds join into bigger builds.
