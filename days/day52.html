Conditional Workflow in LangGraph

Sequential is a line. Parallel takes every branch. Conditional looks branched, but we pick only one path. We build a quadratic graph, then a customer review graph.

687

What Is Conditional

Today we learn about the conditional workflow. It looks like a parallel workflow. It has branches like parallel. But we do not go to every branch. We only choose one branch. The example is an if else condition, or a switch. We choose based on a condition. There might be more than one branch.

We will make two workflows. One is a non LLM workflow. One is an LLM based customer workflow.

688

Quadratic Equation Workflow

A quadratic equation is a times x squared plus b times x plus c equals 0. It has two roots. We find the discriminant. That is b squared minus 4 a c. Call it d. If d is greater than 0, two real roots. If d equals 0, one real root, also called a repeated root. If d is less than 0, no real roots.

The path is START, show equation, calculate discriminant, then one of three possibilities: no real root, real roots, or repeated root. Then END. The diagram below is that graph. Only one of the three result boxes runs.

689

State Equation and Discriminant

State holds a, b, c, the equation string, the discriminant, and the result. show_equation writes the equation text. calculate_discriminant writes b squared minus 4 a c.

State and first two nodes

from langgraph.graph import StateGraph, START, END
from typing import TypedDict, Literal

class State(TypedDict):
    a: float
    b: float
    c: float
    equation: str
    discriminant: float
    result: str

def show_equation(state: State):
    return {
        "equation": f"{state['a']}x^2 + {state['b']}x + {state['c']} = 0"
    }

def calculate_discriminant(state: State):
    return {
        "discriminant": state["b"] ** 2 - 4 * state["a"] * state["c"]
    }

Literal later tells the router which node name it may return.

690

The Router and Three Results

check_discriminant is not a normal node. It is the condition. It returns a string: real_root, repeated_root, or no_real_root. Each result node writes one result string. add_conditional_edges maps those strings to node names. Then every result node goes to END.

Router, nodes, edges

def check_discriminant(
    state: State,
) -> Literal["real_root", "repeated_root", "no_real_root"]:
    if state["discriminant"] > 0:
        return "real_root"
    elif state["discriminant"] == 0:
        return "repeated_root"
    else:
        return "no_real_root"

def no_real_root(state: State):
    return {"result": "No real root"}

def real_root(state: State):
    return {"result": "Two real roots"}

def repeated_root(state: State):
    return {"result": "Repeated root"}

graph_builder = StateGraph(State)
graph_builder.add_node("show_equation", show_equation)
graph_builder.add_node("calculate_discriminant", calculate_discriminant)
graph_builder.add_node("no_real_root", no_real_root)
graph_builder.add_node("real_root", real_root)
graph_builder.add_node("repeated_root", repeated_root)

graph_builder.add_edge(START, "show_equation")
graph_builder.add_edge("show_equation", "calculate_discriminant")

graph_builder.add_conditional_edges(
    "calculate_discriminant",
    check_discriminant,
    {
        "real_root": "real_root",
        "repeated_root": "repeated_root",
        "no_real_root": "no_real_root"
    }
)

graph_builder.add_edge("no_real_root", END)
graph_builder.add_edge("real_root", END)
graph_builder.add_edge("repeated_root", END)

graph = graph_builder.compile()

Only the mapped node for the returned string runs. The other two result nodes stay idle.

Run the Quadratic Graph

We invoke with a 1, b 2, and c 1. Discriminant is 2 squared minus 4 times 1 times 1, which is 0. The output below is from this same code. The chosen branch is repeated_root.

Invoke

result = graph.invoke({
    "a": 1,
    "b": 2,
    "c": 1
})

print(result)

Output

{'a': 1, 'b': 2, 'c': 1, 'equation': '1x^2 + 2x + 1 = 0', 'discriminant': 0, 'result': 'Repeated root'}

Because d equals 0, the router returns repeated_root. real_root and no_real_root do not run.

Customer Review Workflow

Now the LLM based workflow. START finds sentiment with an LLM. If positive, write a positive reply with the LLM, then END. If negative, run diagnosis with the LLM, then write a negative response with the LLM, then END. The diagram below is that split. Only one side runs.

693

Find Sentiment

SentimentSchema forces the model to return only positive or negative. ReviewState holds review, sentiment, diagnosis, and response. find_sentiment calls the structured model. route_sentiment returns positive_response if sentiment is positive, otherwise diagnosis.

Schema, state, find, route

from langchain_openrouter import ChatOpenRouter
from langgraph.graph import StateGraph, START, END
from pydantic import BaseModel, Field
from typing import Literal
from typing_extensions import TypedDict
from dotenv import load_dotenv

load_dotenv()

model = ChatOpenRouter(
    model="openrouter/free",
    temperature=0
)

review = """
I had a great experience with the product.
The quality was excellent and the customer service was outstanding.
I would definitely recommend this to my friends and family.
"""

class SentimentSchema(BaseModel):
    sentiment: Literal["positive", "negative"] = Field(
        description="The sentiment of the customer review"
    )

structured_model = model.with_structured_output(SentimentSchema)

class ReviewState(TypedDict):
    review: str
    sentiment: str
    diagnosis: str
    response: str

def find_sentiment(state: ReviewState):
    result = structured_model.invoke(
        f"""
        Analyze the sentiment of the following customer review.

        Review:
        {state["review"]}

        Classify it as positive or negative.
        """
    )
    return {
        "sentiment": result.sentiment
    }

def route_sentiment(
    state: ReviewState
) -> Literal["positive_response", "diagnosis"]:
    if state["sentiment"] == "positive":
        return "positive_response"
    return "diagnosis"

The sample review is a happy one. The negative path still exists in the graph for other reviews.

694

Positive and Negative Paths

positive_response thanks the customer. diagnosis names the main problem, why the customer is unhappy, and what the company should do. negative_response uses that diagnosis to acknowledge, show empathy, apologize, and say the issue will be addressed, without unrealistic promises. diagnosis then goes to negative_response. positive_response goes straight to END.

Nodes, edges, invoke

def positive_response(state: ReviewState):
    result = model.invoke(
        f"""
        You are a professional customer support representative.

        The customer left a positive review.

        Review:
        {state["review"]}

        Write a short, warm and professional response thanking
        the customer for their feedback.
        """
    )
    return {
        "response": result.content
    }

def diagnosis(state: ReviewState):
    result = model.invoke(
        f"""
        You are a customer experience specialist.

        Analyze the following negative customer review.

        Review:
        {state["review"]}

        Identify:
        1. The main problem
        2. Why the customer is unhappy
        3. What the company should do to resolve it

        Keep the diagnosis concise.
        """
    )
    return {
        "diagnosis": result.content
    }

def negative_response(state: ReviewState):
    result = model.invoke(
        f"""
        You are a professional customer support representative.

        Customer review:
        {state["review"]}

        Internal diagnosis:
        {state["diagnosis"]}

        Write a professional response to the customer.

        The response should:
        1. Acknowledge the problem
        2. Show empathy
        3. Apologize appropriately
        4. Mention that the issue will be addressed
        5. Avoid making unrealistic promises

        Keep the response concise and natural.
        """
    )
    return {
        "response": result.content
    }

graph_builder = StateGraph(ReviewState)
graph_builder.add_node("find_sentiment", find_sentiment)
graph_builder.add_node("positive_response", positive_response)
graph_builder.add_node("diagnosis", diagnosis)
graph_builder.add_node("negative_response", negative_response)

graph_builder.add_edge(START, "find_sentiment")
graph_builder.add_conditional_edges(
    "find_sentiment",
    route_sentiment,
    {
        "positive_response": "positive_response",
        "diagnosis": "diagnosis"
    }
)
graph_builder.add_edge("positive_response", END)
graph_builder.add_edge("diagnosis", "negative_response")
graph_builder.add_edge("negative_response", END)

graph = graph_builder.compile()

result = graph.invoke({
    "review": review
})

print("Sentiment:")
print(result["sentiment"])
print("\nDiagnosis:")
print(result.get("diagnosis", "Not required"))
print("\nResponse:")
print(result["response"])

print shows sentiment, diagnosis if it exists, and the reply. Those strings come from the model, so we do not paste a fake reply here. Run the cell to see yours. If diagnosis never ran, get prints the fallback Not required.

Day 52 takeaways

Day 52 takeaways

  • Sequential is a line. Parallel runs every branch. Conditional has branches but chooses only one, like if else or a switch.
  • add_conditional_edges needs a router function that returns a node name, plus a map from those names to nodes.
  • The quadratic graph shows the equation, computes d equals b squared minus 4 a c, then picks two real roots, a repeated root, or no real root.
  • For a 1, b 2, c 1, d is 0, so result is Repeated root.
  • The customer graph classifies sentiment as positive or negative. Positive goes to a thank you. Negative goes to diagnosis, then a careful reply.
