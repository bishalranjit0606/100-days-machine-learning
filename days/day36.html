What an LLM Can and Cannot Do

An LLM is a powerful NLP system. It can think and reason. It can generate language word by word.

Picture a human with a brain and a mouth, but no hands. The model can talk through a problem. It cannot do the real world work by itself.

Thinking

Reason about a question and plan steps.

Language

Write answers, summaries, and code text.

No hands

It cannot buy a flight ticket, touch live systems, or run your app alone.

Ask it to find a cheap flight. It may describe options. It cannot complete the purchase for you without tools.

463

Hard Limits Without Tools

On its own, the LLM hits clear walls.

Live data

It cannot fetch fresh news, prices, or weather by itself.

Complex math

Hard calculations are unreliable in plain generation.

Code and databases

It cannot run code, query a DB, or call your APIs alone.

Tools give the model a way to reach those systems when the task needs them.

464

What Is a Tool

A tool is Python code, a function or an API wrapper, that the LLM can understand and call when needed.

There are two big types.

Type When you use it
Built in tools Common jobs with little or no setup. Search, Wikipedia, shell, email helpers, and more.
Custom tools Your own API, business logic, database, product, or app.

Built in tools are production ready pieces from LangChain. Custom tools are what you write for your domain.

465

How Tools Relate to Agents

An AI agent can finish a task by thinking and then executing actions.

Agent split

  1. Thinking The LLM decides what to do next.
  2. Action Tools run the real work.
  3. Loop Results feed back into the next thought.

Without tools, an agent can only talk. With tools, it can search, compute, send mail, or hit your APIs.

Shell Tool

ShellTool runs a command on the host and returns the text output. Use it only in safe sandboxes you control.

ShellTool whoami

!pip install -U langchain-experimental

from langchain_community.tools import ShellTool

shell_tool = ShellTool()
result = shell_tool.invoke("whoami")
print(result)

What you get

The current user name for that machine,
for example your login name.
Exact text depends on the OS user.

Do not expose ShellTool to untrusted users. It can run any command the process is allowed to run.

When to Make a Custom Tool

Build a custom tool when built in options are not enough.

Your API

Call an endpoint that only your product owns.

Business logic

Wrap rules the LLM should not invent.

DB or app

Let the model talk to your database or app safely.

LangChain gives three common ways to create a tool. We walk through each one.

470

Three Ways to Build a Tool

Pick the style that matches how much control you need.

Method Best for
@tool decorator Fastest path. Turn a typed function into a tool.
StructuredTool Explicit name, description, and Pydantic input schema.
BaseTool class Full control with a custom class and _run method.

All three produce a tool you can invoke the same way. The difference is how you define the schema and logic.

471

Method 1: The @tool Decorator

Start with a normal function. Add type hints. Write a clear docstring so the LLM knows what the tool does. Then put @tool on top.

Three steps

  1. Function Write the Python logic.
  2. Type hints Annotate args and return type.
  3. @tool Decorator turns it into a tool.

@tool multiply

from langchain_core.tools import tool

@tool
def multiply(a: int, b: int) -> int:
    """Multiply two numbers."""
    return a * b

result = multiply.invoke({"a": 3, "b": 2})
print(result)

print(multiply.name)
print(multiply.description)
print(multiply.args)
print(multiply.args_schema.model_json_schema())

What you get

6
multiply
Multiply two numbers.
{'a': {'type': 'integer'}, 'b': {'type': 'integer'}}
# plus a JSON schema from model_json_schema()

The docstring is highly recommended. Future tool calling uses that text to decide when to call the tool.

472

Method 2: StructuredTool and Pydantic

A StructuredTool is a tool whose inputs follow a strict schema, usually a Pydantic model. You define the schema, the function, then wrap them with from_function.

StructuredTool add

from pydantic import BaseModel, Field
from langchain_core.tools import StructuredTool

class AddInput(BaseModel):
    a: int = Field(description="The first number")
    b: int = Field(description="The second number")

def add_func(a: int, b: int) -> int:
    return a + b

add_tool = StructuredTool.from_function(
    func=add_func,
    name="add",
    description="Adds two numbers together",
    args_schema=AddInput,
)

result = add_tool.invoke({"a": 5, "b": 10})
print(result)

What you get

15

Field descriptions help the model fill a and b correctly when it calls the tool.

473

Method 3: BaseTool

For full control, subclass BaseTool. Set name, description, and args_schema. Put the work in _run.

BaseTool subtraction

from typing import Type
from pydantic import BaseModel, Field
from langchain_core.tools import BaseTool

class SubInput(BaseModel):
    a: int = Field(description="The number to subtract from")
    b: int = Field(description="The number to subtract")

class SubTool(BaseTool):
    name: str = "subtraction_tool"
    description: str = "Subtracts b from a"
    args_schema: Type[BaseModel] = SubInput

    def _run(self, a: int, b: int) -> int:
        """Synchronous execution logic."""
        return a - b

sub_tool = SubTool()
result = sub_tool.invoke({"a": 10, "b": 4})
print(result)

What you get

6

Use this style when you need class level state, custom validation, or more than a simple function wrap.

Toolkits

A toolkit is a collection of related tools that share one purpose. You package them together for convenience and reuse. Google Drive style toolkits are a common example.

You can make a small custom toolkit the same way. Hold tools in a class and return them from get_tools.

Simple MathToolkit

from langchain_core.tools import tool

@tool
def add(a: int, b: int) -> int:
    """Add two numbers."""
    return a + b

@tool
def multiply(a: int, b: int) -> int:
    """Multiply two numbers."""
    return a * b

class MathToolkit:
    def get_tools(self):
        return [add, multiply]

toolkit = MathToolkit()
tools = toolkit.get_tools()
print([t.name for t in tools])

What you get

['add', 'multiply']

Agents often take a list of tools. A toolkit is a clean way to hand that list over.

Day 36 takeaways

Day 36 takeaways

  • An LLM can think and write, but it needs tools to act in the real world.
  • A tool is a function or API the model can call when needed.
  • Use built in tools for common jobs. Build custom tools for your API, logic, or database.
  • Create custom tools with @tool, StructuredTool, or a BaseTool subclass.
  • A toolkit groups related tools so agents can reuse them as one set.
