Begin with Day 1 — Introduction to ML

Day 1

Introduction to ML

1

What is Machine Learning?

Machine learning means learning from data. In traditional programming, we write code for every possible outcome — the program produces the output directly.

In machine learning, we do not write every rule. The relationship looks like this:

  • Traditional programming: data + program = output.
  • Machine learning: data + output = pattern.

Or simply: ML = data + algorithm → pattern.

Typical ML workflow.

  1. Question Define the problem.
  2. Data Collect examples.
  3. Train Fit a model.
  4. Evaluate Check performance.
  5. Iterate Improve and repeat.
2

Traditional Programming vs Machine Learning

In traditional programming, you explicitly encode logic. The computer follows your instructions step by step.

In ML, you provide examples and let the system discover the rules. The algorithm generalizes from what it has seen to handle new cases it was never explicitly programmed for.

3

Learning Patterns from Examples

Traditional programming example:

  • 2 + 2 gives 4.
  • 2 + 3 gives 5.

You hard-code each case. In machine learning, you give thousands of addition examples. The model recognizes the pattern of addition — so even with 3- or 4-digit numbers it can answer correctly without you writing rules for every length.

4

Why Rules Break: Spam Detection

In traditional programming you might write:

If an email has words like "big" or "discount", classify it as spam.

Companies can change wording — "big" to "huge", "discount" to "offer" — and brittle rules fail. ML recognizes underlying patterns in language instead of matching fixed keywords.

5

Scale and Learning Over Time

ML learns from data over time. The bigger and more representative the dataset, the better the model can generalize — as long as the data quality stays high.

6

Data Mining and Applications

Data mining extracts useful information from large datasets. Machine learning supplies the patterns; data mining turns those patterns into actionable insight for business, science, and product decisions.

Day 1 takeaways

  • ML learns patterns from data instead of hand-written rules.
  • Traditional code maps inputs to outputs; ML maps data + labels to a reusable model.
  • More quality data usually means better generalization.
Day 2

AI vs ML vs Deep Learning

7

Artificial Intelligence Overview

AI (Artificial Intelligence) is a broad term. It can include simple if/else rule systems — also called symbolic AI or expert systems.

Expert systems encode knowledge from human specialists (e.g. a chess master) into explicit rules. They work well for narrow, well-defined problems but struggle with noisy, real-world data.

8

Expert Systems & Symbolic AI

An expert system captures domain knowledge as rules. It excels at chess-like domains with clear logic but does not adapt when data is fuzzy or constantly changing.

9

Machine Learning with Fuzzy Data

ML works with fuzzy, messy data. You do not hand-write every rule — the model finds statistical patterns using math and optimization.

Concept Simple meaning Use when
AI Any system that mimics intelligent behavior You need broad automation or reasoning frameworks
ML Learns patterns from data without explicit rules You have labeled or unlabeled examples and fuzzy inputs
Deep Learning ML with neural networks that learn features automatically You have very large datasets and complex perception tasks
10

Deep Learning

Deep learning is a subset of machine learning inspired by biology (neural networks). In classic ML you often define features manually — e.g. for cats vs dogs: ears up, long tail.

Deep learning discovers features automatically. It shines on very large datasets and complex inputs (images, audio, text). For many everyday problems, traditional ML is still the practical choice.

Day 2 takeaways

  • AI is the umbrella; ML learns from data; deep learning learns representations with neural nets.
  • Expert systems use explicit rules; ML handles fuzzy real-world data.
  • Choose deep learning when data scale and complexity justify it.
Day 3

Types of Machine Learning

11

Supervised Learning

In supervised learning, you have both input and output (labels). The model learns the mapping between them.

  • Supervised.

    Input + known output; learns mapping.

  • Unsupervised.

    Input only; finds structure.

  • Semi-supervised.

    Mix of labeled and unlabeled data.

  • Reinforcement.

    Agent learns via rewards and mistakes.

  • Feature.

    Measurable input attribute (e.g. CGPA).

  • Label.

    Target output you want to predict.

12

Regression

Regression — both input and output are numeric. Used for prediction.

Example: Input: IA = 99, CGPA = 7.5 → Output: Package = 14 lakh.

13

Classification

Classification — input can be numeric, but output is a category or decision.

Examples:

  • Will rain happen or not?
  • Input: IA = 99, CGPA = 7.5 → Output: Placement = Yes.
14

Unsupervised Learning

In unsupervised learning, you only have input — no output labels. Common goals: grouping similar items or simplifying high-dimensional data.

Example: Student records grouped into high-IQ vs low-IQ clusters without predefined labels.

15

Clustering & Dimensionality Reduction

Clustering — categorize items into groups (e.g. customer segments).

Dimensionality reduction — compress many columns into fewer meaningful ones. Example: combine separate "room" and "washroom" features into one housing-quality score.

16

Anomaly Detection & Association Rules

Anomaly detection — find fraud or unusual events (email fraud, manufacturing defects).

Association rule learning — discover patterns for recommendations (e.g. bread buyers often buy eggs).

17

Semi-Supervised Learning

Semi-supervised learning blends supervised and unsupervised approaches. Labeling data is expensive — it takes time, money, and expertise.

You label only some examples (e.g. "dad", "mom" in photos) and let the model propagate labels to similar unlabeled data.

18

Reinforcement Learning

In reinforcement learning, an agent starts from scratch and learns through trial and error. Rewards and penalties shape behavior.

Example: An AI agent moves near fire → points decrease → next time it avoids fire.

Day 3 takeaways

  • Supervised: labeled data maps to regression or classification.
  • Unsupervised: find groups, reduce dimensions, detect anomalies, or mine associations.
  • Semi supervised and reinforcement learning cover label scarce and interactive settings.
Day 4

Batch Machine Learning

19

Batch vs Online ML in Production

This is another way to group machine learning: how the model is trained in production.

We care about this because most real projects end on a server. The training style affects cost, speed, and how fresh the model stays.

Two main styles: batch learning (also called offline learning) and online learning.

20

What Is Batch Learning

Batch learning is also known as offline ML.

You use all available data to train the model in one go. There is no incremental training during normal operation.

Data is often huge. Training with all data directly on the live server is expensive. That is why teams usually train on a separate offline machine, then move the finished model to the server.

21

Train Offline, Deploy to the Server

The usual batch flow:

Batch workflow.

  1. Data Collect full dataset.
  2. Model Train offline.
  3. Test Check quality.
  4. Server Deploy model.

Training stays off the production server. Only the trained model runs live.

22

Static Models and Retraining

Problem with batch models: knowledge stays static. What the model learned at training time does not change until you retrain.

Example: Netflix keeps adding movies. An old model that never updates will get worse at recommendations.

Fix: retrain on a schedule. Use new data plus the previous model, train again, and deploy the updated model. Teams often retrain daily or weekly.

Batch learning in practice: train on a large offline dataset, deploy to the server, and repeat on a cycle.

23

Disadvantages of Batch Learning

  • Scale limits: very large data may not fit your tools or hardware. Training can fail.
  • Connectivity: without a good link, moving data or a new model to the server is hard.
  • Freshness: on social feeds, batch updates can feel slow. New posts might show up only after the next batch run (for example once every 24 hours).

Day 4 takeaways

  • Batch = train on all data offline, then deploy.
  • Models go stale; retrain on a schedule.
  • Watch data size, hardware, and how fresh users need results.
Day 5

Online Machine Learning

24

What Is Online Learning

If you have heard that the more you use a product, the better it gets, that is often online ML.

Online learning trains incrementally. You feed the model small batches over time. Each batch can make the model a bit smarter.

Because updates are small, training can happen on the server while the product is live. Online learning is popular today.

25

Incremental Training on the Server

Online flow in simple steps:

small data → ML → test → server.

The server keeps receiving new data. The model learns from each new small batch on the server itself.

This is different from batch learning, where training usually happens offline in one big run.

26

Real World Examples

  • Voice assistants (Alexa, Google): learn from chat and usage on the server.
  • Keyboards: the more you type, the more personalized suggestions become.
  • YouTube: real time style recommendations as you watch and click.
27

When to Use Batch vs Online

The key idea is concept drift: when the world or user behavior changes fast, the old model stops fitting.

Use online learning when patterns shift quickly (stocks, sales, ecommerce, fast moving feeds).

Online learning can also help with speed and sometimes cost for continuous small updates.

Use batch learning when patterns are mostly stable and you are fine retraining on a schedule.

Situation Simple meaning Use when
Concept drift Data patterns change fast Prefer online learning
Stable patterns World changes slowly Batch learning can work
Production ease How hard to run live Batch is easier; online is harder
28

Learning Rate

Learning rate controls how strongly each new batch updates the model.

Too fast: the model may forget old good patterns. Too slow: it may not adapt to new trends.

Picking a good learning rate is one of the hardest parts of online learning.

Libraries: scikit learn (batch friendly by default), River, Vowpal Wabbit for online style workflows.

29

Out of Core Learning

When data is too big to load at once, we use out of core learning.

Split huge data into small chunks, train step by step, test, and serve on the server.

big data → small chunks → model → test → server.

Online style training fits this pattern well.

30

Risks and Monitoring

Online learning is powerful but risky.

  • Tricky to set up and tune compared with batch.
  • If the server is hacked or flooded with spam data, attackers could poison what the model learns.

You need a monitoring system to detect bad inputs. If attack or bad data appears, you must be able to roll back and pause online updates until it is safe.

31

Online vs Offline and Tools

  • Offline (batch): simpler to reason about; strong local machines for big training jobs.
  • Online: more complex in production; needs strong server compute and good monitoring.
  • Application rule: mostly stable data → batch can work. Fast changing context → online fits better.

Tools (examples from notes):

  • Batch: Spark, TensorFlow, PyTorch.
  • Online: Storm, MOA, scikit-multiflow.

Day 5 takeaways

  • Online = small incremental updates on the server.
  • Use online when concept drift is high; batch when patterns are stable.
  • Guard online systems with monitoring and rollback.
Day 6

Instance Based vs Model Based

32

Instance Based vs Model Based Learning

Another way to group ML: instance based vs model based learning.

As you learn more algorithms later, you should be able to tell which family each one belongs to.

33

Memorize vs Generalize

The simplest way to learn is to remember everything, like pure memorization.

A better way is to generalize: learn the concept behind the examples.

Example from school: in chemistry we often memorize facts. In physics we learn concepts and apply them to new problems.

Machine learning follows the same idea. Instance based methods lean toward remembering similar past cases. Model based methods lean toward learning a rule or formula.

34

Instance Based Learning

Sample data:

IQ CGPA Placement
80. 8. Yes.
70. 7. No.

New student: IQ 7.5, CGPA 10.3. Will they get placement?

We have not built a traditional model. We look for similarity. Similarity is measured by distance between points.

We do not train a model in the usual sense. We react to the data when a new point arrives.

35

KNN Example

Pick the nearest points, for example the 3 closest students in the table.

If most of those neighbors say yes for placement, we predict yes for the new student.

This method is KNN (K Nearest Neighbors). It is a classic instance based algorithm.

There are fewer instance based algorithms than model based ones.

36

Model Based Learning

With the same placement data, a model based approach tries to understand how the data behaves overall.

Think of a graph with two regions. Points in one region mean fail, points in the other mean pass. The model learns a boundary between them.

It finds a math link between input and output. That link is the decision function. It can classify any new point that arrives.

Even if we delete the old training rows, we can still keep the decision function and score new points.

Examples: linear regression, decision tree, and many other model based algorithms.

A model is often just a set of parameters. In linear regression, parameters include slope and intercept. The model is stored in a compact form with rules inside it.

37

Comparing Both Approaches

Both styles still need prepared data before you use them well.

Topic Instance based Model based
Training No classic training step Build parameters from data
Before scoring No model generated ahead of time Model ready with rules inside
Data at scoring time Needs training data nearby Old data not required once trained
Storage Heavy (keep many examples) Light (store equation or rules)
Nickname Lazy learners Eager learners (train first)

Day 6 takeaways

  • Instance based: compare new points to similar past examples (KNN).
  • Model based: learn a decision function you can reuse without all raw data.
  • Know which type an algorithm is before you pick it for a project.
Day 7

Challenges of Machine Learning

38

Data Collection

If there is no data, there is no point in doing machine learning.

Small projects often use ready datasets (for example Kaggle). In a real company, gathering data is very hard. This is one of the main ML problems.

Common ways to get data.

  1. Open datasets Kaggle, small projects.
  2. API Fetch from services.
  3. Web scraping Pull from websites.
39

Insufficient Labeled Data

Suppose algorithm A is better in theory but has only 100 rows. Algorithm B is weaker but has 1 lakh rows. B often wins in practice because it has more data.

With huge data, which algorithm you pick matters less. In real life we usually have small or medium datasets.

When data or labels are scarce, machine learning becomes much harder.

40

Non Representative Data

If your data covers only part of the real world, your model reflects only that part.

Example: You survey only Spain about who will win the World Cup. Most answers pick Spain, so the model says Spain will win. You needed data from all countries in the tournament.

Watch for sampling noise (random luck in a small sample) and sampling bias (sample does not match the full population).

41

Poor Quality Data

A funny truth: we often spend about 60% of our time cleaning data.

The purer the data, the better the model. Dirty data leads to weak or wrong results no matter how fancy the algorithm is.

42

Irrelevant Features

Garbage in, garbage out. Some columns never help the model.

Example: Predicting a marathon winner from a survey with age, height, weight, and location.

  • Age and weight can matter.
  • Location alone cannot tell you that people from Pokhara will win.
  • Height and weight can be merged into BMI instead of keeping both.
43

Overfitting

The model memorizes training data. It does well on old examples but fails on new ones.

Example: One cinema ticket in Kathmandu costs 120. The model learns that every hall ticket everywhere is 120. That is wrong generalization.

When the model tries to be too accurate on training data only, that is overfitting.

44

Underfitting

The model is too simple or not trained well. It is weak on training data and weak on new data.

Problem What happens Training accuracy
Overfitting Memorizes training, fails on new data Very high (often near 100%)
Underfitting Too simple, misses patterns Low
Good fit Learns real patterns, generalizes Strong but not perfect
45

Software Integration

After you build a model, you must plug it into real software. The ML part must work with the app, APIs, and user flows.

Check compatibility and keep versions aligned. Software integration is often very hard.

Tip: always aim to ship an end to end product, not just a notebook.

46

Deployment and Offline Updates

Once the model is live, data keeps changing. You often retrain offline, test again, then push to the server. That loop is hard to run smoothly.

Deployment is one of the toughest steps in the ML life cycle.

Cloud platforms like AWS and Azure help, but production ML is still not always stable.

47

Cost and End to End Mindset

When many people use your ML system, cost can grow fast. Hosting on your own server can bring hidden costs (compute, storage, traffic).

Monetizing ML products is also hard.

  • MLOps.

    Deploy and monitor models in production.

  • Cost optimization.

    Control compute and storage spend.

  • Load balancing.

    Handle many users without crashes.

Day 7 takeaways

  • Data collection, quality, and representation come before fancy models.
  • Overfitting and underfitting show why we tune models carefully.
  • Integration, deployment, and cost are why we build end to end products.

Learning ML means learning the full life cycle, not only algorithms.

Day 8

Applications of Machine Learning

48

ML in Everyday Life

Look around and you see AI everywhere: chatbots, movie recommendations, and more. Machine learning is part of daily life.

Many people think ML is only what we use directly as customers. But a lot of it is B2B (business to business). B2B often brings more profit than B2C (business to customer).

A famous line: if you are not paying for the product, you are the product. Our data is what gets sold.

49

Retail

If a retail company does not use ML, that can be a major drawback for sales. Competitors with better insight will move ahead.

We collect sales data and find insight: should we stock this product or not? ML helps decision making in retail.

Stores track buying behavior. They may ask for your phone number first. They learn what you buy, like health products after you join a gym. If you shop at certain supermarkets, your data can be sold for target marketing.

Association rule mining finds relations between products. Example: if people buy milk, they often buy eggs too.

50

Banking

When you apply for a loan, the bank analyzes your profile. It compares you to people who did not pay back. If there is an 80% match, they may not give you the loan.

Other banking uses of ML:

  • Deciding where to open new branches.
  • Stock market analysis.
51

Ride Sharing

In ride sharing apps, the price goes up in some areas. This is surge pricing. It happens when demand is high and drivers are few.

ML helps balance demand and supply so prices and availability make sense.

Example: mango price in Nepal goes high when demand increases. Same idea: more demand, higher price.

52

Manufacturing

Tesla uses automation heavily. Robotic arms build the cars.

Machines do not break all at once. Damage happens gradually. ML helps find problems early using sensor data like heat. This is called predictive maintenance.

How predictive maintenance works.

  1. Sensors Heat, vibration, and more.
  2. ML model Spots early warning signs.
  3. Fix early Before a full breakdown.
53

Social Media

Social media runs on algorithms. ML decides what you see in your feed.

Sentiment analysis is widely used today. It finds what people feel or think from text and posts.

It matters in politics, sports, and anywhere we want to know what a crowd will do or what people are thinking. Chatbots also use these ideas.

  • Retail.

    Stock, pricing, and buying patterns.

  • Banking.

    Loans, branches, and markets.

  • Ride sharing.

    Demand, supply, and surge pricing.

  • Manufacturing.

    Automation and predictive maintenance.

  • Social media.

    Feeds, sentiment, and chatbots.

Day 8 takeaways

  • ML is everywhere, often behind the scenes in B2B products.
  • Five major sectors: retail, banking, ride sharing, manufacturing, and social media.
  • Your data powers many free apps. ML turns that data into decisions.

Knowing where ML is used helps you see real world problems worth solving.

Day 9

Machine Learning Life Cycle

54

What Is MDLC

This day is different from earlier topics. About 90% of what we cover next comes from here.

MDLC means Machine Learning Development Life Cycle. It is similar to SDLC. When we build software, we follow SDLC. MDLC teaches us how to build machine learning from idea to product.

As students we often only train the model. Companies need an end to end product.

MDLC has 9 steps. Most future lessons in this series will grow from these steps. The steps are not fixed forever. They can change. The main idea: build ML end to end.

The 9 steps of MDLC.

  1. Framing Define the problem.
  2. Gather Collect data.
  3. Process Clean and format.
  4. EDA Explore patterns.
  5. Features Engineer and select.
  6. Train Evaluate models.
  7. Deploy Ship to users.
  8. Test Beta and A/B.
  9. Optimize Scale and retrain.
55

Framing the Problem

Step 1 happens before any code. It is our job to find all the important details.

  • Cost: what budget and resources do we have?
  • Supervised or not: do we have labels for training?
  • Algorithm: which approach might fit this problem?
  • Data: how will we get the data we need?

Good framing saves time later. A vague problem leads to a weak product.

56

Gathering the Data

This is one of the most important steps. We rarely get data exactly as we want.

Without data we cannot go further.

Data can come from many sources:

  • API (often JSON).
  • Web scraping.
  • Surveys.
  • Company databases, sometimes built into a data warehouse.
  • Data stored in a cluster.

Bringing data together is a critical stage in the life cycle.

57

Data Processing

Raw data is not clean. It can be noisy. Columns may not match. We must preprocess the data.

Common tasks:

  • Remove duplicates.
  • Handle missing data.
  • Remove outliers.
  • Scale values (one column may be very big, another very small).

The key idea: clean and format the data. This step is also called data preprocessing.

58

Exploratory Data Analysis

EDA means we read the input and output. We experiment with the data before modeling.

We make graphs and study patterns:

  • Univariate: mean, median, and curve of each column alone.
  • Bivariate: relationship between two columns.
  • Multivariate: more than two columns together.

Imbalance: handle unbalanced data. Example: dog vs cat classification where cat images far outnumber dog images.

59

Feature Engineering and Selection

We create new columns or remove useless ones.

Example: a house pricing model has number of rooms and washrooms but not square feet. We may drop those columns because we need square feet to predict price well.

We decide which features to use and when. Good features often matter more than a fancy algorithm.

60

Model Training, Evaluation, and Selection

We try multiple algorithms. Not every algorithm fits every problem.

In evaluation we compare different models. This helps us pick which algorithm to use.

Ensemble learning: join multiple ML models to make a stronger result.

Hyperparameter tuning: adjust settings to improve the model.

This is one of the most important things we do in the life cycle.

61

Model Deployment

Turn the model into real software: website, desktop app, and more.

Typical flow:

train model → save binary file → expose API → return JSON.

The user gives input. The Python app gets the data. The model returns a JSON answer.

We build an end to end website. Platforms like Heroku, GCP, and AWS help host it.

62

What Is a Tensor

A tensor is a data structure. Libraries like scikit learn and TensorFlow use tensors to hold data.

In almost any ML problem today, tensors matter. They support both machine learning and deep learning.

One famous library is even named after it: TensorFlow.

A tensor is a container for numbers. Sometimes we store text too, but 99% of the time it is numbers.

71

Scalar to 5D Tensor

  • 0 dimensions: scalar (0D tensor).
  • 1 dimension: vector (1D tensor).
  • 2 dimensions: matrix (2D tensor).
  • 3 or more dimensions: tensor (3D, 4D, 5D, and so on).

3D tensor: a stack of matrices. It has 3 axes.

4D tensor: a collection of 3D tensors.

5D tensor: a collection of 4D tensors.

In machine learning we often work from 1D up to 5D tensors.

72

Key Terms in Simple Words

These words sound similar. Here is what each one means.

  • Tensor.

    A box that holds numbers in an organized way. A list, table, or stack of tables can all be tensors.

  • Element.

    One single number inside the tensor. The smallest piece. In [1, 2, 3] the elements are 1, 2, and 3.

  • Dimension.

    How many levels the data has. One number = 0D. A list = 1D. A table = 2D. More levels = 3D, 4D, and so on.

  • Rank.

    Same idea as dimension. Rank tells how many axes the tensor has. Rank 0 = scalar, rank 1 = vector, rank 2 = matrix.

  • Axis (axes).

    One direction in the tensor. A table has 2 axes: rows and columns. Axis 0 is usually rows. Axis 1 is usually columns.

  • Shape.

    How many slots sit on each axis. Shape (2, 3) means 2 rows and 3 columns.

  • Size.

    Total number of elements. Multiply the shape numbers. Shape (2, 3) → size = 6.

Quick memory trick: rank and dimension mean the same thing. Axes are the directions. Shape counts slots per direction. Size counts all numbers inside.

Example 1: scalar.

4
  • Tensor: yes (0D tensor).
  • Elements: 1 (just the number 4).
  • Rank / dimension: 0.
  • Axes: none (it is a single point).
  • Shape: ().
  • Size: 1.

Example 2: vector.

[1, 2, 3]
  • Tensor: yes (1D tensor).
  • Elements: 1, 2, 3 (three elements).
  • Rank / dimension: 1.
  • Axes: 1 axis (the line of numbers).
  • Shape: (3,).
  • Size: 3.

Example 3: matrix.

[[1, 2, 3],
 [4, 5, 6]]
  • Tensor: yes (2D tensor).
  • Elements: 1, 2, 3, 4, 5, 6 (six elements).
  • Rank / dimension: 2.
  • Axes: axis 0 = rows (2), axis 1 = columns (3).
  • Shape: (2, 3).
  • Size: 6.

In NumPy, ndim gives rank, shape gives shape, and size gives total elements.

3D Tensors

What Is NumPy

NumPy means Numerical Python. It is the main library for fast math on large arrays in Python.

Many languages have built in arrays. Python has lists, but lists are slow when you work with millions of numbers. They also store mixed types easily, which is not ideal for pure number crunching.

NumPy gives you:

  • Powerful n dimension arrays (1D, 2D, 3D, and more).
  • Easy syntax for math on whole arrays at once.
  • Open source code used across data science.
  • Tools for linear algebra, random numbers, and statistics.

Pandas builds on NumPy. The Day 13 placement project starts with import numpy as np for a reason.

Python is an application language. It was made easy on purpose. C is a system language used near hardware: operating systems, robots, and low level work.

Because Python adds layers of comfort, raw loops on huge data are slow. Machine learning often uses millions or billions of numbers. NumPy closes that gap.

People who love Python wrote NumPy core in C. You write Python. You get C speed. That is why NumPy matters so much for machine learning.

Why NumPy Is Fast

Let us compare adding two lists of ten million numbers with pure Python vs NumPy.

Python lists (slow):

Input

import time

a = [i for i in range(10000000)]
b = [i for i in range(10000000, 20000000)]
c = []
start = time.time()
for i in range(len(a)):
    c.append(a[i] + b[i])
print(time.time() - start)

Output

About 1.2 to 3.0 seconds on a laptop. Your time may differ.

NumPy arrays (fast):

Input

import numpy as np
import time

start = time.time()
a = np.arange(10000000)
b = np.arange(10000000, 20000000)
c = a + b
print(time.time() - start)

Output

About 0.02 to 0.15 seconds. Much faster than the loop. First three values in c: [10000000, 10000001, 10000002].

NumPy adds the whole arrays in one step. No Python loop over every element.

df[

How to Frame a Machine Learning Problem

Turn a business goal into a clear ML problem before you write any code.

139

The Netflix Business Problem

Today we learn how to convert a business problem into a machine learning problem.

Suppose you are a data scientist at Netflix. Leadership asks: how do we increase revenue?

Three business levers come to mind:

  • Marketing: bring more new subscribers.
  • Pricing: get existing customers to pay more.
  • Retention: stop existing customers from leaving.

All three can grow revenue. As data scientists we often focus on the third: keep people subscribed.

That is step one in framing. Start with the business goal. Then ask which part of it ML can help with.

140

From Revenue to Churn Rate

Instead of saying "increase revenue" in the meeting room, we narrow the goal to: decrease churn rate.

Churn rate is the share of subscribers who cancel in a period.

Example: Netflix has 100 subscribers and 2 leave. Churn rate is 2%.

In real life Netflix churn is around 4%. The team might set a target: bring it down to 3.75%.

That is a mathematical problem we can track. We leave the meeting with a clear number, not a vague wish.

Business problem: increase revenue. ML framing: reduce churn from 4% to 3.75%.

141

See the End Product First

Look at the big picture. What is the end product?

We do not need a model that predicts the churn rate number itself. Churn rate is a company level metric.

What we need: find if a customer is about to leave.

Once we know that, the product can act:

  • Send a 50% discount offer.
  • Fix a bad UI or help with no internet issues.
  • Reach out immediately when someone shows signs of leaving.

Good framing means you know what the model will do in production, not just what it will predict on paper.

142

Classification and Regression

Now we pick the type of ML problem.

Step 1: Is this person leaving or staying? That is a yes or no question.

Use supervised learning classification. Output: leave or stay.

Step 2: How strong is the feeling to leave? Example: 90% likely to cancel.

That is a number, not yes or no. Use regression to estimate willingness to leave.

Why both? A higher score can trigger a bigger discount. Someone at 90% might get more than someone at 40%.

A real churn solution often uses both models: classification to flag at risk users, regression to rank how urgent the case is.

143

Getting the Right Data

Getting data is one of the most important parts of framing.

Ask: what signals show that someone might leave? Examples:

  • Watch time dropping.
  • Search but did not find what they wanted.
  • Content left in the middle of a show.
  • Clicks on recommendations and the order they clicked.

You rarely pull this data alone. Talk to the data engineer.

They take live app data from OLTP systems and build a data warehouse where you can train models.

If the data you need does not exist yet, framing is not finished. No data means no model.

144

Define Your Metrics

Before you build, decide how you will measure success.

Metrics tell you if what you are doing is good or bad.

For churn you might track whether churn rate actually dropped after the model went live.

Pick metrics that tie back to the business goal. If leadership cares about revenue, show how the model affects revenue, not only model accuracy.

145

Online or Batch Learning

Another framing choice: will the model run in batch or online mode?

A common pipeline looks like this:

OLTP → data warehouse → model → trained model.

Batch learning: retrain on a schedule (daily or weekly). Good when patterns change slowly.

Online learning: update the model as new events arrive. Good when behavior shifts fast.

For churn, many teams start with batch: pull warehouse data, train overnight, score users the next day. Online can come later if you need faster reactions.

146

Check Your Assumptions

The last step in framing: check your assumptions before you invest months of work.

  • Is the data available? Can you actually get watch time, searches, and cancel labels?
  • Does one model fit all regions? Users in different countries may behave differently. You might need separate models by geography.
  • Can the product act on predictions? A discount offer only helps if the system can send it in time.

Catching a wrong assumption early saves the whole project.

read_csv Basics

Start with the two imports you already know:

import numpy as np
import pandas as pd

Load a CSV from a local file:

df = pd.read_csv("file_name.csv")
df

You can also pass a URL instead of a file path. Pandas will download and read it.

url = "https://example.com/data.csv"
df = pd.read_csv(url)
df.head()

df is a DataFrame: a table with rows and columns. We will now look at many read_csv parameters to control how the file is loaded.

150

index_col and header

index_col: use a column as the row index instead of the auto generated 0, 1, 2… index:

df = pd.read_csv("file_name.csv", index_col="col_name")

This removes the extra index column pandas would create by default.

header: pick which row becomes the column names:

df = pd.read_csv("test.csv", header=1)

header=0 is the default (first row). header=1 means the second row becomes your header row.

151

usecols and squeeze

usecols: load only the columns you need:

df = pd.read_csv("test.csv", usecols=["enrolled_id", "gender"])

This saves memory when the file has many columns but you only need a few.

squeeze: when you load one column, turn the DataFrame into a Series:

s = pd.read_csv("test.csv", usecols=["enrolled_id"], squeeze=True)

A Series is a single column of data with an index. In newer pandas versions you can also call .squeeze() on a one column DataFrame.

152

skiprows and nrows

skiprows: skip specific rows when reading:

df = pd.read_csv("test.csv", skiprows=[0, 5])

This skips row 0 and row 5. Useful when the file has junk rows at the top or broken rows in the middle.

nrows: read only the first N rows:

df = pd.read_csv("test.csv", nrows=100)

Good for quick previews on very large files without loading everything.

153

encoding and Bad Lines

encoding: some files use a different text encoding. Special characters may break unless you set it:

df = pd.read_csv("test.csv", encoding="latin-1")

Try latin-1 or cp1252 when you see strange symbols or read errors.

Skip bad lines: sometimes a row is corrupt. Example: rows 5, 6, or 7 have wrong data.

df = pd.read_csv("test.csv", on_bad_lines="skip")

If a row expects 8 columns but has 9 values, pandas skips that row instead of crashing. Older pandas used error_bad_lines=False. Newer versions use on_bad_lines="skip".

154

dtype and parse_dates

dtype: set column types while loading. This helps save memory:

df = pd.read_csv("test.csv", dtype={"target": int})

Without this, pandas may load numbers as floats or objects. Telling it the type upfront keeps the DataFrame smaller.

parse_dates: dates often arrive as plain strings. Convert them on load:

df = pd.read_csv("test.csv", parse_dates=["date"])

After this, the date column is a real datetime type. You can filter, sort, and plot dates properly.

155

converters and na_values

converters: very powerful in pandas. Run your own function on each value in a column.

Example: instead of the full name Bishal Ranjitkar, store a short code br:

def rename(name):
    if name == "bishal ranjitkar":
        return "br"
    else:
        return "norbr"

df = pd.read_csv("test.csv", converters={"team1": rename})

na_values: tell pandas which values should count as missing (NaN):

df = pd.read_csv("test.csv", na_values=["male"])

You can pass strings like "-", "nan", or any custom token your file uses for empty data.

156

Loading Data in Chunks

Sometimes the dataset is so large that loading it all at once fails or slows your machine.

Use chunksize to read the file in pieces:

chunks = pd.read_csv("test.csv", chunksize=100)

for chunk in chunks:
    print(chunk.shape)
    # process each chunk here

Each chunk is a DataFrame with 100 rows. You can clean, filter, or aggregate chunk by chunk without holding the full file in memory.

Day 15 takeaways

  • Data gathering has four paths: CSV, JSON/SQL, API, and web scraping. CSV is the starting point.
  • pd.read_csv works on local files and URLs.
  • Parameters like index_col, header, usecols, and dtype control how data loads.
  • Use encoding, on_bad_lines, converters, and na_values to handle messy real world files.
  • For huge files, use chunksize to process data in batches.

    hq = []
    how_old = []
    no_of_employee = []

    for i in company:
        try:
            name.append(i.find("h2").text.strip())
        except Exception:
            name.append(np.nan)

        try:
            rating.append(i.find("p", class_="rating").text.strip())
        except Exception:
            rating.append(np.nan)

        try:
            reviews.append(i.find("a", class_="review-count").text.strip())
        except Exception:
            reviews.append(np.nan)

        try:
            ctype.append(i.find_all("p", class_="infoEntity")[0].text.strip())
        except Exception:
            ctype.append(np.nan)

        try:
            hq.append(i.find_all("p", class_="infoEntity")[1].text.strip())
        except Exception:
            hq.append(np.nan)

        try:
            how_old.append(i.find_all("p", class_="infoEntity")[2].text.strip())
        except Exception:
            how_old.append(np.nan)

        try:
            no_of_employee.append(i.find_all("p", class_="infoEntity")[3].text.strip())
        except Exception:
            no_of_employee.append(np.nan)

    df = pd.DataFrame({
        "name": name,
        "rating": rating,
        "reviews": reviews,
        "company_type": ctype,
        "Head_Quarters": hq,
        "Company_Age": how_old,
        "No_of_Employee": no_of_employee,
    })
    final_pages.append(df)

final = pd.concat(final_pages, ignore_index=True)
final.shape

One page has 30 rows. Across 1000 pages you can reach about (30000, 7).

Use pd.concat to stack page tables. Older notebooks used DataFrame.append, but that method is gone in current pandas.

Day 18 takeaways

  • Web scraping pulls data from HTML when no API is available.
  • Use requests to download a page and BeautifulSoup to search tags.
  • Send a User Agent header if the site returns 403.
  • Scrape one card at a time so fields stay aligned in your lists.
  • Loop pages, handle missing fields with try and except, then combine with pd.concat.

Respect site rules and rate limits. Scrape only public pages you are allowed to use.

Day 19

Understanding Your Data

Ask the right questions before you build any model.

171

Questions After Loading Data

After you get a dataset, do not jump straight into modeling. Ask basic questions first.

Load the file and keep a simple checklist:

import pandas as pd

df = pd.read_csv("train.csv")
  • How big is the data?
  • How does the data look?
  • What are the column data types?
  • Are there missing values?
  • What do the numbers look like mathematically?
  • Are there duplicate rows?
  • How do columns relate to each other?

The next lessons answer each question with one pandas method.

172

How Big Is the Data

Question 1: How big is the data?

df.shape

shape gives two numbers: rows and columns.

Example output: (1000, 12) means 1000 rows and 12 columns.

Size tells you if the file is small enough to explore in memory, or if you need chunking later.

173

How Does the Data Look

Question 2: How does the data look?

See the first few rows:

df.head()

head() shows the top 5 rows by default.

Or sample random rows to avoid bias from the top of the file:

df.sample(5)

This gives 5 random rows so you see different parts of the dataset.

174

Column Data Types

Question 3: What is the data type of each column?

df.info()

info() shows column names, data types, and non null counts.

It also shows how much memory the DataFrame is using.

Check this early. A number stored as text, or a category stored as float, can break later steps.

175

Missing Values

Question 4: Are there any missing values? This is very important.

df.isnull().sum()

This counts missing values in each column.

After you know where gaps are, you can either fill them or remove the column. Do not ignore missing data and train a model on broken rows.

176

Math Summary with describe

Question 5: How does the numeric data look mathematically?

df.describe()

describe() gives count, mean, standard deviation, min, max, and quartiles like 25%, 50%, and 75%.

Use this to spot odd ranges, very large values, or columns that look flat and unhelpful.

177

Duplicate Values

Question 6: Are there duplicate rows?

df.duplicated().sum()

This counts how many rows repeat exactly.

Duplicates can inflate scores and mislead your model. Remove or fix them before training.

178

Correlation Between Columns

Question 7: How are columns related to each other?

Correlation means when one value goes up or down, another column may move in a linked way.

See the full correlation matrix:

df.corr()

Pick one column and read its links to others:

df.corr()["column_name"]

Values range from negative 1 to positive 1. Values close to 0 mean weak link. Values near 1 or negative 1 mean stronger link.

Use this to drop columns that repeat the same signal, or to spot features that may matter for your target.

Day 19 takeaways

  • Always explore data before modeling.
  • shape, head(), and sample() show size and samples.
  • info() shows types and memory use.
  • isnull().sum() finds missing values you must handle.
  • describe(), duplicated(), and corr() complete your first data check.

Run this checklist on every new dataset. Clean understanding here saves hours later.

Day 20

Gen AI for Beginners

Learn what generative AI is, why it matters, and how to map builder vs user skills.

179

What Generative AI Is

Generative AI is a type of AI that creates new content such as text, music, video, and images.

It learns patterns from existing data. Then it mimics human creative work to make something new.

In short: older tools often predicted or classified. Gen AI can create.

180

Gen AI Changed Creative Work

Machine learning has long had many kinds of models, for example:

  • Prediction models like regression.
  • Classification problems.
  • Recommendation problems.

For a long time, ML was not strong on creative platforms. Gen AI changed that.

Creating text, images, music, and video is a big power of Gen AI.

People used to say AI cannot replace human creativity. Gen AI made that debate real again.

181

From AI to Gen AI

A simple path helps you place Gen AI in the stack:

AI → ML → DL → Gen AI

  • AI has many techniques. ML is the main one for most products.
  • ML has many techniques. Deep learning (DL) is used a lot.
  • DL has many techniques. Gen AI is the popular focus now.

So Gen AI sits on top of deep learning ideas, not outside AI.

182

Impact Areas

In about three years, Gen AI became very important. These are major impact areas.

1. Customer support

Chatbots try to solve the problem first. A human support person steps in only when the chatbot cannot finish the job.

2. Content creation

People make blogs, videos, and more with Gen AI. Content is one of the main places Gen AI has reached.

3. Education

Learners can have a personal tutor available any time.

4. Software development

Gen AI writes code and makes programming easier. That is another real impact.

183

Is Gen AI Successful

Yes. Gen AI is successful.

Think about other big tech waves. The internet was huge. Crypto and blockchain were loud too.

Success is not only hype. Success means real use and real problems solved.

184

Success Questions

Ask these questions when you judge any big technology.

Will it solve real world problems?

The internet fixed many real world problems. Crypto did not solve many daily life problems. Gen AI is solving real world problems.

Is it useful day by day?

Yes. People use Gen AI daily.

Is it impacting the world economy?

Yes.

Is it creating new jobs?

Yes. New roles include AI engineer, AI automation, and AI integration.

Is it accessible?

Yes. Gen AI is accessible to many people through apps and APIs.

185

Why Learning Gen AI Feels Hard

Some people ask: why not Gen AI yet?

  • The tech feels new.
  • It might be a bubble.
  • Gen AI keeps bringing a new term, a new tool, or a new paper.

That flood of new things feels overwhelming. Feeling lost is common. It does not mean you are behind forever.

186

Problems and Mental Models

Gen AI has clear problems for learners:

  • Very fast progress.
  • A lot of noise. FOMO merchants can make you feel demotivated.
  • No single source to learn everything.

Solution: build a mental model.

A mental model is a simple map in your head. It tells you where a new term belongs, so every new tool does not restart your learning from zero.

187

Foundation Models

The main idea to learn early is the foundation model.

A foundation model is an AI model trained on very large data.

Many models we build for products are task specific. They mainly do one job.

Foundation models are generalized. They have many parameters and much training data.

A top example of a foundation model is an LLM (large language model). An LLM can do many tasks, not only one narrow prediction.

188

LLMs and Multimodal Models

Foundation models do more than predict the next bit of text. They can chat, summarize, translate, write code, and more.

There are not only LLMs. There are also multimodal models (sometimes called LMMs).

Multimodal models work with more than one kind of input, for example text, sound, and images together.

So Gen AI is bigger than chatbots alone.

189

Build or Use

Gen AI has two big paths:

  • Make an LLM or foundation model.
  • Use an LLM or foundation model.

You can think from a user perspective or a builder perspective.

Once you hold that lens, the game gets clearer. Most new buzzwords fit one side or the other.

190

User vs Builder Terms

Any new term you hear is usually a user idea or a builder idea.

  • Prompt engineering: user perspective. Better prompts for better responses.
  • RLHF: builder perspective. It helps safeguard and steer the LLM.
  • RAG: user perspective. Give personal or private data to the LLM safely.
  • Pre training: builder perspective.
  • Quantization: builder perspective. Optimize the LLM so it can run in more environments.
  • AI agent: user perspective.
  • Vector database: user perspective.
  • Fine tuning: both user and builder perspectives.

Labeling each term this way cuts confusion fast.

191

Builder Learning Path

Prerequisite: PyTorch or TensorFlow.

  1. Transformer architecture. Learn how transformers work, including self attention.
  2. Types of transformers. Encoder only models like BERT. Decoder only models like GPT.
  3. Pre training. Training objectives, tokenization strategies, training strategies, challenges, and evaluation.
  4. Optimization. Training optimization, model compression, and inference optimization.
  5. Fine tuning. Task specific tuning, instruction tuning, and continual pre training.
  6. Evaluation. Measure quality and safety.
  7. Deployment. Ship the model into real use.

This path is closer to research and deep model work.

192

User Learning Path

  1. Build basic LLM apps. Use open source models, closed source models, LLM APIs, Hugging Face, Llama, and frameworks like LangChain.
  2. Improve the LLM for your case.
    • Prompt engineering for better responses.
    • RAG so the model can use your personal or company data.
    • Fine tuning at the user level when prompts and RAG are not enough.
  3. AI agents. Let the LLM do work for you, such as booking a ticket.
  4. LLM Ops. Deploy the application. Many libraries help here.
  5. Miscellaneous. Other Gen AI tools such as Stable Diffusion for images, and more.

This path is closer to product building with existing models.

193

Do You Need Both

Do you need builder and user paths?

  • Data scientist: often more builder level.
  • Software developer: often more user side.
  • Combination: AI engineer.

An AI engineer knows foundation model ideas from the builder side and can also ship work on the user side.

You do not need every paper. You need a clear map: build, use, or both for your role.

Day 20 takeaways

  • Gen AI creates new content by learning patterns from data.
  • It sits in the path AI to ML to DL to Gen AI.
  • Foundation models and LLMs are the core mental models.
  • Sort new terms by user vs builder to cut noise.
  • Pick a path for your role: builder, user, or AI engineer.

Start with the map. Then learn tools one step at a time.
