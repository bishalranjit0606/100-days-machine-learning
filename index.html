Why this website exists

Teaching the full ML life cycle — together

This course is an introduction to a new series titled “100 Days of Machine Learning.” Each day, a new topic is added for 100 days, building a complete learning path for the community.

The goal is an end-to-end understanding of the Machine Learning Life Cycle (also called the Product Life Cycle). Unlike algorithm-specific tutorials, this series follows the entire process from start to finish — how real ML work actually happens.

It is designed for beginners and intermediate learners who want to reach a proficient level: confident with data, models, and decisions — not just memorizing model names.

Data analysis

Model selection

Feature selection

Focus on inputs that actually matter.

Bias–variance trade-off

Balance fit and generalization.

What this series is not

Specific machine learning algorithms are not covered in depth here — on purpose. Excellent resources already exist for individual algorithms. This site fills the gap: the full life cycle and how all the pieces connect.

Begin with Day 1 — Introduction to ML

Day 1

Introduction to ML

1

What is Machine Learning?

Machine learning means learning from data. In traditional programming, we write code for every possible outcome — the program produces the output directly.

In machine learning, we do not write every rule. The relationship looks like this:

  • Traditional programming: data + program = output
  • Machine learning: data + output = pattern

Or simply: ML = data + algorithm → pattern

Typical ML workflow

  1. Question Define the problem
  2. Data Collect examples
  3. Train Fit a model
  4. Evaluate Check performance
  5. Iterate Improve and repeat
2

Traditional Programming vs Machine Learning

In traditional programming, you explicitly encode logic. The computer follows your instructions step by step.

In ML, you provide examples and let the system discover the rules. The algorithm generalizes from what it has seen to handle new cases it was never explicitly programmed for.

3

Learning Patterns from Examples

Traditional programming example:

  • 2 + 2 gives 4
  • 2 + 3 gives 5

You hard-code each case. In machine learning, you give thousands of addition examples. The model recognizes the pattern of addition — so even with 3- or 4-digit numbers it can answer correctly without you writing rules for every length.

4

Why Rules Break: Spam Detection

In traditional programming you might write:

If an email has words like "big" or "discount", classify it as spam.

Companies can change wording — "big" to "huge", "discount" to "offer" — and brittle rules fail. ML recognizes underlying patterns in language instead of matching fixed keywords.

5

Scale and Learning Over Time

ML learns from data over time. The bigger and more representative the dataset, the better the model can generalize — as long as the data quality stays high.

6

Data Mining and Applications

Data mining extracts useful information from large datasets. Machine learning supplies the patterns; data mining turns those patterns into actionable insight for business, science, and product decisions.

Day 1 takeaways

  • ML learns patterns from data instead of hand-written rules.
  • Traditional code maps inputs to outputs; ML maps data + labels to a reusable model.
  • More quality data usually means better generalization.
Day 2

AI vs ML vs Deep Learning

7

Artificial Intelligence Overview

AI (Artificial Intelligence) is a broad term. It can include simple if/else rule systems — also called symbolic AI or expert systems.

Expert systems encode knowledge from human specialists (e.g. a chess master) into explicit rules. They work well for narrow, well-defined problems but struggle with noisy, real-world data.

8

Expert Systems & Symbolic AI

An expert system captures domain knowledge as rules. It excels at chess-like domains with clear logic but does not adapt when data is fuzzy or constantly changing.

9

Machine Learning with Fuzzy Data

ML works with fuzzy, messy data. You do not hand-write every rule — the model finds statistical patterns using math and optimization.

Concept Simple meaning Use when
AI Any system that mimics intelligent behavior You need broad automation or reasoning frameworks
ML Learns patterns from data without explicit rules You have labeled or unlabeled examples and fuzzy inputs
Deep Learning ML with neural networks that learn features automatically You have very large datasets and complex perception tasks
10

Deep Learning

Deep learning is a subset of machine learning inspired by biology (neural networks). In classic ML you often define features manually — e.g. for cats vs dogs: ears up, long tail.

Deep learning discovers features automatically. It shines on very large datasets and complex inputs (images, audio, text). For many everyday problems, traditional ML is still the practical choice.

Day 2 takeaways

  • AI is the umbrella; ML learns from data; deep learning learns representations with neural nets.
  • Expert systems use explicit rules; ML handles fuzzy real-world data.
  • Choose deep learning when data scale and complexity justify it.
Day 3

Types of Machine Learning

11

Supervised Learning

In supervised learning, you have both input and output (labels). The model learns the mapping between them.

  • Supervised

    Input + known output; learns mapping

  • Unsupervised

    Input only; finds structure

  • Semi-supervised

    Mix of labeled and unlabeled data

  • Reinforcement

    Agent learns via rewards and mistakes

  • Feature

    Measurable input attribute (e.g. CGPA)

  • Label

    Target output you want to predict

12

Regression

Regression — both input and output are numeric. Used for prediction.

Example: Input: IA = 99, CGPA = 7.5 → Output: Package = 14 lakh

13

Classification

Classification — input can be numeric, but output is a category or decision.

Examples:

  • Will rain happen or not?
  • Input: IA = 99, CGPA = 7.5 → Output: Placement = Yes
14

Unsupervised Learning

In unsupervised learning, you only have input — no output labels. Common goals: grouping similar items or simplifying high-dimensional data.

Example: Student records grouped into high-IQ vs low-IQ clusters without predefined labels.

15

Clustering & Dimensionality Reduction

Clustering — categorize items into groups (e.g. customer segments).

Dimensionality reduction — compress many columns into fewer meaningful ones. Example: combine separate "room" and "washroom" features into one housing-quality score.

16

Anomaly Detection & Association Rules

Anomaly detection — find fraud or unusual events (email fraud, manufacturing defects).

Association rule learning — discover patterns for recommendations (e.g. bread buyers often buy eggs).

17

Semi-Supervised Learning

Semi-supervised learning blends supervised and unsupervised approaches. Labeling data is expensive — it takes time, money, and expertise.

You label only some examples (e.g. "dad", "mom" in photos) and let the model propagate labels to similar unlabeled data.

18

Reinforcement Learning

In reinforcement learning, an agent starts from scratch and learns through trial and error. Rewards and penalties shape behavior.

Example: An AI agent moves near fire → points decrease → next time it avoids fire.

Day 3 takeaways

  • Supervised: labeled data maps to regression or classification.
  • Unsupervised: find groups, reduce dimensions, detect anomalies, or mine associations.
  • Semi supervised and reinforcement learning cover label scarce and interactive settings.
Day 4

Batch Machine Learning

19

Batch vs Online ML in Production

This is another way to group machine learning: how the model is trained in production.

We care about this because most real projects end on a server. The training style affects cost, speed, and how fresh the model stays.

Two main styles: batch learning (also called offline learning) and online learning.

20

What Is Batch Learning

Batch learning is also known as offline ML.

You use all available data to train the model in one go. There is no incremental training during normal operation.

Data is often huge. Training with all data directly on the live server is expensive. That is why teams usually train on a separate offline machine, then move the finished model to the server.

21

Train Offline, Deploy to the Server

The usual batch flow:

Batch workflow

  1. Data Collect full dataset
  2. Model Train offline
  3. Test Check quality
  4. Server Deploy model

Training stays off the production server. Only the trained model runs live.

22

Static Models and Retraining

Problem with batch models: knowledge stays static. What the model learned at training time does not change until you retrain.

Example: Netflix keeps adding movies. An old model that never updates will get worse at recommendations.

Fix: retrain on a schedule. Use new data plus the previous model, train again, and deploy the updated model. Teams often retrain daily or weekly.

Batch learning in practice: train on a large offline dataset, deploy to the server, and repeat on a cycle.

23

Disadvantages of Batch Learning

  • Scale limits: very large data may not fit your tools or hardware. Training can fail.
  • Connectivity: without a good link, moving data or a new model to the server is hard.
  • Freshness: on social feeds, batch updates can feel slow. New posts might show up only after the next batch run (for example once every 24 hours).

Day 4 takeaways

  • Batch = train on all data offline, then deploy.
  • Models go stale; retrain on a schedule.
  • Watch data size, hardware, and how fresh users need results.
Day 5

Online Machine Learning

24

What Is Online Learning

If you have heard that the more you use a product, the better it gets, that is often online ML.

Online learning trains incrementally. You feed the model small batches over time. Each batch can make the model a bit smarter.

Because updates are small, training can happen on the server while the product is live. Online learning is popular today.

25

Incremental Training on the Server

Online flow in simple steps:

small data → ML → test → server

The server keeps receiving new data. The model learns from each new small batch on the server itself.

This is different from batch learning, where training usually happens offline in one big run.

26

Real World Examples

  • Voice assistants (Alexa, Google): learn from chat and usage on the server.
  • Keyboards: the more you type, the more personalized suggestions become.
  • YouTube: real time style recommendations as you watch and click.
27

When to Use Batch vs Online

The key idea is concept drift: when the world or user behavior changes fast, the old model stops fitting.

Use online learning when patterns shift quickly (stocks, sales, ecommerce, fast moving feeds).

Online learning can also help with speed and sometimes cost for continuous small updates.

Use batch learning when patterns are mostly stable and you are fine retraining on a schedule.

Situation Simple meaning Use when
Concept drift Data patterns change fast Prefer online learning
Stable patterns World changes slowly Batch learning can work
Production ease How hard to run live Batch is easier; online is harder
28

Learning Rate

Learning rate controls how strongly each new batch updates the model.

Too fast: the model may forget old good patterns. Too slow: it may not adapt to new trends.

Picking a good learning rate is one of the hardest parts of online learning.

Libraries: scikit learn (batch friendly by default), River, Vowpal Wabbit for online style workflows.

29

Out of Core Learning

When data is too big to load at once, we use out of core learning.

Split huge data into small chunks, train step by step, test, and serve on the server.

big data → small chunks → model → test → server

Online style training fits this pattern well.

30

Risks and Monitoring

Online learning is powerful but risky.

  • Tricky to set up and tune compared with batch.
  • If the server is hacked or flooded with spam data, attackers could poison what the model learns.

You need a monitoring system to detect bad inputs. If attack or bad data appears, you must be able to roll back and pause online updates until it is safe.

31

Online vs Offline and Tools

  • Offline (batch): simpler to reason about; strong local machines for big training jobs.
  • Online: more complex in production; needs strong server compute and good monitoring.
  • Application rule: mostly stable data → batch can work. Fast changing context → online fits better.

Tools (examples from notes):

  • Batch: Spark, TensorFlow, PyTorch
  • Online: Storm, MOA, scikit-multiflow

Day 5 takeaways

  • Online = small incremental updates on the server.
  • Use online when concept drift is high; batch when patterns are stable.
  • Guard online systems with monitoring and rollback.
Day 6

Instance Based vs Model Based

32

Instance Based vs Model Based Learning

Another way to group ML: instance based vs model based learning.

As you learn more algorithms later, you should be able to tell which family each one belongs to.

33

Memorize vs Generalize

The simplest way to learn is to remember everything, like pure memorization.

A better way is to generalize: learn the concept behind the examples.

Example from school: in chemistry we often memorize facts. In physics we learn concepts and apply them to new problems.

Machine learning follows the same idea. Instance based methods lean toward remembering similar past cases. Model based methods lean toward learning a rule or formula.

34

Instance Based Learning

Sample data:

IQ CGPA Placement
80 8 Yes
70 7 No

New student: IQ 7.5, CGPA 10.3. Will they get placement?

We have not built a traditional model. We look for similarity. Similarity is measured by distance between points.

We do not train a model in the usual sense. We react to the data when a new point arrives.

35

KNN Example

Pick the nearest points, for example the 3 closest students in the table.

If most of those neighbors say yes for placement, we predict yes for the new student.

This method is KNN (K Nearest Neighbors). It is a classic instance based algorithm.

There are fewer instance based algorithms than model based ones.

36

Model Based Learning

With the same placement data, a model based approach tries to understand how the data behaves overall.

Think of a graph with two regions. Points in one region mean fail, points in the other mean pass. The model learns a boundary between them.

It finds a math link between input and output. That link is the decision function. It can classify any new point that arrives.

Even if we delete the old training rows, we can still keep the decision function and score new points.

Examples: linear regression, decision tree, and many other model based algorithms.

A model is often just a set of parameters. In linear regression, parameters include slope and intercept. The model is stored in a compact form with rules inside it.

37

Comparing Both Approaches

Both styles still need prepared data before you use them well.

Topic Instance based Model based
Training No classic training step Build parameters from data
Before scoring No model generated ahead of time Model ready with rules inside
Data at scoring time Needs training data nearby Old data not required once trained
Storage Heavy (keep many examples) Light (store equation or rules)
Nickname Lazy learners Eager learners (train first)

Day 6 takeaways

  • Instance based: compare new points to similar past examples (KNN).
  • Model based: learn a decision function you can reuse without all raw data.
  • Know which type an algorithm is before you pick it for a project.
Day 7

Challenges of Machine Learning

38

Data Collection

If there is no data, there is no point in doing machine learning.

Small projects often use ready datasets (for example Kaggle). In a real company, gathering data is very hard. This is one of the main ML problems.

Common ways to get data

  1. Open datasets Kaggle, small projects
  2. API Fetch from services
  3. Web scraping Pull from websites
39

Insufficient Labeled Data

Suppose algorithm A is better in theory but has only 100 rows. Algorithm B is weaker but has 1 lakh rows. B often wins in practice because it has more data.

With huge data, which algorithm you pick matters less. In real life we usually have small or medium datasets.

When data or labels are scarce, machine learning becomes much harder.

40

Non Representative Data

If your data covers only part of the real world, your model reflects only that part.

Example: You survey only Spain about who will win the World Cup. Most answers pick Spain, so the model says Spain will win. You needed data from all countries in the tournament.

Watch for sampling noise (random luck in a small sample) and sampling bias (sample does not match the full population).

41

Poor Quality Data

A funny truth: we often spend about 60% of our time cleaning data.

The purer the data, the better the model. Dirty data leads to weak or wrong results no matter how fancy the algorithm is.

42

Irrelevant Features

Garbage in, garbage out. Some columns never help the model.

Example: Predicting a marathon winner from a survey with age, height, weight, and location.

  • Age and weight can matter.
  • Location alone cannot tell you that people from Pokhara will win.
  • Height and weight can be merged into BMI instead of keeping both.
43

Overfitting

The model memorizes training data. It does well on old examples but fails on new ones.

Example: One cinema ticket in Kathmandu costs 120. The model learns that every hall ticket everywhere is 120. That is wrong generalization.

When the model tries to be too accurate on training data only, that is overfitting.

44

Underfitting

The model is too simple or not trained well. It is weak on training data and weak on new data.

Problem What happens Training accuracy
Overfitting Memorizes training, fails on new data Very high (often near 100%)
Underfitting Too simple, misses patterns Low
Good fit Learns real patterns, generalizes Strong but not perfect
45

Software Integration

After you build a model, you must plug it into real software. The ML part must work with the app, APIs, and user flows.

Check compatibility and keep versions aligned. Software integration is often very hard.

Tip: always aim to ship an end to end product, not just a notebook.

46

Deployment and Offline Updates

Once the model is live, data keeps changing. You often retrain offline, test again, then push to the server. That loop is hard to run smoothly.

Deployment is one of the toughest steps in the ML life cycle.

Cloud platforms like AWS and Azure help, but production ML is still not always stable.

47

Cost and End to End Mindset

When many people use your ML system, cost can grow fast. Hosting on your own server can bring hidden costs (compute, storage, traffic).

Monetizing ML products is also hard.

  • MLOps

    Deploy and monitor models in production

  • Cost optimization

    Control compute and storage spend

  • Load balancing

    Handle many users without crashes

Day 7 takeaways

  • Data collection, quality, and representation come before fancy models.
  • Overfitting and underfitting show why we tune models carefully.
  • Integration, deployment, and cost are why we build end to end products.

Learning ML means learning the full life cycle, not only algorithms.
